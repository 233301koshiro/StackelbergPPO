# 研究方針（猿でもわかる版）

---

## この研究は何をしたいのか

**「ロボットのスケッチを描くだけで、そのロボットでタスクができるか自動でわかるシステム」** を作ることを目指しています。

```
ユーザーが手描きのスケッチを入力
    ↓
形のパラメータ（腕の長さ・関節の強さ）に変換
    ↓
Stackelberg PPO が形と動き方を同時に最適化
    ↓
「この形でこのタスクはいけるか？」を数エポックで判定
```

ロボット設計の専門知識がなくても、アイデアを素早く試せるようにするのがゴールです。

---

## 今やっていること（現在のスコープ）

理想システムへの基盤として、まず **「固定された根本のアームロボット（2関節）」** に限定して研究を進めています。

| ロボット | 今やるか | 理由 |
|---|---|---|
| 固定根本アーム | **✅ やる** | 関節が少ない・倒れない・扱いやすい |
| 四脚ロボット | 将来 | 歩行が絡んで複雑 |
| ヒューマノイド | 遠い将来 | 自由度が多すぎる |

---

## 研究の核心となる問い

> **シンプルな報酬だけで、AI はタスクに合った形態を正しく選べるか？**

「報酬」は AI が「良い行動」を学ぶための点数です。複雑な報酬を作れば誘導できますが、
複雑にするほど「形の違いを正しく反映する点数」としての機能が壊れる問題があります。

過去の実験で実際に失敗しています（詳細 → [実験系譜.md](実験系譜.md)）:
- cube を「目標位置に」近づける報酬を作った → AI が cube に腕を貫通させて高得点を稼ぐバグが発生
- 複数の報酬を組み合わせた → シグナルが打ち消し合って何も学習しなくなった

**結論: 報酬はシンプルなほど良い。**

---

## 3つのタスク

| タスク | 報酬（シンプル版） | 理想の行動 |
|---|---|---|
| **Pusher** | cube が動いた速さ | キューブを遠くに吹き飛ばす |
| **Reach** | アーム先端〜目標点の距離（近いほど良い） | 先端を x=0.8m にピタリと止める |
| **Target-Pusher** | cube〜目標点の「近さ」の変化量 | キューブをちょうど x=2.0m に止める |

これら 3 つで最適な形が**異なること**を確認するのが Phase 2〜3 の目標です。

---

## 研究のフェーズ（現状）

```
Phase 0 ✅ 完了
  → Pusher で co-design（形と動き方の同時学習）が機能することを確認
  → co-design あり vs なし で 8〜10 倍の差

Phase 1 ✅ 完了
  → Reach タスクでも co-design が機能することを確認
  → 短い腕より長い腕を選ぶことを実証

Phase 2 ✅ 完了
  → Pusher と Reach の最適形態が異なることを実証（タスク識別 = YES）

Phase 3 進行中
  → Target-Pusher タスクを追加・3タスク比較
  → 第3の形態クラスタが出現することを確認済み
```

---

## 元論文との違い

この研究は「Stackelberg PPO（ICLR 2026 採録）」という論文のコードをベースにしています。

| 要素 | 元論文 | この研究 |
|---|---|---|
| ロボット | 体ごと移動できるロボット | **固定根本アーム** |
| タスク | Pusher 1種のみ | **Pusher + Reach + Target-Pusher** |
| 貢献 | アルゴリズム提案 | **固定アームへの適用 + 複数タスク形態比較** |

元論文のロボットは「体ごと移動できる」ため Pusher タスクが自然に機能しますが、
固定根本アームに移植したら色々なバグと設計ミスが出てきました。
それを全部解決した記録もこの研究の貢献の一部です。
