貼り付けられたレビュー（別モデルのセカンドオピニオン／指導教員・助教の指摘）を処理する。

## なぜこのコマンドがあるか

CLAUDE.md §10 は「別モデルにレビューさせ、結果を貼り返して Claude が反映する」と定めているが、
**そのまま受け入れてはいけない**と同時に書いている。理由は2つある。

1. **外部レビュアーは実験ログを知らない。** 「それは検討済み」「その反証は既にある」という
   指摘が必ず混ざる。実際、2026-09-02 の助教の指摘「リカバリーは現在なんの案もない」は、
   9-11 の閉ループ検証（397 mm → 0.33 mm、2 seed）を知らないための行き過ぎだった
2. **逆に、こちらが気づいていない急所を突くこともある。** 同じ回の
   「把持を外すようなタスク難易度なら設計支援になっていないのでは」は、
   限界節に無い論点で、最も鋭かった

**鵜呑みも全否定もせず、1件ずつ証拠に当てる**のがこのコマンドの役割。

## 手順

### 1. 指摘を1件ずつ番号を振って分解する

まとめて評価しない。**1つの指摘に正しい部分と行き過ぎな部分が同居する**ことが多い。

### 2. 各指摘を、この repo の一次記録に当てる

**推測で答えない。必ず grep して実データを見る。**

```bash
grep -rn "<指摘のキーワード>" docs/研究応用/実験系譜.md docs/デバッグ戦記.md \
     docs/研究応用/想定問答.md docs/研究応用/修論ドラフト/
```

見るべき順序は CLAUDE.md §2 と同じ。**一次記録（実験系譜・デバッグ戦記）が最優先**で、
修論本文は派生なので、食い違ったら一次記録を信じる。

### 3. 4つに仕分ける

| 判定 | 意味 | やること |
|---|---|---|
| **採用** | 正当で、まだ対応していない | 対応方針と工数を書く。実装するなら着手 |
| **既に対応済み** | 指摘の内容は正しいが、既に本文・限界節にある | **どこに書いてあるか**を示す。書いてあるのに伝わっていないなら**書き方**の問題 |
| **反論する** | 一次記録が反証を持っている | **数値を挙げて反論する。**「そう思わない」ではなく「9-9 で範囲が重ならない」と言う |
| **部分的に正当** | 正しい部分と行き過ぎが同居 | **分けて書く。**「ここまでは認める / ここからは違う」 |

⚠️ **「部分的に正当」がいちばん多い。** 安易に採用/却下の二択にしない。

### 4. 反映先へ書く

| 指摘の性質 | 反映先 |
|---|---|
| 実験設計・結論の妥当性 | `研究応用/研究方針.md`、該当する修論章 |
| 審査で繰り返し来そう | `研究応用/想定問答.md` に Q を追加 |
| 限界として認めるべき | 第5章 5.7 / 第6章 6.4.2 |
| 指導教員・助教からの指摘 | `研究応用/指導教員アドバイス対応方針.md`（**一次記録。指摘の内容・評価・対応方針・工数の4点セットで**） |

**根拠まで書く。** 「なぜ採用しなかったか」「なぜ反論できるか」を数値つきで残さないと、
次に同じ指摘が来たときに一から議論をやり直すことになる。

### 5. `/reflect` を続けて実行する

方針や限界が変わったら §4-2 のトリガーを踏んでいる。**配布資料3件を忘れない。**

## 出力の形

指摘ごとに次を書く。

```
### 指摘N: <要約>
**指摘の内容**: <相手の主張>
**正しい部分**: <認める範囲。証拠つき>
**行き過ぎな部分**: <反論。必ず数値・run 名を挙げる>
**対応方針**: <採用/対応済み/反論/部分採用> + 具体的にどこへ何を書くか
**工数**: <実装が要るか、執筆だけか>
```
