直前の作業について、**CLAUDE.md §4-2「記録のトリガーと反映先」の反映漏れを潰す**。

## なぜこのコマンドがあるか

§4-2 は「トリガーを踏んだらその場で書く」と定めているが、**実際に何度も漏れている**。

| 日付 | 漏れ |
|---|---|
| 2026-09-02 | 配布資料3件（中間発表原稿・論文2枚・論文6枚）が「E2E は未実施」のまま。1 例通っていた |
| 2026-09-02 | B1 の結果を一次記録には書いたが、進捗・引き継ぎ・実験一覧・パイプラインMD・第3章・scripts/README の 6 件が漏れた |
| 2026-09-02 | 描画基準を変えたとき実寸表だけ直し、プロンプト側の比のロックを放置。B1 が壊れる寸前だった |

**漏れる理由は構造的**である。§4-2 の表は「どこに書くか」を定めるが、
**表に載っていないファイル**（配布資料・凍結スナップショット・スクリプトの索引）は
その場では思い出せない。だから毎回このコマンドで機械的に洗う。

## 手順

### 0. 他セッションの差分を取り込む（**最初に必ず**）

**別端末・別セッションで並行開発されていることがある。** 自分のコンテキストに無い
コミットが入っていると、**古い解釈のまま喋る**。

```bash
git log --oneline -20 --format="%h %ad %s" --date=format:'%m-%d %H:%M'
git status --short          # 未コミットの変更も見る
```

**とくに危ないのは、結論や解釈を書き換えたコミット**である。これらは
「数値は変わっていないが読み方が変わった」型なので、数値を見ても気づけない。

```bash
git log --oneline -30 | grep -iE "訂正|取り下げ|反証|撤回|誤り|解釈|限界"
```

該当したら **`git show <hash>` で本文を読む**。要約だけで済ませない。

**知見の現在地は [知見総括表.md](../../docs/研究応用/執筆/知見総括表.md) を見る。**
とくに **E 節「反証・取り下げた主張」**に、いま言ってはいけない読みが集めてある。

### 0-2. 学習が完走していたら、**解釈を書く前に収束形態を実測する**

**best 値だけを見て解釈を書くと交絡を見落とす。** 2026-09-04 に実際に踏んだ:
「縦型は平面より Reach が悪く Pusher が良い」→「自由度が Reach では負債、Pusher では資産」
と結論して記録したが、**収束形態を実測したら縦型はリンク長も最適化されて腕が約 2 倍に
伸びていた**（`pusher_tripo_v3` の `body_params.offset`、平面は `{}` で凍結）。
**方向はリンク長だけで説明がつき、解釈は取り下げになった。**

```bash
COMPARE_RUNS="single_run/A:single_run/B" COMPARE_LABELS="A:B" \
USE_CHOREONOID=1 /choreonoid_ws/install/bin/choreonoid --no-window \
  --python scripts/compare_morphology.py
```

**とくに条件間で cfg が違うときは、`design_opt/cfg/*.yml` の
`body_params` / `geom_params` / `actuator_params` を直接見比べる。**
「何が最適化対象か」が違えば、best の比較は別物どうしの比較になる。

### 1. 踏んだトリガーを判定する

直前の作業を見て、CLAUDE.md §4-2「トリガー → 反映先」の表のどの行に当たるかを**すべて**挙げる（複数可）。
表はここに写さない。写しは CLAUDE.md の改訂に追随せず、反映先の行・パス・節番号が古くなる。

### 2. 反映先を実際に開いて確認する

**「書いたつもり」で済ませない。** `grep` で当該の語がそのファイルに入っているかを見る。

```bash
for f in docs/進捗.md docs/研究応用/引き継ぎ_再起動後.md docs/実験一覧_詳細.md \
         scripts/README.md; do
  printf "  %-40s %s\n" "$f" "$(grep -c '<今回のキーワード>' $f)"
done
```

### 3. とくに漏れやすい箇所を明示的に見る

- **`scripts/README.md`** — スクリプトの挙動を変えたのに索引が古いまま
- **同一ファイル内の別箇所** — 第4章 4.5.3 を直して 4.6 の要約を忘れた例がある
- **凍結スナップショット**（冒頭に `doc-policy: frozen` を書いたもの）— 古いままでよいが、その旨の注記が要る（例だった `要旨_詳細版.md` は 2026-10-23 に削除）
- **修論の限界節** — 限界が1つ消えたのに「残された改良点」と書いたままになりやすい
- **「2箇所に同じことを書く構造」の片割れ** — 参照画プロンプト ↔ M1 プロンプト、
  実寸表 ↔ 比のロック、専門MD ↔ 修論本文。
  **2026-09 に 3 回踏んだ**（CLAUDE.md §4-2 の表を見る）

### 4. 検査を回す

CLAUDE.md §4-2「自動チェック」の表の「いつ走らせるか」の列を見て、今回踏んだトリガーに当たる検査をすべて回す。
表はここに写さない（手順 1 と同じ理由）。どの作業の後でも §5-2 ③ の 2 本は回す。

週に1回の棚卸しの週なら、CLAUDE.md §4-2「定期棚卸し」のコマンドも回す。

### 5. 漏れがあれば直し、無ければ「無し」と報告する

**取り繕わない。** 漏れが無かったならそう言う。あったなら、
**なぜ漏れたか**（どのファイルが §4-2 の表に無かったか）まで報告する。
表に無いせいで漏れたなら、§4-2 の表自体を直す。
