# A1_m1var — **M1（画像整形）の非決定性**を測る（実験系譜 9-68）

**問い**: 同じ手描き写真を Gemini に n 回入れたとき、出てくる形態はどれだけ揺れるか。

## なぜ要るか — 18 % はこれとは別の量だった

9-22 の **18 %** は **A1 と A2 の比較**で、**別々に描いた 2 枚の写真**である
（手描き段階の比はどちらも 1.01 で揃っていた）。つまり測っていたのは
**M1 の「入力感度」**であって、**同じ入力に対する非決定性ではない**。

| | 測る量 | 状態 |
|---|---|---|
| ① M2 の非決定性 | 同じ M1 画像 → Tripo ×4 | ✅ **±0.7 %**（9-39） |
| ② **M1 の非決定性** | **同じ写真 → Gemini ×4** | ⏳ **本フォルダ** |
| ③ M1 の入力感度 | 違う写真（A1 対 A2） | ✅ **18 %**（n=2） |

## ⚠️ 判定基準（**測る前に決めた**。9-50 の教訓）

| ② の結果 | 読み |
|---|---|
| **5 % 以上** | **M1 の非決定性が効いている。** プロンプトを詰める価値がある（発表の言い分どおり） |
| **2 % 未満** | **18 % は入力感度が主犯。** 直すのはプロンプトではなく**手描きの撮り方・正規化**。**「プロンプトで直せる」は言い過ぎ**になる |
| 2〜5 % | どちらとも言えない。**その旨を書く**（無理に寄せない） |

## 手順

1. **入力**: `sketch/A1_hand.webp`（A1 の手描き写真そのもの）
2. **プロンプト**: `sketch/prompt_used.txt` を**毎回そのまま**貼る
   ⚠️ **1 文字も変えない。** 変えると非決定性ではなく介入を測ることになる
3. Gemini を **4 回**回し、出力を `sketch/` へ
   `A1_m1var_m1.jpeg` / `_r2.jpeg` / `_r3.jpeg` / `_r4.jpeg`
4. 各画像を Tripo3D に入れ、GLB を `3D/` へ
   `A1_m1var.glb` / `A1_m1var_r2.glb` / `_r3.glb` / `_r4.glb`
   ⚠️ **Tripo の設定も毎回同じにする**
5. 測る:

   ```bash
   python3 scripts/probe_m2_variance.py --name A1_m1var --work /tmp/m1_variance
   ```

   ⚠️ スクリプト名は「m2」だが、**中身は「GLB 群 → 縦型パイプライン → XML → 水平到達」**
   なので、GLB の出所が M1 違いであれば **M1 の分散を測る道具になる**。
   9-39 と同じ経路なので**数字が直接比較できる**。

## ⚠️ やってはいけないこと

- **M1 が出した画像から比を測る。** 遠近で歪むので信用できない（9-22③）。**必ず XML まで通す**
- 途中で「揃ってきたから」と本数を変える。**4 本と決めて 4 本回す**（optional stopping）
- `data/test/` の中に scratch を作る。`--work` は **`/tmp` 側**を使う（9-39 で踏んだ）
