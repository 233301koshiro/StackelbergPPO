## 言葉

| 言葉 | 意味 |
|---|---|
| 鎖 | 胴から出る、関節が一列に並んだ部分（四脚なら脚 1 本） |
| ホーン | サーボの回る円盤。関節の軸はホーンの中心を通り、円盤に垂直 |
| リンク | 前のサーボのホーン → Hinge →（LEGO の段）→ Frame → 次のサーボ |
| 系統 | Frame とサーボのつなぎ方（4 通り）。同じ長さでも、サーボの向きが変わる |
| 付け方 | RobotAssembler の attach の向き。fixed・invert・rotate90・rotate-90 の 4 通り |
| めり込み | 部品の点が、別の部品の芯（表面から 1 mm 内側）に入る体積。1 mm の格子で数える。ねじで接しているだけでも約 250 mm³ 出る |
| 0° の姿勢 | 入力の形（関節 → 次の関節の向き）に部品の鎖をそろえた姿勢。ホーンへの付け角を変えることに当たり、部品どうしの付け方は変わらない |

## 入力（関節の表）

軸の向きは**立体から推定しない**。チャットで決めた向き（例「股も膝も左右の水平軸」）を、そのまま表に書く。
立体から取るのは関節の位置（マゼンタの球の中心）と先端だけである（`segment_quad_mesh.py`）。

```json
{"name": "quad_walk_ra235",
 "torso": {"plate": "plate_16_16", "rail": "plate_4_8"},
 "range_deg": 30, "tip_hinge": "Hinge_Short_Plug", "link_names": ["thigh", "shin"],
 "chains": [
  {"name": "脚1",
   "joints": [{"pos": [-52.3, -70.9, 2.3], "axis": "+y"}, {"pos": [-107.7, -63.5, -38.3], "axis": "+y"}],
   "tip": [-107.5, -65.4, -107.0]}
 ]}
```

- 長さは mm、原点は胴の板の中心、z が上。`axis` は `"+y"` のような文字か、`[ax, ay, az]` のベクトル（± x・y・z に丸める）
- 省略できるもの: `mount_target_xy`（根元の狙う位置）・`lengths_mm`（関節の間の長さ）・`tip_mm`（先端までの長さ）。省略すると位置から出す
- `rail`: 空なら股のサーボを胴の板の下に直接吊る。`plate_4_8` なら板を 1 枚はさんで側面の外へ出す（[四脚の形のノウハウ.md](四脚の形のノウハウ.md) の K4）

## 手順

図の ①〜⑦ と同じ番号。

1. **① 軸を丸める。** ±x・±y・±z のどれかにする。部品は直角にしかつながらないので、斜めの軸は作れない。丸めた角度は出力に残す。鎖の中で隣り合う軸が平行でなければ止める。直交の組み方は、四脚の `quad_4x2`（股が鉛直）で組めなかった（系譜 9-342）。
2. **② 長さと向きを出す。**
   - 関節の間の長さ: 軸に垂直な距離
   - 0° の向き: 関節 → 次の関節（最後の関節は → 先端）
   - 根元の狙う位置: 先端の面より 19 mm 外。Hinge はサーボを挟むので、リンクの中心線がホーンより約 19 mm 内側へ寄る（K4）。そのぶん外に置く
3. **③ 部品どうしの相対位置の表を作る。** 「部品 A の点 p に、部品 B の点 q を付け方 c で付けたら、B はどこに来るか」を、RobotAssembler 自身の attach で小さいロボットに 1 回ずつ試し、4×4 の行列で覚える。
   - 部品の寸法を自分で書き写さなくてよい
   - 以降の探索は行列の掛け算だけで済む
4. **④ リンクの型を選ぶ。** 事前に数え上げた組み方の表（`data/axis6/irsl_link_all_v2.csv`、系譜 9-325）から、系統ごとに長さがいちばん近い行を選ぶ。表には、軸が平行・LEGO がポッチを全部覆う・段の継ぎ目が直交、を満たす組み方だけが入っている。先端は Hinge にブロックを 0〜8 段積み、先端までの長さがいちばん近いものを選ぶ。
5. **⑤ 根元を選ぶ。** 次の 4 つの組み合わせを総当たりする:
   - 胴の板の穴
   - フレーム（`Frame_Long_Plug`）の角
   - 付け方
   - サーボの点

   次の 3 つを満たす付け方だけを残す:
   - フレームのポッチが全部、板の穴に入る
   - ホーンの軸が ① の向き
   - サーボが板の下にある

   残ったもののうち、狙う位置にいちばん近いもの（＋0.5 mm 以内）を候補にする。
6. **⑥ 組み合わせを全部試す。** 系統 × 根元の候補 × 各 Hinge の付け方（4^関節の数）を試し、組み合わせごとに次を回す:
   1. 0° の姿勢を ② の向きにそろえる
   2. 各関節を −30・0・+30° に振る（3^関節の数の姿勢）
   3. めり込みの最大を数える

   めり込みの少ない順に選び、同じなら 0° へそろえる回転の小さいものを選ぶ。めり込みが 400 mm³ 未満（接している面のぶんだけ）の候補が見つかった系統で止め、無ければ次の系統へ進む。
7. **⑦ 組んで確かめる。** 選んだ組み方を本物の attach で組み直し、関節の間が表と 0.2 mm 以内・軸が平行かを確かめる。出力は 2 つ:
   - 部品の JSON: 型・姿勢・どの部分か。`build_quad_ra.py` と同じ形で、関節が 2 つなら `make_quad_ra_xml.py` にそのまま通る
   - `.roboasm`: RobotAssembler の GUI で開ける組み立ての履歴。RobotAssembler 自身の `createRoboasm` で書き、読み戻して書き直した履歴が同じになるかを確かめる

## 使い方

```bash
cd /userdir/StackelbergPPO_ra        # ブランチの worktree
# 入力の表を XML から作る（手で書いてもよい）
python3 scripts/ra_spec_from_xml.py --xml assets/mujoco_envs/quad_walk_ra235.xml --rail plate_4_8 --target plane \
    --link-mm 68.7 --tip-mm 68.7 --link-names thigh shin --out /userdir/StackelbergPPO/data/axis6/tree/quad_walk_ra235_spec.json
# 組む（Choreonoid の中で。1 脚に数分）
SPEC=/userdir/StackelbergPPO/data/axis6/tree/quad_walk_ra235_spec.json OUT=/userdir/StackelbergPPO/data/axis6/tree/quad_walk_ra235_parts.json \
  timeout -k 10 3000 /choreonoid_ws/install/bin/choreonoid --no-window --python scripts/build_ra_tree.py > ログ 2>&1
# → quad_walk_ra235_parts.json と quad_walk_ra235.roboasm（RobotAssembler の GUI の「読み込み」で開ける）
```

`--target hip` は最初の関節の位置そのものを狙う（`build_quad_ra.py` の `QUAD=tripo`）。`--target plane` は先端の面より 19 mm 外を狙う（同じく `QUAD=walk`）。
`--link-mm`・`--tip-mm` は全部の鎖の長さをそろえる。左右・前後で同じ脚にしたいときに使う。

## 確かめたこと（2026-11-20）

四脚の 2 つの形（11-06 に `build_quad_ra.py` で組んだもの）を、XML から作った表で組み直して前の結果と比べた。
- tripo: `--target hip --link-mm 108.8 --tip-mm 102.4`
- walk: `--rail plate_4_8 --target plane --link-mm 68.7 --tip-mm 68.7`
- 入力の表・JSON・`.roboasm` は `data/axis6/tree/`（git の外）

| 比べたもの | tripo（部品 125 個） | walk（部品 65 個） |
|---|---|---|
| 部品の型と並び・脚と部分の並び | 一致 | 一致 |
| 各脚のめり込みの最大（mm³） | 246・250・259・256（前と同じ） | 258・257・243・245（前と同じ） |
| 股のサーボの姿勢 | 一致（差 7×10⁻¹⁵ mm） | 一致 |
| `make_quad_ra_xml.py` に通した XML | 前の `quad_tripo_rab.xml` と 1 文字も違わない | 前の `quad_walk_ra235_rab.xml` と 1 文字も違わない |
| 0° の姿勢へそろえた後の部品 | 一致（差 5×10⁻¹³ mm） | 脚 4 の股の板（plate_4_8）だけ 180° 回った置き方。前後対称の板で、中心の位置・胴の板の下のポッチの数（16）は同じ |
| `.roboasm` を読み戻す | 部品ごとのつなぎ方と回転が一致 | 同じ |
| `.roboasm` から作った Body | 関節 8・1,310.0 g。関節の位置の差 0.0 mm・軸は平行 | 関節 8・938.0 g。同じ |

- 組み方を選ぶ前の生の JSON では、3 本の脚（tripo の脚 4・walk の脚 3・4）で Hinge の付け方の名前が前と違った（前は fixed、今回は rotate-90）。
  - 違いが出る理由: Hinge をホーンに 90° 回して付けても、0° の姿勢へそろえる回転が 90° 変わるだけで、そろえた後の形は同じ。だからめり込みの値も同じになり、どちらを選ぶかは格子の数え方の丸めで決まる。
  - 実物で違うところ: サーボのどの角度をモデルの 0° とするか（0° へそろえる回転。JSON の `rot_to_zero_deg`）だけで、組む形は同じ。
- `build_quad_ra.py` との違いは 1 つ: RAIL が無いときも、根元のフレームをめり込みの相手に入れた（`LEGACY_BASE=1` で前と同じ扱いに戻せる）。tripo は、入れても入れなくても結果が同じだった。
- 1 脚に 1〜2 分かかった（attach を試した数は 4,139〜4,654）。

`.roboasm` の確かめで 1 度つまずいた。最初は、読み戻した履歴を文字どおりに比べて「不一致」と出た。原因は 2 つで、どちらも見かけだけの違いだった。
- 読み戻すと部品の並ぶ順が木の辿り方の順になる
- z 軸まわりの回転を、+180° と −180° のどちらで書くかが変わる

そこで、部品の名前ごとに、つなぎ方と回転（行列にして）を比べる形に直した。

## できないこと

| できないこと | 理由・直し方 |
|---|---|
| 斜めの軸 | 部品が直角にしかつながらない。① で丸め、丸めた角度を出す |
| 隣り合う軸が直交する鎖（腕の根元の旋回 → お辞儀など） | 直交のリンクの探索は `build_quad_ra.py` の `QUAD=x42` にあるが、四脚では組めなかった（腿の Hinge が板を突き抜けた）。腕の根元は `build_bow.py` が研究室の腕と同じつなぎ方を決め打ちで使っている。汎用にするには、直交のリンクの表を作る |
| 鎖の途中で枝分かれする形 | 胴から出る直列の鎖だけ |
| 胴が板 1 枚でない形・サーボを板の上に置く形 | 根元は「板の下にフレームで吊る」だけ |
| 関節が 3 つ以上の鎖を XML・`.body` にする | 組むこと（JSON・`.roboasm`）はできる。`make_quad_ra_xml.py` が関節 2 つ（腿・脛）の決め打ち |
| 強度・ねじの位置・配線 | 見ていない（軸6 §8 の「まだ基準に入れていないもの」） |
