## 1. ⭐ なぜ数週間かかったのか — **1 本の因果鎖だった**

⚠️ 「ホッケーは Pusher ＋ 壁の反発係数くらい」という見立ては自然だが、**実際は違った。**

```
① ⛔ 反発係数を物理エンジンに渡せない（9-198）
        │
        ▼
② ⛔ 跳ね返る壁を Python の step() に手書き（35 行）        → 欠陥あり（A）
        │
        ▼
③ ⛔ 壁が物理に無いので腕も通り抜ける → 腕ブロックも手書き（68 行）
        │
        ▼
④ ⛔ 腕を止めた途端「腕が壁の外だと永久に入れない」（9-192）
        │
        ▼
⑤ ⛔ 初期姿勢を計算で決める必要 → その式が壊れていた（Bug 52 / 9-196）→（B）
```

⭐⭐ **①が起点。**⛔ **そして ②③⑤ のそれぞれに別個の欠陥が出た。**

⚠️ **さらに別層の問題が重なっていた**

| | |
|---|---|
| 9-98 | ⛔ **変換器が `worldbody` 直下 geom を落とす** → 壁がそもそも実走に存在しなかった |
| 9-93 | ⛔ **腕が壁越しにパックを押せた** → 反射が不要になっていた |
| ⑤-3-2 × 4 | ⛔ **掴む対象を間違えた**（固定リンク・中央板・末端リンク×2） |

## 2. ⛔ 根本原因 — **AISTSimulator は反発係数を扱えない**（9-198）

| 経路 | 実態 |
|---|---|
| MuJoCo の `solref` / `solimp` / geom `friction` | ⛔ **この repo の変換器が 0 回参照** |
| `ContactMaterial` の `restitution` | ⛔⛔ **AISTSimulatorItem が 0 回参照。**読むのは **AGXDynamicsPlugin ただ 1 箇所** |
| ワールド全体の `setEpsilon()` | ⛔⛔ **デッドパラメータ**（宣言・初期化=0.0・setter・getter の 4 箇所のみ。求解部から読まれない） |

⭐ **産総研（開発元）の公式見解と一致**:
> 「産総研エンジンでは、マテリアルの摩擦係数だけ対応しています。」

⭐ **既定 0.0（完全非弾性）がそのまま使われるので、実測 0.055 になる。**

### ⚠️ 他エンジンへ替えない理由（9-198 追記）

⭐ **Bullet は同梱・ビルド済みで反発係数を実装している。**⛔ **Python に `py::init<>()` が無いだけ。**

⛔ **それでも替えない:**

| | |
|---|---|
| ⛔⛔ **反射慣性を読まない** | ⭐ この repo は `setEquivalentRotorInertia(armature=1)` を使い、⭐ **それが慣性行列の 99 % 以上**を占める。⛔ **Bullet は `Jm2` を 0 回参照**（AIST の `ForwardDynamicsABM` だけが使う）。⛔⛔ **実効慣性が 1/50〜1/210 になる＝別の機械** |
| ⛔ **比較可能性** | 全接触が変わり、既存 171 run と比べられなくなる |
| ⚠️ **二重適用** | この env は「AIST が無視する量を `step()` で明示適用する」設計 |

⭐ **したがって「速度反射で代替する」は回避策ではなく唯一の手段。**
⚠️ **修論には「壁との接触は物理エンジンではなく速度反射としてモデル化した」と明記する。**

### ⭐ A. 反発係数の正味が合わない

| 条件 | 設定 | 実測 e |
|---|---|---|
| 反射なし | 無効 | 0.0145 |
| ⛔ **③ 以前**（env step の最後に 1 回） | 0.75 | ⛔⛔ **0.0128**（効いていない） |
| ⛔ 同・別環境 | 0.75 | ⛔⛔ **2.0593**（エネルギー増加） |
| ⭐⭐ **③ 適用後・`easy`** | 0.75 | ⭐⭐ **① 0.750**（② 0.6958 / ③ 0.7099） |
| ⭐⭐ **③ 適用後・`wall3`** | 0.75 | ⭐⭐ **① 0.750**（② 0.6958 / ③ 0.7919） |

⭐⭐ **③ だけで 0.0128 → 0.8299。**
⭐⭐⭐ **残りの +11 % は測り方だった**（9-201）: **イベント単位の比は 3 回とも 0.750（期待 0.75）**、
**「当て直し: 接触が 1.00 倍」**（以前は 2.3 倍）。
⭐ プローブの接近ピークは壁から離れた地点で取られ、`damping=0.02` で 7.2 % 減速してから反射する。
⭐⭐ **A は解決。**

⭐ **1 イベントの比は合っている**（`比 0.750（期待 0.75）`）。
⛔⛔ **だが正味は両方向に外れる。**⭐ コード自身のコメントが原因を言い当てている:
> 「反射した直後の残り tick で、接触解決が押し出しながら速度を 2.3 倍にする。
> 反射の計算自体は検証済みなので、**適用のタイミングだけの問題**。」

#### ⭐ 他エンジンの定石 — **速度を書き換えず、拘束の目標速度に畳み込む**

| エンジン | やり方 |
|---|---|
| **Bullet**（sequential impulse） | `velocityError = restitution − rel_vel` を solver へ渡し、**力積は solver が出す** |
| **ODE**（Dantzig LCP） | `dContactBounce` ＋ `bounce`（0〜1）＋ ⭐ **`bounce_vel`（これ未満の入射速度では跳ねない）** |
| ⛔ **本実装** | ⛔ **solver の外で `dq` を直接書き換える** → 押し出しと喧嘩する |

⭐⭐ **共通する考え方: 「反発は、非貫通拘束と一緒に解く」。**

#### ⭐ 借りる策（⚠️ **変数は一度に 1 つ**）

| # | 案 | 出典 | 規模 |
|---|---|---|---|
| ⛔ ① | ~~エネルギー非増加クランプ~~ | 一般 | ⛔⛔ **入れない。**⭐ **実装が厳密に正しいので対症療法になる**（9-201、§5-2 ①） |
| ⚠️ ② | `bounce_vel` しきい値 | ODE | ⚠️ **当面不要。**低速ジッタが問題になったら |
| ⭐⭐ ③ | ~~`frame_skip` の各 tick で当て直す~~ | — | ⭐⭐ **適用済み（9-200）。0.0128 → 0.8299** |

⭐ **見込みが高い理由**: ⭐⭐ **パックは 2 自由度の slide 関節。**
⭐ **回転なし・摩擦円錐なし・多点接触 LCP なし。**1 軸の速度反転だけで、一般の接触より桁違いに易しい。
