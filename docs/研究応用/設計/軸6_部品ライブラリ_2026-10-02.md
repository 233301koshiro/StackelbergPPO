### ⛔ 検討して**やらない**と決めたこと — **M1 の絵をサーボ＋レゴ風にする**（2026-10-02）

⭐ **出た案**: 「M1（Gemini）の画像生成を、サーボ＋レゴ（RobotAssembler 風）の見た目にしてはどうか。

⛔⛔ **やらない。**理由は 3 つ。

| # | ⛔ 理由 |
|---|---|
| ⛔⛔ **①** | **絵柄は見た目のためではなく M3 のためにある。**プロンプトに **「※ マゼンタはアーム本体色には絶対に使わないこと（**自動検出用のため**）」**と明記してあり、⭐ **「CAD レンダリング風」はマゼンタ球を単色で確実に出すための指定である。**⛔ **サーボを描けばマーカーが埋もれる** |
| ⛔⛔ **②** | **同じ失敗を実測済み**（9-195）。⛔ **プロンプトが「円柱カプセル」と指示していたせいで、丸い端が関節球を視覚的に代替してマーカーが消えた**（3/5）。⭐ **平らな円柱にして 5/5 に直した。**⛔ **サーボ形状は同型の失敗を誘発する** |
| ⛔ **③** | ⭐ **軸6 の方針は「システムを作り替えず、実験を 1 つ足す」。**⛔ **M1 を変えるのは作り替えにあたる** |

⭐⭐⭐ **そして決定的なのは、軸6 では入力を変える必要が全く無いことである。**

```
現行の絵 → M1〜M5 → ⭐ リンク長・関節軸の数値 → ⭐⭐ ここから人が部品を選ぶ
```

## 8. ⭐⭐⭐ 【方針の具体化】β を本命、α を対照（2026-10-05、ユーザーと検討）

⭐ 当日の資料: [ミーティング_2026-10-09_準備.md](../方針/ミーティング_2026-10-09_準備.md) の 3。タスクの正は [進捗.md](../../進捗.md) の L 表。

### ⭐⭐ なぜ α（形を固定）だけでは足りないか — ユーザー指摘

⛔ α は人が組んだ形を固定して制御を学習するだけなので、**Stackelberg（設計と制御の入れ子）である必要が無い**。
⛔ 制御だけなら別の強化学習（SAC など）の方が良い可能性もあり、**この枠組みで判定するという主張の検証にならない。**
⭐⭐ **β（部品で作れる範囲で長さを学習）なら、Leader が「Follower がこう動かせるならこの長さが良い」を選ぶ仕事が残る。**

| | 設計変数 | 既存の仕組み |
|---|---|---|
| ⭐ β | **長さだけ**（範囲 17.6〜212.8 mm、向きはスケッチのまま） | 9-150 の `rel_frac`（横方向 0） |
| 太さ | 部品の断面で固定 | `geom_params` から外す |
| ギア比 | サーボ 1 種類なので固定 | `actuator_params` の上下限を同じに |
| リンク・サーボの質量 | 部品の組み合わせ表から「長さ→質量」、サーボ 26.4 g を関節ごとに | XML の密度・9-83 の「カプセル＋駆動系」 |
| ⭐ 新規（小） | 学習後の長さを**作れる組み合わせへ丸めて再評価** | — |

⭐ α は β の初期の形を固定したもの（スケール・物理・初期の形を共有）。**β − α ＝ 部品の制約の中で co-design が足したもの。**

### ⭐ 3 つの懸念への答え（要約）

| 懸念 | 答え |
|---|---|
| 連続（育てる）と離散（部品を足す・減らす） | 長さは隙間 0.4 mm でほぼ連続なので問題にならない。⛔ 選べなくなるのは太さとギア比 |
| 質量・密度が部品ごとに違う → 計算量 | 変わらない（数値を持つだけ）。リンク数と衝突形状は「固定関節のリンクをまとめる」＋カプセルで今と同じにできる |
| ギア比が設計変数から消える | 定数になる。軸5 と同じ扱い |

⚠️ **E2E の標準構成（`pusher_gearonly`）はリンクの長さを学習していない**（スケッチの比で固定、学習は太さ・延長・ギア比）。
⭐ β は設計変数の組が入れ替わるので、既存の E2E とは直接比べない。

### ⛔⛔ 今の流れとのギャップ

⭐ M1〜M4（スケッチ → XML）はそのまま使える。⛔ ギャップは物理・報酬・判定に集中する。
