## 1. 研究の一言要約

「手描きスケッチ → co-design（Stackelberg PPO）でロボット形態のタスク適性を判定するシステム」の修士研究（2月修論・10月中間発表）。

**コア主張（rrbot 2関節、確定）**: シンプルな報酬のみで、3タスク × 2 seed において co-design はタスクごとに異なる形態と行動類型に収束する（タスク識別 = YES）。

**tripo アーム（3〜4関節、Tripo3D生成メッシュ由来）での再現検証が進行中**。当初 tripo_arm_v2 で確認できたが、後に環境の物理パラメータが rrbot と揃っていない confound が2件見つかり（下記2章）、修正版で再実験中。

## 4. 落とし穴（新セッションが踏みがちなもの）

- **Bug 8**: `pgrep/pkill -f` は自分自身にマッチする。ブラケット記法（`pgrep -f "foo_[b]ar"`）を使い、kill 系は単独の Bash 呼び出しで実行
- **学習の起動形式**: `nohup env USE_CHOREONOID=1 OMP_NUM_THREADS=1 /choreonoid_ws/install/bin/choreonoid --no-window --python scripts/choreonoid_train.py cfg=... hydra.run.dir=single_run/<name> > .../stdout.log 2>&1 &`（bash -c で包まない）
- **Bug 12（転用の必須引数）**: 転用起動は `+restore_dir=... epoch=best` の**両方**が必要。`epoch=best` を忘れると重みはロードされず無言でゼロスタートになる。転用 run を起動したら ep0 の exec_R_eps が転用元 final に近いことを必ず確認する
- **Bug 13（新アーム形状の env コード前提）**: `env_specs.get(key, <ハードコード値>)` パターンは、その値が特定アーム専用でないか要確認。新アーム追加時は学習中欠陥チェックリスト.md の②を実施
- **Bug 14（並列実行時のworkerパス衝突）**: 修正済みだが、新しい共有一時リソースを追加するコードを書くときは複数run同時起動でも衝突しないか確認する
- **ハングに見えるクラッシュ**: Choreonoid は `--python` スクリプト内の例外を握りつぶし Qt ループだけ残すため、CPU使用率が低いまま止まって見える。真っ先にプロセス自身の生ログ（stdout・`/tmp/cnoid_worker_*.log`）を確認する（状況証拠より先に）
- **並列本数と ETA**: 3並列を超えると CPU 競合で ETA が大きく悪化する（9並列で1本のETAが14日まで悪化した実測あり）。並列起動前に `uptime`/`free -g` を確認し、必要なら優先度の低い run を止める
- **epoch数の妥当性**: 「200epで十分」に根拠はない。I1 vs I2 は ep200→240→600 で順位が2回反転した実測があり、単一epoch数での判定は避ける（詳細: 実験系譜.md）
- **eval スクリプト**: `timeout -s KILL` 必須（Qt が例外を握って hang する）、`torch.set_default_dtype(torch.float64)`
- **判定指標**: 形態の良し悪しは決定論 eval 単発で判定しない。学習曲線の ep75/100 順位法を使う
- **md の信頼度**: 一次データ（log/overrides）> 実験系譜（監査済み）> 進捗.md の古い節・現在地ロードマップ（07-15付けで停止、tripo関連は本ファイルの方が新しい）
- **ユーザーの文体好み**: md は平易な日本語（ゼロスタート・頭打ち等）+ 用語は実験系譜.md 冒頭の辞典に集約。修論ドラフト本文のみ学術文体（だ・である）。コミットは内容別に分ける
- **ファイル参照の形式**: マークダウンリンクはこの環境ではクリックできない。ファイルパスを伝えるときはコードブロック内の生パス（相対パス）で書く
