# 図表・圧縮計画

## 目的

図表を配置した最終版を前提に、本文を100〜105ページ程度へ圧縮する。削除は一括で行わず、主張単位で実施する。各単位について、本文から削除した内容・削除理由・根拠の保存先を `削除・圧縮記録.md` に記録し、検査後に個別コミットする。

## 中心主張

手描きスケッチ由来の形態をシミュレーションへ接続し、co-design によってタスク適性を判定し、不適合時には修正方向を返すシステムを構築した。

## 圧縮優先順位

1. 第4章の予備実験・補足実験・未採用条件
2. 第4章の同じ結果を説明する文章と図表キャプションの重複
3. 第5章の実験値の再掲（考察は機序と含意だけ残す）
4. 第6章の第4・5章との重複
5. 第3章の工程説明をシステム図・処理表へ集約
6. 第2章の代表研究以外の詳細説明

## 削除単位とコミット規則

- 1コミットは1つの主張・節・図表群の圧縮に限定する。
- コミットメッセージに「何を削ったか」と「なぜ削ったか」を書く。
- `削除・圧縮記録.md` に、削除した根拠・理由・保存先・復元対象を同時に追記する。
- 削除した内容を復元する場合は、削除記録から対象コミットを特定して戻す。
- 各コミット後に `check_stale_claims.py`、`check_docs_consistency.py`、`check_citations.py`、PDFビルドを実行する。
- 先生から復元指示があった場合は、削除理由を再検討し、該当コミットだけを revert または逆パッチで戻す。

## 第一段階の停止条件

- 図表を含むPDFが100〜105ページ程度に入る。
- 中心実験（タスク分離、順位反転、配分判別、診断閉ループ）と限界が残っている。
- 各削除単位に根拠の保存先がある。
- これ以上削ると、主張の再現条件または反証可能性が失われる場合は停止する。
