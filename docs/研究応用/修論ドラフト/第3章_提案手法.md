## 3.5 システム全体像

提案システムは、手描きスケッチを入力とし、その形態の対象タスクへの適性判定と、不適合であった場合の修正方向を出力する。全体の構成を図 3.1 に示す。処理は 7 つの工程（M1〜M7）からなり、図ではこれを 4 つのフェーズに分けている。

![**図 3.1**: 提案システムの全体構成。上段はスケッチから形態パラメータを得るまで（フェーズ 1・2）、下段はシミュレーションモデルの生成と評価・診断（フェーズ 3・4）である。色と矢印の意味は図の下の凡例に示す。{width=1.0}](figures/system_overview.pdf)

各フェーズの役割は次のとおりである。

- **フェーズ 1（入力・画像整形）**: M1 が、固定プロンプト（関節マーカー規約）のもとでスケッチを白背景・単一視点で CAD のレンダリングを模した画像に描き直し、関節にマゼンタの球を描かせる（3.6 節）。
- **フェーズ 2（三次元化・リンク分割）**: M2 が画像を色付きの単一メッシュに変換する（3.7 節）。M3 がマーカーの色から関節を検出してメッシュをリンクごとに切り分け（3.8 節）、M4 が関節間の距離と断面から形態パラメータを求める（3.9 節）。
- **フェーズ 3（シミュレーションモデル生成）**: M5 が各リンクをカプセルで近似し、MuJoCo 互換 XML を出力する（3.10 節）。
- **フェーズ 4（評価・形態診断）**: XML はまず M7 の第1層が幾何だけで判定する。目標に届かない形態は学習に進めず、届くのに必要な拡大倍率とともに棄却する。通過した形態は、M6 が Stackelberg PPO で形態と制御を同時に最適化し（3.11 節）、その結果を M7 の第2・3層が診断して報告する（3.12 節）。

M7 が M6 の前後に分かれているのは、第1層が学習を要さず、第2・3層が学習の結果を読むためである。データは図の矢印に沿って一方向に流れるが、第1層で棄却された場合に限り、助言どおりリンク長を N 倍した XML を第1層へ戻す閉ループを持つ（図の破線、4.5.2 項）。

**自動化の範囲について先に述べる。** M3 以降（関節検出からモデル生成・学習起動まで）は単一のシェルスクリプトで自動化している。**M1（画像整形）と M2（三次元形状生成）は外部の生成 AI サービスに依存し**、本研究ではその API 経路も実装した（付録D.2）。したがって本章で「人手を介さない」と述べる範囲は、**M3 以降の決定論的処理と M6 の学習**であり、生成物の取得工程は含まない。

設計思想は 3 点である。第一に、可動構造の抽出に学習ベースの推定を用いず、上流（M1）での入力規約と下流（M3）での決定論的な色検出に置き換える。生成モデルの出力の不確実性をパイプライン内部で補償するのではなく、入力を拘束することで構造推定の不良設定問題を回避する。第二に、M3〜M5 を乱数や学習を含まない決定論的処理とし、失敗時の原因特定と再現性を担保する。第三に、M5 が既存の co-design フレームワークと互換な MuJoCo 互換 XML を出力することで、学習系の内部コードを改変せずに接続する。

## 3.6 M1: 画像整形と関節マーカー規約

3.6〜3.10 節では、手描きスケッチ A1（4.6.4 項）を例に、各工程の途中経過を図 3.2〜3.5 に示す。

![**図 3.2**: M1・M2 の入出力（手描きスケッチ A1）。① 手描きスケッチ、② M1 が描き直した画像、③ M2 が生成した三次元メッシュを横から見たもの。{width=1.0}](figures/pipeline_m12_paper.png)

入力スケッチは、画像生成 AI（Gemini）によって、後段の三次元化と色検出に適した画像へ描き直される（図 3.1 の M1、図 3.2 ①→②）。描き直した画像は単一の視点から CAD のレンダリングを模して描き、寸法線・文字・複数の視点を含まない。単一の視点に限るのは三次元化が 1 枚の画像を入力とするためであり、寸法線と文字を禁じるのは三次元化がそれらを立体として拾うためである。この際、本システムの中核である**関節マーカー規約**を固定プロンプトとして課す。規約は生成モデルに構造の推定を委ねるのではなく、**構造の境界の宣言を強制する**。要点は次の 3 つである。

1. **すべての関節接続部に純マゼンタ（#FF00FF）の球を 1 個ずつ描く**。マゼンタは自然画像・工業製品に稀な色相であり、色検出で他の部分と分けやすい
2. **各リンクを彩度の高い単色で塗り分け、グラデーションとマゼンタの使用を禁止する**
3. **関節の位置を場所として列挙し（「台座と上腕の間」等）、描画後に球の個数を自己検査させる**。列挙を欠くと先端側の関節が機械要素として描き分けられ、マーカーが欠落する

これにより M3 の関節検出は、精度保証のない推定問題から閾値つきの色マッチングという決定的問題に変わる。プロンプトの全文は付録A に示す（ゼロから生成する版 A.1 と、手描きスケッチを整形する版 A.2。4.6.4 項の end-to-end 実走 5 件はすべて A.2 を用いた）。

リンクは「両端が平らな円柱」として指示する（丸い端は関節球と紛らわしく、マーカーが省略されるため）。⚠️ **出力のばらつきを最も小さくする設定（サンプリング温度 0。最も確からしい出力だけを選ぶ指定）にしても、出力が規約（向き・寸法線の禁止・比の保存）を満たすとは限らない（5.3 節の 3）。**腕が傾いて出力されると関節が近い高さに並び、Z 座標を境界とする分割が通らなくなる。このため M1 の出力は人手で確認してから次段へ渡す。

## 3.7 M2: 三次元形状生成

整形済み画像は image-to-3D サービス（Tripo3D）により三次元メッシュ（GLB 形式、Y-up 座標系）へ変換される（図 3.1 の M2、図 3.2 ③）。API 経由で、生成に用いる乱数の初期値（以下、生成のシード）を固定して呼び出す。

**生成サービスは出力メッシュのバウンディングボックスの最長辺を 1.0（= 1 m）に正規化する**（手元の GLB 4 件すべてで 1.0000）。したがって絶対寸法は入力画像の画素数や添えた寸法に依らず、**絵の中の比率だけで決まる**。利用者が絶対寸法を数値で指定する手段は無く、必要なら生成後に一様な倍率を掛ける。

## 3.8 M3: 関節検出とリンク分割

M3 は GLB メッシュから関節位置を検出し、メッシュをリンク単位に分割する（図 3.1 の M3、図 3.3）。

![**図 3.3**: M3 の途中経過（手描きスケッチ A1）。①〜③ は本文の 3 つの段階に対応する。{width=1.0}](figures/pipeline_m3_paper.png)

まず、UV テクスチャの色を頂点に焼き込み、各頂点に色を持たせる（図 3.3 ①）。

次に、マーカーの頂点を抜き出して関節を求める（図 3.3 ②）。目標色 $c_0$ と許容幅 $\tau$ に対し、各チャネルで $|c_i^{(k)} - c_0^{(k)}| \le \tau$ を満たす頂点をマーカーの頂点とする。生成の過程でマーカーの色は公称色からずれるため、$c_0$ と $\tau$ は固定せず、マゼンタの色相域（285〜345°）にある頂点クラスタの中央値と広がりから自動で較正する。該当クラスタが無ければ検出失敗として停止する。抜き出した頂点を**三次元で**連結成分に分け（連結の半径は外接寸法の 0.02 倍）、各成分の重心を関節とする。マーカー頂点全体の 2 % 未満の成分は色滲みのノイズとして捨てる。

最後に、関節の Z 座標（図 3.3 ③ の破線）を境界として、各ポリゴンを重心の Z で区分し、リンクごとの STL とする。境界の間にポリゴンが無ければ関節位置の異常として停止する（フェイルファスト）。

## 3.9 M4: 形態パラメータ抽出

分割された各リンクから、co-design の設計変数の初期値を求める（図 3.1 の M4）。結果は topology.json に書き出す。A1 での結果を図 3.4 に示す。

![**図 3.4**: M4 の抽出結果（手描きスケッチ A1）。各リンクの頂点を、骨の軸に沿った距離（縦軸）と骨からの距離（横軸）で描いた。破線が骨の軸、▲がそのリンクの関節、黒線が抽出した長さと半径によるカプセルである。{width=1.0}](figures/pipeline_m4_paper.png)

骨の軸は M3 の関節座標から決まるので、長さと半径はその軸に沿って測る。

- **リンク長** $L$: **関節と関節の距離**（M3 が保持する関節座標から求める。先端リンクは最後の関節から最も遠い点まで。図 3.4 の破線）
- **カプセル半径** $r$: **骨の軸に垂直な断面**の 2 方向の幅の平均の半分（図 3.4 の黒線の幅）

関節可動域とギア比の初期値はスケッチの幾何から一意に定まらないため、既定値（ギア比 100、可動域 ±90°）を用いる。設計空間の探索範囲（ギア比の上限、リンク長の伸縮の幅）と物理の値（リンクの密度、アクチュエータの回転子の慣性と速度の上限）は co-design 側の設定で与える（表 4.2）。

## 3.10 M5: シミュレーションモデル生成

topology.json は MuJoCo 互換 XML へ変換される（図 3.1 の M5）。各リンクをカプセルで近似し、子を親の先端に取り付ける入れ子の構造にして、関節とアクチュエータ（ギア比）を付ける（図 3.5 の右）。学習側では読み込み時に Choreonoid のモデル形式（.body）へ変換される。⚠️ 学習系はリンク数の異なる形態を扱えるが（第3章前段 3.3 節）、前段（M1〜M3）を 3 関節以外で実行した事例は無く、**M3 が検出した関節はどれも 3 つである**（縦型モードは根本に旋回関節を 1 つ足して 4 関節にする）。

![**図 3.5**: M5 が生成したモデル（手描きスケッチ A1、縦型モード）。左は初期姿勢（全関節 0°）の模型で、描いた腕の角度は持ち込まず、長さと太さだけを使う。右は XML の抜粋である。{width=1.0}](figures/pipeline_m5_paper.png)

関節軸は関節ごとに座標軸 x・y・z のいずれかを割り当てる。既定として、全関節をヨー軸としボーンを X 軸方向へ並べる**平面モード**と、根本をヨー軸・以降をピッチ軸とする**縦型モード**（図 3.5 の左）を用意する。**本論文が報告する実験の大半は平面モードによる。**⚠️ **軸の割り当ては入力形状から推定するものではなく、利用者が与える。**形状からの軸推定は今後の課題とする。

## 3.11 M6: co-design による評価・補正と判定

生成されたモデルを初期形態として Stackelberg PPO による形態-制御 co-design を実行する（図 3.1 の M6。枠組みは第3章前段、Leader が編集する量は表 4.1）。学習の進行に伴い、(i) 実行リターンの推移が**その形態系列のタスク達成度の評価**を、(ii) Leader による設計パラメータの更新が**スケッチ由来の初期値の補正**を与える。判定は学習曲線の順位で読む。所要学習量は 4.6.3 節で較正する。

## 3.12 M7: 形態診断

M7 は、不適合の原因と修正の方向を言語化して返す。追加の学習を要さず、M6 が生成する既存の成果物のみを入力とする。診断に生成 AI は用いず、閾値との比較で選んだ定型文に実測値を差し込んで返す。

### 3.12.1 三層構造

M7 は三つの層から成る（表 3.2）。第1層が用いるリンク長と目標位置は学習の結果にも乱数シードにも依らないのに対し、第2層・第3層が用いる学習の帰結はシードや打ち切りに依存する。そこで、総合判定（「この形ではタスクを達成できません」）を出すのは第1層だけとし、第2・3層は観察の報告に留める。図 3.1 の 2 つのひし形が、学習の前の第1層と学習の後の第2・3層に当たる。

**表 3.2**: 診断の三層

| 層 | いつ・入力 | 検出するもの | 返すもの |
|---|---|---|---|
| 第1層（幾何）・判定 | 学習前・初期 XML（数秒） | 目標が最大リーチの外にある／静止姿勢で先端が対象物に貫入する／関節軸の向きがタスクの想定と一致しない | 判定を覆すのに必要な最小の拡大倍率（例: 「腕全体を 1.99 倍に伸ばしてください」） |
| 第2層（収束形態）・報告 | 学習後・収束形態 | ギア比の探索範囲の上限・下限への張り付き | 上限なら出力不足。下限は押しタスクでのみ不適合の兆候 |
| 第3層（行動）・報告 | 学習後・行動トレース（1 エピソード） | 戦略（押し: 一撃で吹き飛ばす／穏やかに押す／触れられていない。到達: 目標で静止する／ずれて止まる／到達できない）と、各関節が可動域のうち使った割合 | 使用率 10 % 未満の関節を固定する候補。意図と異なる戦略なら代替タスク |

第1層の倍率は切り上げる（四捨五入では提示値が必要量を下回り、従っても判定が覆らない場合がある）。最小の変更のみを返すことは、反実仮想説明・実行可能なリコースの要件と一致する（2.4 節）。リンク長の総和が到達半径に等しいのは、各関節が直前のリンクの先端にあり、かつ平面アームである場合に限られるため、前者が破れた XML は棄却し、非平面アームでは旋回軸に平行なリンクを除いた水平限界で判定する。可動域を考えた到達判定は、格子の粗さに由来する余地を順運動学のリプシッツ定数で見積もり、**「届かない」側だけが確実になる**ように構成する。リンク長が学習中に伸びうる設定もあるため、第1層は「到達できない」という否定的判定のみを行う。

第2層で下限への張り付きを押しタスクに限るのは、到達タスクでは、目標に到達した形態でもギア比が下限に張り付くためである（4.4.3.1 節）。

### 3.12.2 第3層の閾値は判定規則ではなく候補生成器である

第3層の閾値（可動域の 10 %）は実験によって較正されていない（5.3 節の 5）。**ただし閾値が決めるのは「固定を試す価値のある関節」であって、「固定すべき関節」ではない。**採否は、助言どおり固定した形態を学習させ、元の形態と成績の範囲が重なるかどうかで決める（4.2.2 項の基準。結果は 4.5.5 項）。したがって閾値が不正確でも誤った助言は採用されないが、有効な助言を見落とす可能性は残る。本手法が秒で返すのは候補であって、採用の結論ではない。
