## 3.5 システム全体像

提案システムは、手描きスケッチを入力とし、描かれた形態が対象タスクに適しているかの判定結果と、不適合であった場合の修正方向を出力する。全体の構成を図 3.1 に示す。処理は 7 つの工程（M1〜M7）から構成され、図ではこれらを 4 つのフェーズに分けて示す。

![**図 3.1**: 提案システムの全体構成。上から順にフェーズ 1〜4 を示す。画像は手描きスケッチ A1 における各工程の出力であり、図 3.2〜3.5 と同じものである。色と矢印の意味は図の下の凡例に示す。{width=0.62}](figures/system_overview.pdf)

各フェーズの工程と入出力を表 3.2 に示す。

**表 3.2**: フェーズと工程

| フェーズ | 工程 | 入力 → 出力 | 節 |
|---|---|---|---|
| 1. 入力・画像整形 | M1 | 手描きスケッチ → 白背景・単一視点で再描画し、関節にマゼンタの球を描いた画像 | 3.6 |
| 2. 三次元化・リンク分割 | M2・M3・M4 | 画像 → 色付きの単一メッシュ → リンクごとのメッシュと関節位置 → 形態パラメータ | 3.7〜3.9 |
| 3. シミュレーションモデル生成 | M5 | 形態パラメータ → 各リンクをカプセルで近似した MuJoCo 互換 XML | 3.10 |
| 4. 評価・形態診断 | M7 第1層 → M6 → M7 第2・3層 | XML → 判定と助言。第1層で棄却した形態は学習に進めず、到達に必要な拡大倍率を提示する | 3.11・3.12 |

M7 が M6 の前後に分かれているのは、第1層が学習を要さず、第2・3層が学習の結果を入力とするためである。データは図の矢印に沿って一方向に流れるが、第1層で棄却された場合に限り、助言に従ってリンク長を N 倍した XML を第1層へ再入力する閉ループを持つ（図の破線、4.5.2 項）。

M1（画像整形）と M2（三次元形状生成）は、外部の生成 AI サービスを API 経由で呼び出す（サービスと版は付録D.2）。M3 以降（関節検出からモデル生成と学習の起動まで）は、単一のシェルスクリプトによって自動化している。

本システムの設計方針は次の 3 点である。第一に、関節の位置を形状から推定せず、上流（M1）で描かせたマーカーを下流（M3）で色検出して求める。生成モデルの出力の不確実性をパイプライン内部で補正するのではなく、入力を拘束することで、関節位置の特定を決定論的な処理とする。第二に、M3〜M5 を乱数や学習を含まない決定論的処理とし、失敗時の原因特定と再現性を担保する。第三に、M5 が既存の同時最適化の枠組みと互換な MuJoCo 互換 XML を出力することで、学習系の内部コードを改変せずに接続する。

## 3.6 M1: 画像整形と関節マーカー規約

3.6〜3.10 節では、手描きスケッチ A1（4.6.1 項）を例に、各工程の途中経過を図 3.2〜3.5 に示す。

![**図 3.2**: M1・M2 の入出力（手描きスケッチ A1）。① 手描きスケッチ、② M1 が再描画した画像、③ M2 が生成した三次元メッシュを横から見たもの。{width=1.0}](figures/pipeline_m12_paper.png)

入力スケッチは、画像生成 AI（Gemini）によって、後段の三次元化と色検出に適した画像へ再描画される（図 3.1 の M1、図 3.2 ①→②）。再描画した画像は、単一の視点から CAD のレンダリングを模して描画し、寸法線、文字、複数の視点を含めない。単一の視点に限るのは三次元化が 1 枚の画像を入力とするためであり、寸法線と文字を禁じるのは三次元化の際にそれらも立体として生成されるためである。この再描画に、本システムの中核である関節マーカー規約を固定プロンプトとして課す。この規約は、構造の推定を生成モデルに委ねるのではなく、構造の境界を明示的に描かせるものである。要点は次の 3 つである。

1. すべての関節接続部に純マゼンタ（#FF00FF）の球を 1 個ずつ描く。マゼンタは自然画像や工業製品にはまれな色相であり、色検出によって他の部分と分離しやすい
2. 各リンクを彩度の高い単色で塗り分け、グラデーションとマゼンタの使用を禁止する
3. 関節の位置を場所として列挙し（「台座と上腕の間」等）、描画後に球の個数を自己検査させる。列挙を欠くと、先端側の関節が機械要素として描き分けられ、マーカーが欠落する

これにより、M3 の関節検出は、精度の保証がない推定問題から、閾値付きの色マッチングという決定論的な問題に置き換えられる。プロンプトの全文は付録A に示す。

リンクは「両端が平らな円柱」として描くよう指示する。端が丸いと関節の球と区別しにくく、マーカーが省略されるためである。なお、出力のばらつきを最も小さくする設定（サンプリング温度 0、すなわち最も確からしい出力のみを選ぶ指定）にしても、マーカーの個数とリンク長の比が規約を満たすとは限らない。また、三次元化（M2）において腕が寝た姿勢で生成されると、関節が近い高さに並び、Z 座標を境界とする分割（3.8 節）が成立しない。そこで、M2 の出力についてマーカーの個数と関節の高さの広がりを検査し、いずれかが基準を満たさない場合は M3 へ進めない。リンク長の比の保存は手描き 5 例で確認したが（表 4.5）、個々の出力に対しては検査していない。

## 3.7 M2: 三次元形状生成

整形済み画像は image-to-3D サービス（Tripo3D）により三次元メッシュ（GLB 形式、Y-up 座標系）へ変換される（図 3.1 の M2、図 3.2 ③）。API 経由で、生成に用いる乱数の初期値（以下、生成のシード）を固定して呼び出す。

生成サービスは、出力メッシュのバウンディングボックスの最長辺を 1.0（= 1 m）に正規化する（本研究で得た GLB 4 件はすべて 1.0000）。したがって、絶対寸法は入力画像の画素数や画像に書き添えた寸法に依らず、画像内の比率のみによって定まる。利用者が絶対寸法を数値で指定する手段はないため、必要な場合は生成後に一様な倍率を乗じる。

## 3.8 M3: 関節検出とリンク分割

M3 は GLB メッシュから関節位置を検出し、メッシュをリンク単位に分割する（図 3.1 の M3、図 3.3）。

![**図 3.3**: M3 の途中経過（手描きスケッチ A1）。①〜③ は本文の 3 つの段階に対応する。{width=1.0}](figures/pipeline_m3_paper.png)

まず、UV テクスチャの色を頂点に焼き込み、各頂点に色を持たせる（図 3.3 ①）。

次に、マーカーの頂点を抽出して関節位置を求める（図 3.3 ②）。目標色 $c_0$ と許容幅 $\tau$ に対し、各チャネルで $|c_i^{(k)} - c_0^{(k)}| \le \tau$ を満たす頂点をマーカーの頂点とする。生成の過程でマーカーの色は公称色からずれるため、$c_0$ と $\tau$ は固定せず、マゼンタの色相域（285〜345°）にある頂点クラスタの中央値と広がりから自動的に較正する。該当するクラスタが存在しない場合は、検出の失敗として処理を停止する。抽出した頂点を三次元空間で連結成分に分け（連結の半径は外接寸法の 0.02 倍）、各成分の重心を関節位置とする。マーカー頂点全体の 2 % 未満の成分は、色の滲みによるノイズとして除去する。

最後に、関節の Z 座標（図 3.3 ③ の破線）を境界として、各ポリゴンを重心の Z で区分し、リンクごとの STL とする。境界の間にポリゴンが存在しない場合は、関節位置の異常として処理を停止する。

## 3.9 M4: 形態パラメータ抽出

分割された各リンクから同時最適化の設計変数の初期値を算出し、形態の構造と初期値をまとめた JSON ファイル（以下、topology.json）を作成する（図 3.1 の M4）。topology.json は、リンクごとに、名前と親リンク、関節（種類・軸・可動域）、リンク長、カプセルの半径、ギア比を保持する。手描きスケッチ A1 に対する抽出結果を図 3.4 に示す。図では、リンクごとに、メッシュの各頂点を骨の軸に沿った距離（縦軸）と骨からの距離（横軸）の平面に描き、骨の軸を破線、そのリンクの関節をマゼンタの▲、抽出した長さと半径によるカプセルを黒線で重ねた。

![**図 3.4**: M4 によるリンクごとの長さと半径の抽出結果（手描きスケッチ A1）。{width=1.0}](figures/pipeline_m4_paper.png)

各リンクの両端の関節（先端リンクでは最後の関節と最も遠い点）を結ぶ線分を骨と呼び、長さと半径は、M3 の関節座標から定まる骨の軸に沿って測定する。

- **リンク長** $L$: 関節と関節の距離（M3 が保持する関節座標から求める。先端リンクは最後の関節から最も遠い点まで。図 3.4 の破線）
- **カプセル半径** $r$: 骨の軸に垂直な断面における 2 方向の幅の平均の半分（図 3.4 の黒線の幅）

半径を断面の幅の平均から求めるため、台座のように断面の幅が一様でないリンクでは、カプセルはメッシュの一部を覆わない。また、先端リンクの長さは最後の関節から最も遠い点までとするため、カプセルの端の半球はメッシュの先端より外へ出る（図 3.4 の右端）。

関節可動域とギア比の初期値はスケッチの幾何から一意に定まらないため、既定値（ギア比 100、可動域 ±90°）を用いる。設計空間の探索範囲（ギア比の上限、リンク長の伸縮の幅）と物理の値（リンクの密度、アクチュエータの回転子の慣性と速度の上限）は同時最適化側の設定で与える（表 4.2）。

## 3.10 M5: シミュレーションモデル生成

topology.json は MuJoCo 互換 XML へ変換される（図 3.1 の M5）。各リンクをカプセルで近似し、子を親の先端に取り付ける入れ子の構造にして、関節とアクチュエータ（ギア比）を付与する（図 3.5 の右）。学習側では読み込み時に Choreonoid のモデル形式（.body）へ変換される。なお、学習系はリンク数の異なる形態を扱えるが（第3章前段 3.3 節）、上流の工程（M1〜M3）を 3 関節以外の形態で実行した事例はなく、M3 が検出した関節はいずれも 3 つである。初期姿勢は全関節 0° とし、スケッチに描かれた関節角は用いない。

関節軸には、関節ごとに座標軸 x、y、z のいずれかを割り当てる。既定として、全関節をヨー軸として骨を X 軸方向へ並べる平面モードと、根元をヨー軸、それ以降をピッチ軸とする縦型モード（図 3.5 の左）を用意する。縦型モードでは、根元に旋回関節を 1 つ追加して 4 関節とする。本論文が報告する実験の大半は平面モードによる。軸の割り当ては入力形状から推定するものではなく利用者が与えるものであり、形状からの推定は今後の課題とする（5.3 節の 6）。

![**図 3.5**: M5 が生成したモデル（手描きスケッチ A1、縦型モード）。左は初期姿勢（全関節 0°）の模型（▲が関節）、右は XML の入れ子の構造を擬似コードで示したものである。{width=1.0}](figures/pipeline_m5_paper.png)

## 3.11 M6: 同時最適化による評価・補正と判定

生成されたモデルを初期形態として Stackelberg PPO による形態と制御の同時最適化を実行する（図 3.1 の M6。枠組みは第3章前段、Leader が編集する量は表 4.1）。学習の進行に伴い、(i) 実行リターンの推移はその形態系列のタスク達成度の評価を与え、(ii) Leader による設計パラメータの更新はスケッチ由来の初期値の補正を与える。判定は学習曲線の順位に基づいて行い、判定に要する学習量は 4.6.3 節で較正する。

## 3.12 M7: 形態診断

M7 は、不適合の原因と修正の方向を言語化して提示する。追加の学習は必要とせず、M6 が生成する既存の成果物のみを入力とする。診断は、閾値との比較によって選択した定型文に実測値を埋め込んで出力する。

### 3.12.1 三層構造

M7 は三つの層から成る（表 3.3）。第1層が用いるリンク長と目標位置は学習の結果にも乱数シードにも依らないのに対し、第2層と第3層が用いる学習の結果は、シードや学習の打ち切り時点に依存する。そこで、総合判定（「この形ではタスクを達成できません」）を出力するのは第1層のみとし、第2・3層は観察結果の報告に留める。図 3.1 の二つのひし形は、学習前の第1層と学習後の第2・3層に対応する。

**表 3.3**: 診断の三層

| 層 | いつ・入力 | 検出するもの | 出力 |
|---|---|---|---|
| 第1層（幾何）・判定 | 学習前・初期 XML（数秒） | 幾何によって定まる不適合（下記の三つ） | 判定を覆すのに必要な最小の拡大倍率（例: 「腕全体を 1.99 倍に伸ばしてください」） |
| 第2層（収束形態）・報告 | 学習後・収束形態 | ギア比の探索範囲の上限・下限への張り付き | 上限なら出力不足の可能性。下限は押しタスクでのみ不適合の兆候 |
| 第3層（行動）・報告 | 学習後・行動トレース（1 エピソード） | 戦略（押し: 一撃で吹き飛ばす／穏やかに押す／触れられていない。到達: 目標で静止する／ずれて止まる／到達できない）と、各関節が可動域のうち使用した割合 | 使用率 10 % 未満の関節を固定する候補。意図と異なる戦略なら代替タスク |

第1層は、次のいずれかに該当する形態を「この形ではタスクを達成できない」と判定する。

- **目標に到達できない**（到達タスク）: 根元から目標までの水平距離が腕の到達半径を超える。腕全体の拡大倍率 $N$ を提示する。目標がリンク長の差によって生じる内側の到達不能な円の中にある場合は、リンク長を揃えるか目標を遠ざけるよう提示する。
- **対象を押し込めない**（押しタスク）: 対象の初期位置の分布のうち最も奥にある対象に対して、先端が触れたうえで押し込むことができない。拡大倍率 $N$ を提示する。対象が横方向にも分布する場合は、分布の端にある対象にも到達できるかを判定する。
- **目標が腕の動作平面の外にある**（平面アーム）: 全関節の軸が同じ向きであり、目標の高さが腕の動作平面からずれている。関節軸の向きがタスクの想定と異なる可能性を提示する。

このほか、静止姿勢で先端が対象物に貫入しうる形態には、判定ではなく警告として、対象から逸らした初期姿勢で学習を開始するよう提示する。

第1層が提示する倍率 $N$ は次式で求める。

$$N = \left\lceil \frac{d}{L} \right\rceil_{0.01}$$

ここで、$L$ は腕の到達半径、$\lceil \cdot \rceil_{0.01}$ は 0.01 単位の切り上げである。$d$ は、到達タスクでは根元から目標までの水平距離である。押しタスクでは、対象の初期位置の分布のうち最も奥にある対象に先端が触れる距離 $d_{\mathrm{touch}}$ に、押し込む距離 $d_{\mathrm{push}} = 0.1$ m を加えた値とする。$d_{\mathrm{push}}$ を加えるのは、$d_{\mathrm{touch}}$ のみでは最も奥の対象に触れても押し込めないためである（4.5.4 項）。その値は、押しタスクの成否を判定する対象の移動量（4.5.4 項）と同じとした。倍率を切り上げるのは、四捨五入では提示値が必要量を下回り、助言に従っても判定が覆らない場合があるためである。最小の変更のみを提示することは、反実仮想説明および実行可能なリコースの要件と一致する（2.4 節）。リンク長の総和が到達半径に等しくなるのは、各関節が直前のリンクの先端にあり、かつ平面アームである場合に限られる。そのため、前者の条件を満たさない XML は棄却し、非平面アームについては旋回軸に平行なリンクを除いた水平方向の限界で判定する。可動域を考慮した到達判定では、格子の粗さに由来する誤差の余地を順運動学のリプシッツ定数で見積もり、「到達できない」という判定のみが確実になるように構成する。また、リンク長が学習中に伸びうる設定もあるため、第1層は「到達できない」という否定的な判定のみを行う。

第2層で下限への張り付きを押しタスクに限るのは、到達タスクでは、目標に到達した形態でもギア比が下限に張り付くためである（4.4.3.1 節）。

### 3.12.2 第3層の閾値の位置づけ

第3層の閾値（可動域の 10 %）は実験によって較正されていない（5.3 節の 5）。この閾値が定めるのは「固定を試行する価値のある関節」であり、「固定すべき関節」ではない。採否は、助言に従って関節を固定した形態を学習させ、元の形態と成績の範囲が重なるかどうかによって判断する（4.2.2 項の基準。結果は 4.5.5 項）。したがって、閾値が不正確であっても誤った助言が採用されることはないが、有効な助言を見落とす可能性は残る。本手法が秒単位で提示するのは候補であり、採用の結論ではない。
