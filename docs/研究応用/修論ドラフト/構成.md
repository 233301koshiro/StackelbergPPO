# 修論の構成 — 各章・節が何を担うか

> **役割**: 「どこに何を書くか」を一枚で示す。**執筆中に迷ったときの行き先表**。
> ⚠️ **末尾の見出し一覧は生成物である。** 手で直さない。節を足したら次で再生成する。
>
> ```
> python3 scripts/dump_thesis_outline.py --write    # 一覧を更新
> python3 scripts/dump_thesis_outline.py --check    # 本文と食い違わないか検査
> ```
>
> ⚠️ **本文が正。**この md は説明を持つだけで、**数値も結論も持たない**（CLAUDE.md §4-2 の③派生層）。

## 全体の設計

**第4章の 4 つの軸が、そのまま主張の単位である。** 章立ては軸に従っている。

| 軸 | 問い | 章での扱い |
|---|---|---|
| 軸1 | **前段は通るか**（入力からモデル生成まで） | 手法 3.6〜3.10 / 実験 4.2 |
| 軸2 | **エンジンは妥当か**（形態を正しく順序づけるか） | 手法 3.11 / 実験 4.3 |
| 軸3 | **助言は使えるか** | 手法 3.12 / 実験 4.4 |
| 軸4 | **システムとして成立するか** | 実験 4.5 |

**層の分担**（CLAUDE.md §4-2 の 4 層と対応する）

| 章 | 持つもの | 持たないもの |
|---|---|---|
| 第3章 | **手法と、その設計にした理由** | ⚠️ **実験値**（第4章へ） |
| 第4章 | **測った値と条件** | ⚠️ **方法論の教訓**（第5章へ 1 回だけ） |
| 第5章 | **なぜそうなるかの解釈** | 手法の説明 |
| 第6章 | **結論・限界・課題** | 新しい数値 |

⚠️ **苦労話は書かない。** 修論は最終的な値とその根拠を述べる場で、
「プラン A で困ってプラン B にした」は台帳（実験系譜）へ（CLAUDE.md §4-2）。
**判定は「その文を消すと読者が『なぜこの値か』を答えられなくなるか」。**

## 各章が担うもの

### 第1章 序論
背景（生成 AI でソフトは速くなったが機体モデルの供給が追いつかない＝律速段階）、
既存技術の三つの障壁、アプローチと目的、**貢献 6 点**、論文の構成。
⭐ **貢献 2「判定に必要な入力の特定」が本研究の切り口**である
（リンクの中核要素だけで適性が測れる）。**序論で主張し、第6章 6.2.2 で証明する。**

### 第2章 関連研究
4 系統（スケッチ三次元化・可動構造推定・co-design・判定とフィードバック）への差分。
⭐ **2.5 が要。新規性は個々の改良ではなく三領域の結合である**と明言する。

### 第3章前段 前提
借りている土台の説明。階層ゲームとしての co-design、報酬設計の規定、方策の構造、実装構成。

### 第3章 提案手法
3.5 で全体像、3.6〜3.12 で M1〜M7 を順に述べる。**各節は「何をするか」と「なぜその設計か」を持つ。**

| 3.6 M1 画像整形 | マーカー規約。3.6.1 に**改訂履歴 6 版と規約遵守の非決定性** |
| 3.7 M2 三次元化 | 3.7.1 に**スケールの決まり方（三つの「1」の区別）** |

### 第4章 実験および評価
4.1 が共通設定（ロボット・タスク・ハイパーパラメータ・指標・**要求仕様**）。以降は軸ごと。

| 節 | 担うもの |
|---|---|
| 4.2 軸1 | 接続の成立と、**生成 AI の出力ブレに対する許容幅** |
| 4.3 軸2 | R1 形態最適化の必要性 / R2 タスクが形態に反映 / **R3 順序づけ** / R4 学習量 |
| 4.4 軸3 | 閉ループの構成・**そこで見つかった指針の欠陥**・是正後の有効性 |
| 4.5 軸4 | 接続・所要時間・**未達の項目**・関節固定の閉ループ |
| 4.6 | 結果の要約 |

⚠️ **4.3.3 が本研究の中心**（形態集合を正しく順序づけられるか）。
前向き判定 → パイプライン生成形態 → マトリクス → **配分判別**と、
「幾何で分かる範囲」から「幾何の外側」へ順に進む構成になっている。

### 第5章 考察
**「なぜそうなるか」だけを持つ。** 実験値は第4章、手法は第3章。

| 節 | 担うもの |
|---|---|
| 5.1 | タスク識別の機序（形態が何で分化するか） |
| 5.2 | **設計論の知見 5 点**（報酬の複雑化・シェーピング・境界・ペナルティ・長期学習） |
| 5.3 / 5.4 | 転用の構造 / 成分分解 |
| 5.5 | **なぜ三層に分けたか**。⭐ 層はコストではなく**確定性**で分かれる |
| 5.6 | フェーズ0 支援としての実用性 |
| 5.7 | **限界（スコープの宣言と個別の限界）** |

### 第6章 結論
6.1 で 3 つの問いへの到達、6.2 で**主要な結論 5 点**、6.3 設計知見、
6.4 位置づけと**限界 7 件**、6.5 **今後の課題 10 件**。

⚠️ **限界は二段構え。** 5.7.1 がスコープの宣言、6.4.2 が個別の限界。
**同じ限界を両方に書かない。** 前者は「何を扱わないか」、後者は「扱ったが届かなかったこと」。

## 節を足すときの手順

1. **どの層に属するか**を上の表で決める（手法／値／解釈／結論）
2. 挿入した位置より後ろの**節番号を繰り下げ**、`grep` で**他章・他 md の参照を同期**する
   （2026-09-13 は 3.12.5 の挿入で **7 ファイル 13 箇所**が動いた）
3. **表番号の重複**を確認する（同じ章に 2 つ同じ番号が出やすい）
4. `python3 scripts/dump_thesis_outline.py --write` で下の一覧を更新する
5. `check_citations.py` / `check_stale_claims.py` / `check_docs_consistency.py` を回す
