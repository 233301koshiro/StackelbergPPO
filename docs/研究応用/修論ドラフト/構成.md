## 全体の設計

**第4章の 4 つの軸が、そのまま主張の単位である。** 章立ては軸に従っている。

| 軸 | 問い | 章での扱い |
|---|---|---|
| 軸1 | **前段は通るか**（入力からモデル生成まで） | 手法 3.6〜3.10 / 実験 4.3 |
| 軸2 | **エンジンは妥当か**（形態を正しく順序づけるか） | 手法 3.11 / 実験 4.4 |
| 軸3 | **助言は使えるか** | 手法 3.12 / 実験 4.5 |
| 軸4 | **システムとして成立するか** | 実験 4.6 |

**層の分担**（CLAUDE.md §4-2 の 4 層と対応する）

| 章 | 持つもの | 持たないもの |
|---|---|---|
| 第3章 | **手法と、その設計にした理由** | ⚠️ **実験値**（第4章へ） |
| 第4章 | **測った値と条件** ＋ **各実験直後の考察** | ⚠️ 手法の説明（第3章へ） |
| 第5章 | **結論・位置づけ・課題** | 新しい数値 |
| **付録D** | **条件と全データ** | 本文は結論のみ |

⚠️ **苦労話は書かない。** 修論は最終的な値とその根拠を述べる場で、
「プラン A で困ってプラン B にした」は台帳（実験系譜）へ（CLAUDE.md §4-2）。
**判定は「その文を消すと読者が『なぜこの値か』を答えられなくなるか」。**

## 各章が担うもの

### 第1章 序論
背景（生成 AI でソフトは速くなったが機体モデルの供給が追いつかない＝律速段階）、
既存技術の三つの障壁と本研究のアプローチ（1.2。課題を受けてアプローチを述べる先輩の序論の形にそろえた、10-19）、目的と**貢献 3 点**（1.3）、論文の構成。
⭐ **貢献 2「判定に必要な入力の特定」が本研究の切り口**である
（リンクの中核要素だけで適性が測れる）。**序論で主張し、5.2.2 節で証明する。**

### 第2章 関連研究
4 系統（スケッチ三次元化・可動構造推定・co-design・判定とフィードバック）への差分。
⭐ **2.5 が要。新規性は個々の改良ではなく三領域の結合である**と明言する。

### 第3章前段 前提
借りている土台の説明。階層ゲームとしての co-design、報酬設計の規定、方策の構造、実装構成。

### 第3章 提案手法
3.5 で全体像、3.6〜3.12 で M1〜M7 を順に述べる。**各節は「何をするか」と「なぜその設計か」を持つ。**

| 3.6 M1 画像整形 | マーカー規約と、温度 0 でも規約を満たすとは限らないこと（人手で確かめる理由） |
| 3.7 M2 三次元化 | GLB への変換と、スケールの決まり方（最長辺を 1 m にそろえるので比だけで決まる） |
| 3.8 M3 関節検出・分割 | マゼンタ検出と Z 座標での分割 |
| 3.9 M4 パラメータ抽出 | 長さと太さ。**どちらも外接直方体を使わない理由** |
| 3.10 M5 モデル生成 | XML 変換と関節軸の二モード |
| 3.11 M6 判定 | co-design を判定器として使う構成 |

### 第4章 実験および評価
4.1 が実験の条件（ロボット・物理・タスク・ハイパーパラメータ）、4.2 が評価の枠組み（**要求仕様**・実験の一覧・指標・順位の判定）。以降は軸ごと（2026-10-21 に組み替え）。

| 節 | 担うもの |
|---|---|
| 4.3 軸1 | 接続の成立と、**生成 AI の出力ブレに対する許容幅** |
| 4.4 軸2 | R1 形態最適化の必要性 / R2 タスクが形態に反映 / **R3 順序づけ**（R4 学習量は 4.6.3） |
| 4.5 軸3 | 閉ループの構成・**そこで見つかった指針の欠陥**・是正後の有効性 |
| 4.6 軸4 | 接続・所要時間・R4 学習量・**未達の項目**・考察 |
| 4.7 | 実証題材（エアホッケーの打ち込み） |

⚠️ **4.4.3 が本研究の中心**（形態集合を正しく順序づけられるか）。
前向き判定 → パイプライン生成形態 → マトリクス → **配分判別**と、
「幾何で分かる範囲」から「幾何の外側」へ順に進む構成になっている。

## 節を足すときの手順

1. **どの層に属するか**を上の表で決める（手法／値／解釈／結論）
2. 挿入した位置より後ろの**節番号を繰り下げ**、`grep` で**他章・他 md の参照を同期**する
   （2026-09-13 は 3.12.4 の挿入で **7 ファイル 13 箇所**が動いた）
3. **表番号の重複**を確認する（同じ章に 2 つ同じ番号が出やすい）
4. `python3 scripts/dump_thesis_outline.py --write` で下の一覧を更新する
5. `check_citations.py` / `check_stale_claims.py` / `check_docs_consistency.py` を回す
