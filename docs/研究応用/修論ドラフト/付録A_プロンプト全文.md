> **改訂前の本付録には A.1（ゼロから生成する版）しか収録していなかった。**

本付録は 2 種類のプロンプトを収録する。

| | 用途 | 本論文での使用箇所 |
|---|---|---|
| **A.1** | 入力画像を用いずゼロから生成する | 第4章の `tripo_arm_v2c`（4.3.1 項）の生成 |
| **A.2** | **手描きスケッチを入力として整形する** | **第4章 4.6 の end-to-end 実走 5 件すべて** |

A.2 は、各スケッチの実測の比を入れて `scripts/make_m1_prompt.py` が出力したものを転記した。

## A.1 ゼロから生成する版

本付録は、第3章 3.6節「M1: 画像整形と関節マーカー規約」で述べた関節マーカー規約を、画像生成 AI（Gemini）に対する固定プロンプトとして課した際の全文である（3関節アームの例）。

```text
以下の仕様に従い、3関節ロボットアームを機械設計図スタイルで描いてください。

【形状・姿勢 — 最重要】
- 固定台座から垂直に伸びるシリアルチェーンアーム（根元が下・先端が上）
- リンク1（上腕）: 台座から伸びる中太の円柱カプセル
- リンク2（前腕）: 上腕より細く1.5倍長い円柱カプセル
- リンク3（先端）: 平たいパドル・へら形状

【関節マーカー — 最重要・省略厳禁】
すべての接続部に、純マゼンタ (#FF00FF) の球を1個ずつ描くこと。具体的には以下の3箇所:
1. 台座と上腕（赤）の間
2. 上腕（赤）と前腕（青）の間
3. 前腕（青）と先端パドル（緑）の間 ← ここも省略しないこと
- 3箇所すべて同じ様式（リンクより太いマゼンタの球）で統一すること。
  先端側の関節だけを金具・ヒンジ・ブラケット等の機械要素で描くのは禁止
- 描き終えたら、マゼンタの球がちょうど3個あることを確認すること

【色分け — グラデーション禁止・各色を単色で塗ること】
- ベース台座: 濃いグレー (#333333)
- リンク1（上腕）: 鮮明な赤 (#FF2222)
- リンク2（前腕）: 鮮明な青 (#2222FF)
- リンク3（先端パドル）: 鮮明な緑 (#22CC22)
- 関節球: 純マゼンタ (#FF00FF)
  ※ マゼンタはアーム本体色（赤・青・緑・グレー）には絶対に使わないこと（自動検出用のため）

【スタイル】
- 白背景
- CADソフトウェアのレンダリング風（プラスチック質感・影あり・幾何学的）
- 斜め45度視点（3/4アングル）、ロボット全体が収まる構図
```

## A.2 手描きスケッチを入力とする版

**第4章 4.6 の end-to-end 実走（A1・A2・A3・B1・B2 の 5 件）はすべて本節のプロンプトを用いた。**
A.1 との主な差は次の 4 点である。

| 差 | 理由 |
|---|---|
| **【最優先: スケッチの構造を保つこと】節の新設** | 生成 AI が「きれいに直す」ためにリンク長比を変える事例があった |
| **「必ず立て直して描くこと」を向きの例外として明示** | M3 のリンク分割は Z 座標を境界とするため、腕が寝ていると分割が原理的に通らない |
| **【描いてはいけないもの】節の新設** | 寸法線が入ると三次元化がそれを立体として拾い、外接寸法が変わって縮尺が狂う |
| **リンク長比の明示（1 枚ごとに異なる）** | 手描きから実測した比を数値で固定する。下例の「2 / 1.7 / 1.1」がこれにあたる |

⚠️ **向きの制約は「スケッチに忠実」という最優先事項と衝突しうる。** 衝突を残したまま運用すると、
寝た絵を入力したとき寝たまま生成されうる。そのため**向きのみを明示的な例外として書く**。

以下は A1（リンク長比 2 / 1.7 / 1.1）に対して生成したものである。
**比の 3 数値のみが 1 枚ごとに変わり、他の全文は共通である。**

```text
添付した手描きスケッチのロボットアームを、下記の仕様に従って
機械設計図スタイルの画像に描き直してください。

【最優先: スケッチの構造を保つこと】
- リンクの本数、各リンクの長さの比、関節の位置は、スケッチに忠実に従うこと
- **ただし全体の向きは例外。** スケッチが斜めや横向きに描かれていても、
  **必ず「根元が下・先端が上」の縦向きに立て直して描くこと**。
  保つのは「比と関節の位置関係」であって「紙の上での傾き」ではない
- スケッチにない関節を足したり、あるものを省いたりしないこと
- 全体のプロポーション（台座の高さに対する各リンクの長さの比）を変えないこと
- 台座の高さを 1 としたとき、リンクの長さは根元から 2 / 1.7 / 1.1 である。この比を変えないこと
- スケッチが粗くても、読み取れる構造をそのまま反映すること。
  「きれいに直す」ためにリンク長の比を変えるのは禁止
- スケッチの紙にある罫線は無視すること。罫線を図の一部として描かないこと

【形状・姿勢 — 最重要】
- 固定台座から垂直に伸びるシリアルチェーンアーム（根元が下・先端が上）
- **腕全体を寝かせない。** 元のスケッチが寝ていても立てること（上の【最優先】の例外を参照）
- 各リンクは**両端が平らな円柱**。⚠️ **端を丸めない（カプセル状にしない）**。
  丸い端は関節球と紛らわしく、後段の関節検出が壊れる
- 先端リンクのみ、やや太い円柱でよい
- 関節が同じ高さに並ばないよう、各リンクに角度をつけて描くこと

【関節マーカー — 最重要・省略厳禁】
すべての接続部に、純マゼンタ (#FF00FF) の球を1個ずつ描くこと。具体的には以下の3箇所:
1. 台座と上腕（赤）の間
2. 上腕（赤）と前腕（青）の間
3. 前腕（青）と先端（緑）の間 ← ここも省略しないこと
- スケッチで隣り合うリンクがほぼ一直線に並んでいる場合も、その境目に必ずマゼンタ球を描くこと。
  2本のリンクを1本の長いリンクとして描くのは禁止
- 球は**両側のリンクから明確にはみ出させること**（リンクに埋まって見えない球は検出で見落とされる）。
  ⚠️ **ただしリンクを短くしてまで球を大きくしないこと。**リンク長の比が最優先である
- 3箇所すべて同じ様式（リンクより太いマゼンタの球）で統一すること。
  先端側の関節だけを金具・ヒンジ・ブラケット等の機械要素で描くのは禁止
- **1つの関節に球は1個だけ**。ブラケットや金具の両側にそれぞれ球を置くなど、
  **同じ関節に2個描くのは禁止**（後段が関節を余分に検出して壊れる）
- 描き終えたら、マゼンタの球がちょうど3個あることを確認すること

【描いてはいけないもの】
- **寸法線・矢印・数値・注釈・文字**。比を数値で指示しているが、それは**あなたが従うための情報**であって
  **絵に描き込むものではない**。寸法線が入ると後段の三次元化がそれを立体として拾い、
  さらに図の外接寸法が変わって縮尺が狂う
- 指・グリッパ・ハンド・分岐（先端はリンクのまま終わる）
- 複数のビュー。**1つの視点だけ**を描くこと

【色分け — グラデーション禁止・各色を単色で塗ること】
- ベース台座: 濃いグレー (#333333)
- リンク1（上腕）: 鮮明な赤 (#FF2222)
- リンク2（前腕）: 鮮明な青 (#2222FF)
- リンク3（先端）: 鮮明な緑 (#22CC22)
- 関節球: 純マゼンタ (#FF00FF)
  ※ マゼンタはアーム本体色には絶対に使わないこと（自動検出用のため）

【スタイル】
- 白背景
- CADソフトウェアのレンダリング風（プラスチック質感・影あり・幾何学的）
- 斜め45度視点（3/4アングル）、ロボット全体が収まる構図
```

**関節数が 3 以外の場合**、マーカー節の列挙と個数の自己検査の数値が対応して変わる。
本論文で扱った 5 件はいずれも 3 関節である。
