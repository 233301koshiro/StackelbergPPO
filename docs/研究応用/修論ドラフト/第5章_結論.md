## 5.1 研究目的の達成

本研究は、ハードウェアの専門知識を持たない開発者が、手描きスケッチから出発してロボット形態のタスク適性をシミュレーション上で検証できる環境を構築することを目的とし、次の 3 つのリサーチクエスチョンを設定した。

1. **RQ1（システムの成立）**: スケッチに由来する形態について、モデル生成から適性判定、不適合であった場合の修正指針の提示までを、専門知識を要さない形で接続できるか
2. **RQ2（検証エンジンの妥当性）**: 中核に据えた形態-制御 co-design は、タスクの要求に照らして形態を正しく順序づけ、かつそれを返すのにどれだけの学習量を要するか
3. **RQ3（フィードバックの有用性）**: システムが返す修正指針は、設計のやり直しに実際に使えるか

⭐ **最大の結論は RQ1 に対するものである。**生成 AI が出力した三次元形状から、関節構造の自動抽出・モデル生成・co-design 学習の起動・適性判定・修正指針の提示までが一つのシステムとして接続された。設計者に要求されるのは形状の入力のみであり、関節可動域の定義、回転軸の指定、質量特性の算出といった機械工学の知識は要さない。⭐ **手描きの線画そのものを入力とする end-to-end の実走も 4 例を完了している。**

⚠️ **未達は、手描き入力の実走を API 経路で取り直していないこと**（実走は画像整形と三次元形状生成を対話的インタフェースで行った）**と、専門知識を持たない利用者を対象とした評価**である。いずれも 5.4 節の今後の課題に対応する。

## 5.2 主要な結論

### 5.2.1 スケッチから適性判定までを通すシステムが成立した

関節マーカー規約に基づく画像から、三次元形状生成・関節検出・リンク分割・モデル生成・学習起動・適性判定・修正指針の提示までが接続された（第3章、第4章 4.2〜4.5 節）。RQ1 に対しては、スケッチ由来の形態をシミュレーション上で評価するシステムを構築できたと結論づける。⚠️ ただし前段の生成は決定的ではなく、学習による比較には形が明確に違う候補で約 4 時間を要し、外部サービスの取得には人手が残る（4.2・4.5 節）。

### 5.2.2 判定に必要な入力は形態の中核要素のみである

**判定が要求する入力は、リンクの本数・長さの比・関節位置と関節軸の割り当てに限られる。**質量・材料・アクチュエータの型番・部材の断面形状は与えていない。それでもタスクによって最良形態の順位が入れ替わり（4.3.3.3 節）、幾何診断が同一の出力を返す形態対にも順序が付き（4.3.3.4 節）、三層診断の総合判定は 6 条件すべてで実測と一致した（4.4.1 節）。⭐ **したがって判定は線画を一枚描いた時点に置ける。**本手法の位置は「線画と精密設計の間」ではなく「線画の直後」であり、⚠️ 細部の動力学が判定にほとんど入らないことはその裏面である（5.3 節 (C)、5.4 節 7）。

### 5.2.3 検証エンジンはタスクに適した形態を識別する

タスクのみを変えたときに収束形態が分かれるかを、スケッチ由来の縦型 4 関節アームで調べた（各 2 シード、4.3.2 節）。**ギア比は 4 関節すべてで、到達と押しの範囲が重ならなかった。**押しは第2〜第4関節で探索範囲の上限に近いギア比を、到達は第2関節で下限を選んだ。両タスクとも学習は成立しており（押しは箱を 5.3〜6.4 m 運び、到達は目標まで 0.1〜1.8 mm）、収束形態の違いはタスクの要求の違いとして読める。⚠️ 根元の関節の隙間は小さく（6.3 N·m）、到達の第2関節は探索範囲の下限に張り付いており、先端リンクの太さはタスクを分けない。非平面 4 関節アームの結果は付録D に示す（空欄: 系譜 9-246）。⚠️ 各条件 1〜2 シードであり、主張は初期的な一貫性の確認に留める（5.3 節 (A)）。

### 5.2.4 修正指針に従えば不適合は解消するが、その実行可能性は判定の正しさとは独立に壊れうる

診断が返した拡大倍率を適用しただけで、到達タスクの平均残存距離は 397 mm から 0.33 mm へ三桁改善した（2 シード、4.4.4 節）。⭐ **ただし助言の実行可能性は判定の正しさとは独立に壊れうる。**判定が 6 条件すべてで実測と一致していたにもかかわらず、助言に従った形態を同じ診断が再び却下し（倍率の丸め方向。4.4.3 節）、是正後には助言どおりに形態を生成する工程にも欠陥が見つかった（4.4.4 節）。いずれも助言を適用した形態を再入力する閉ループを構成して初めて現れた。⭐ **反実仮想的な助言を返すシステムは、出力の正しさとは別に、出力の実行可能性を検証する手順を持たなければならない。**

### 5.2.5 判定は実在の部材とアクチュエータに基づく設計空間で行った

設計空間の境界と物理の値を、アルミニウム薄肉パイプと協働ロボット（UR5e）の諸元から導き、本研究の全実験をその条件で行った（4.1.1 節 表 4.2）。（空欄: 系譜 9-246。この条件で R2・R3 が成立したかを結果を見て書く）⚠️ 粘性減衰・可動域・制御コスト・接触の摩擦には実在の値の根拠が無い（5.3 節 (C)）。

原論文の枠組みを据え置き型アームへそのまま移すと判定器として使う前提が崩れるため、報酬・タスク条件・初期形態の扱いを定め直した（4.1.6）。

## 5.3 本研究の位置づけと限界

⭐ **本研究の成果はアルゴリズムの改良ではなく、これまで独立に発展してきた領域を結合した設計支援のシステムである。**スケッチからの形状生成、co-design、反実仮想説明に立脚した設計フィードバックはいずれも既存の研究領域に属し、本研究はこれらを**専門知識を持たない設計者が概念設計段階で使える一つのパイプラインとして接続した**（差分は 2.5 節 表 2.1）。⭐ **このシステムにおいて co-design は「最適形態を自動設計する手法」ではなく「形態のタスク適性を判定する検証エンジン」として用いられる。**

⚠️ **本研究のスコープはシミュレーション環境における初期判定に限定され、実機ハードウェアの構築と sim-to-real gap の解決はスコープ外である。**あわせて、本研究が用いる「妥当」の語は想定利用者が同じ語で意味するものと一致しない。本研究の「妥当」は**タスクを達成できるか**を指し、関節の実装可能性・部材の強度・組立可能性を含む**製作可能性は判定しない**。したがって本手法の出力は「このタスクに向く形態の候補」であって「製作してよい設計」ではない。⚠️ **この区別が影響するのは主張ではなく、判定を経た形態を製作へ引き渡せるという利用経路の完結性である。**

限界は次の 4 群に整理できる。

**(A) 検証の範囲と統計的信頼性。** 検証はパイプライン由来の水平3関節とスケッチ由来の4関節の固定根本アームで行い、非平面4関節への再現は確認したが（付録D）、非平面形態における識別の強弱は主張しない。全方向到達や移動型形態への一般化は範囲外である。各条件のシード数は 1〜2 で統計的検定を行っていないため、**本論文では「頑健」の語を用いず、主張は「シード間で初期的な一貫性が確認された」の水準に留める。**手描き入力から規約準拠のモデル生成まで到達した事例も 5 件であり、前段の頑健性を成功率として報告できる件数ではない。エアホッケー（4.6 節）は、ゴール口と初期位置の幅を当初の仕様より緩め、制御コストを 0 とした条件での結果である。当初の仕様での達成と、現実的な出力の範囲での達成は主張せず、2 つの緩和のどちらが効いたかも分離していない。

**(B) 入力側の制御可能性。** 判定対象の絶対的な大きさは生成モデルの出力に依存し、本手法から制御できない。一方タスク側の目標位置は絶対座標で与えられるため、**このスケール不整合は形態最適化では吸収できない。**本研究はこれをスコープ外と宣言し、不整合を検出して必要な拡大倍率を返す立場をとる（3.12 節）。また外部サービスは API 経由でパラメータを固定できるが（3.13 節）、⛔ **画像生成は低温設定でも出力が一意に定まらず、再現できるのは「後段が使う量の一致」までであって生成物の同一性ではない。**⛔ **4.5 節が報告する実走 5 件は API 実装前に取得したものである。**関節可動域とギア比の初期既定値、エンドエフェクタ向きの補正指定も人手の設定が残る。

**(C) 物理モデルの不完全性。** リンクはカプセル（円柱＋半球）で近似され、学習系が設計変数として扱える形はカプセルと球に限られる。腕のリンクどうしの接触は隣り合わない組についてのみ判定しており、**隣り合う組は判定しない**（関節で必ず重なるため）。そのため肘を大きく折り返す姿勢では、隣り合う 2 本のリンクが体積として重なりうる。実機では段違いに取り付けるなどの対処を要する。同じ理由で、平面アームの台座はリンクと同じ高さの球（半径 0.1 m、形状生成の既定値）として置いており、1 本目のリンクが短い形では 2 本目のリンクが台座に当たって姿勢が制限される（実機の平面アームはリンクを台座の上に積むので当たらない）。縦型アーム（4.3.2 節・4.6 節）では柱がリンクを台座より高く持ち上げるため、この制約は生じない（学習後の動作で台座の球とリンクは一度も接しなかった）。傾いた腕を水平な面で分割するため半径は小さめに見積もられうる（B1 の手先で頂点の 70.9 % が外に出るが、はみ出し量の中央値は 5〜10 mm。3.9 節）。関節空間の慣性行列に占めるリンク形状の寄与は、実在の密度と回転子の慣性（第4章 表 4.2）のもとで平面アームの根元の関節が 1.8〜40 %（腕を伸ばした姿勢、形態による）であり、形態の動力学的な性質も成績に効きうる。⚠️ **ただし、形態の差がどの動力学的な機序で成績に現れたかは個々に確かめておらず、機序は主張しない。**リンクの密度は、初期形状の半径から求めたアルミニウム薄肉パイプの実効密度を全リンクで平均した一つの値であり、質量は中実のカプセルとして計算する。半径は設計変数であるため、太さを変えると質量は半径の 2 乗に比例して変わり、探索範囲の端では同じ太さの実在のパイプの 0.55〜2.75 倍となる。⚠️ **したがって収束形態の太さの違いには「太いほど実在より重い」効果が含まれうるため、太さは形の特徴として報告し、その機序は主張しない。**本研究の主張する順位とギア比の傾向は太さに依存しない。また MuJoCo 互換 XML から Choreonoid への変換器は**接触に関する記述を一つも読み取らず**、学習側の実効的な反発係数は約 0.055 で、実在の金属・樹脂間で報告される 0.2〜0.5 を大きく下回る。さらに台座リンクの位置オフセットは運動学の連鎖に寄与しないため、**10 次元の設計空間のうち 2 次元には勾配が伝わらない。**⚠️ **設計空間の次元は是正が容易である**が、変更すると既存の全実験と探索範囲が異なり**比較可能性が失われる**ため是正していない。⛔⛔ **一方、接触条件は本研究が用いる物理エンジンでは設定する手段そのものが無い。**Choreonoid の AISTSimulator は材質ごとの反発係数を参照せず、ワールド全体の反発係数を設定する API も求解部から読まれない。⭐ **反発係数を設定するには物理エンジンを置き換える必要がある。**同梱の Bullet プラグインは反発係数を実装しており、置き換えは原理的には可能である。⛔ **しかし接触を扱うエンジンを替えると全条件の物理が変わり、既存の全実験との比較可能性が失われる。**⭐ **そこで本研究は、壁との接触を物理エンジンではなく速度反射としてモデル化した。**⚠️ **本研究の主張はタスク間・形態間の相対的な順序であり、全条件が同一の設定を共有するため順序の比較そのものは成立する。**物理の値のうち、関節の粘性減衰の係数（$b$ = 1）・関節の可動域・制御コストの係数・接触の摩擦は実在の値に基づかず、原論文またはシミュレータの既定の値を用いた（第4章 表 4.2）。アクチュエータはトルクと角速度を定格で飽和させる単純なモデルであり、回転が速いほど出せるトルクが下がる特性は含まない。可動域の端では角度を止めて角速度を零にする硬い止めとしており、原論文の物理エンジン（MuJoCo）の柔らかい拘束とは端での挙動が異なる。⛔ **初期の実験は、移植したシミュレータが制御入力を飽和させず、関節の減衰を腕の総質量で割り、対象にも回転子の慣性を与えていた状態で行っていた。**同じモデルと同じ入力を原論文の物理エンジンに与えて比べる試験でこれらを見つけ、第4章の結果はすべて是正後の物理（表 4.2）で取り直した。初期の結果は撤回し、用いない。

**(D) 判定の精度と費用。** 判定に要する学習量は、設計が明確に異なる候補で 30 エポック（約4時間）であり、**対話的な設計支援が要求する「即時」の水準には達していない。**実用的とみなす所要時間の基準は設けておらず、所要時間は工程ごとの実測を示すにとどめる（4.5.2 節）。⛔ 差が乱数程度の候補どうしは 200 エポックでも順位が定まらず、本手法は「区別できない」としか返せない（4.5.3 節）。第2層・第3層の判定閾値は較正されていない。関節使用率の閾値（可動域の 10 %）について較正を試みたが、**閾値近傍の関節を固定した成績はシード間で向きが反転した**（+24.1 % と −34.1 %）。⭐ **ただし閾値が決めるのは固定を試す候補であって採用の可否ではなく、採用は成績範囲の重なりで判断するため、閾値が不正確でも誤った助言は採用されない。**⚠️ **防げないのは見落としであり、閾値が候補に挙げなかった助言が成績を改善した実例がある。**実在部材に基づく条件では使用率の最小が 14 % で第3層が助言を出さず、実測で最小の関節を直接固定しても成績範囲は可動側と重なった。⭐ **採否の手続きは実在条件でも設計どおり働いているが、第3層の閉ループが閉じたわけではない。**⭐ **第1層の助言は到達可能半径と目標距離という幾何のみで決まるため、密度・アクチュエータ出力・リンク長の設定に原理的に依存しない。**

## 5.4 今後の課題

1. **設計空間を実在部材の組み合わせへ離散化する（最も優先度が高い）**: 本研究は設計空間の境界を実在部材とアクチュエータの諸元から導き直したが（4.1.1 節）、**空間そのものは連続のままである。したがって得られた形態が実在の部品で組み立てられる保証はない。**関節種別・部材強度・組立可能性を判定しない以上（5.3 節 (A)）、出力は「このタスクに向く形態の候補」に留まり、「製作してよい設計」には届かない。
   **この距離を埋める直接的な道筋は、設計空間を連続な数値範囲から実在部品の組み合わせへ置き換えることである。**部品ライブラリに基づく組立システム（RobotAssembler 等）は、各部品に質量・慣性・関節軸・可動域・トルク上限を属性として持ち、接続規則を満たす組み合わせのみを生成する。**この空間の上で探索すれば、得られた形態は定義上かならず製作可能である。**本研究が用いるシミュレータと同じモデル形式を出力する実装も存在するため、接続は現実的である。
   ⚠️ **ただし設計空間が連続から離散へ変わるため、本研究が用いた勾配に基づく形態最適化はそのままでは適用できず、組み合わせ最適化としての定式化を要する。**この点は基盤手法の枠組みを超えるため、本研究では扱わない。
2. **前段の再現性と入力の一般性**: 前段の 2 工程は API 経由の呼び出しを実装し、パラメータを固定できる状態にしたが、報告した実走 5 件はそれ以前に取得したものであり、実走数自体も少ない。API 経路での取り直しと生成サービスの版管理を進め、関節数や入力構図の異なる線画で、関節検出からモデル生成までの成立条件を評価する。
3. **形態・タスク・判定性能の一般性**: 非平面形態ではタスク別の分岐を確認したが、モデルはパイプライン出力ではなく、リンク長の探索範囲にも限界がある。関節配置の偏りなど未検証の形態軸、配分のタスク依存性、立体・移動型形態への拡張を調べる。あわせてシード数を増やし、順位反転と非平面形態の主張を強化する。候補間の差に応じた停止則も課題である。
4. **診断の拡張**: 現在の診断は固定閾値に依存し、第1層以外では判定を覆す最小変更を直接求められない。閾値の較正、関節軸・形態変数に対する反実仮想的な助言、およびLLMを含む診断方式の比較を行う。
5. **関節軸の推定**: 関節軸は関節ごとに指定できる（第3章 3.10 節）が、**軸そのものを入力形状から推定する処理は無く**、最終的な割り当ては利用者が候補から選ぶ。候補の列挙と第1層診断を組み合わせた枝刈りは、リンク長を固定した設定でのみ有効である。学習でリンク長を最適化する設定では、第1層が棄却した配置も目標に到達したため（2 シード）、学習前の棄却には使えない。線画やメッシュの形状特徴から軸を推定する手法が課題である。
