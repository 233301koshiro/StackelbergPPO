## 3.1 問題設定: 階層ゲームとしての co-design

Stackelberg PPO は、形態と制御の同時最適化を Stackelberg ゲーム — 先導者（Leader）が追従者（Follower）の最適応答を見越して意思決定する階層ゲーム — の変種として定式化する。Leader は形態を編集する方策 $\pi^L(\cdot \mid s^L_t; \theta^L)$、Follower は確定した形態のもとで制御を行う方策 $\pi^F(\cdot \mid s^F_t; s^L_T, \theta^F)$ である。

ここで $\pi(\cdot \mid \ldots)$ は、縦棒の右の条件のもとで各行動をとる確率を返す関数を表し、セミコロンの右はその方策を用いるあいだ固定される量である。各記号の意味を表 3.1 に示す。すなわち $\pi^F$ は、形態 $s^L_T$ と重み $\theta^F$ を固定したうえで、各時刻の状態 $s^F_t$ から制御行動の確率を返す。本研究の実装では、確定した形態の設計パラメータが Follower の観測にも含まれ、これによって Follower は形態に条件づけられる。

**表 3.1**: 方策の記号

| 記号 | 意味 |
|---|---|
| $\pi$ | 方策。状態を入力とし、各行動をとる確率を返す |
| 上付きの $L$・$F$ | Leader と Follower のどちらの量かを示す添字（べき乗ではない） |
| $(\cdot \mid \ldots)$ | 条件付き確率の表記。縦棒の右が条件、左の $\cdot$ が確率を割り当てる行動 |
| $s^L_t$ | 時刻 $t$ における形態（各リンクの設計パラメータ） |
| $s^L_T$ | Leader が時刻 $T$ に確定させた形態 |
| $s^F_t$ | 時刻 $t$ における制御側の状態（各関節の角度と角速度、手先から見た対象物の相対位置） |
| $\theta^L$・$\theta^F$ | それぞれの方策ネットワークの重み。学習で更新される |
| セミコロン（;） | 右側は確率変数ではなく、方策を用いるあいだ固定される量 |

1エピソードは2つのフェーズに分かれる。前半（$t = 0, \dots, T-1$）では Leader が形態編集行動 $a^L_t$ を実行し、終端形態 $s^L_T$ を確定させる。後半（$t \ge T$）では Follower が形態 $s^L_T$ に条件づけられた制御行動 $a^F_t$ を実行し、タスク報酬 $R^F$ を得る。

両者の目的関数は次で与えられる。

$$J^F(\theta^L, \theta^F) = \mathbb{E}\left[\sum_{t=T}^{\infty} \gamma^{t-T} R^F(s^F_t, a^F_t; s^L_T)\right]$$

$$J^L(\theta^L, \theta^F) = \mathbb{E}\left[\sum_{t=0}^{T-1} \gamma^t R^L(s^L_t, a^L_t) + \sum_{t=T}^{\infty} \gamma^{t-T} R^F(s^F_t, a^F_t; s^L_T)\right]$$

本研究にとって本質的なのは $J^L$ の第2項である。**Leader の評価には、自身が編集を行わない実行フェーズの Follower のリターンがそのまま継承される**。すなわち形態は運動学的な理論的妥当性によってではなく、**その形態を制御方策が実際にどれだけ活用し得たか**によって評価される。この性質が、co-design を形態の設計判定器として用いる本研究の根拠である。

Leader の更新は、Follower の最適応答の感度を織り込んだ Stackelberg 勾配により行われる。同勾配は Follower 側の損失の Hessian を含み、共役勾配法による陰関数微分で近似される（正則化係数 $\lambda$ が Stackelberg 勾配（$\lambda \to 0$）と通常の方策勾配（$\lambda \to \infty$）を内挿する）。制御・形態の双方の方策更新には PPO を用いる。詳細は原論文に譲る。

## 3.2 役割別の報酬設計に関する原論文の規定

原論文の付録は、報酬項を Leader と Follower に選択的に割り当てる「役割別の報酬設計」を明示的に許容している — 例えば材料コストや複雑さのペナルティを Leader の更新のみに適用し、制御学習には干渉させない、という使い方である。重要なのはその境界であり、**Leader 専用の報酬項を $J^L$ に加算することは枠組みの想定内**だが、$J^L$ の第2項（Follower リターンの継承）を別の量に**置き換える**ことは、Leader が Follower の実応答を見なくなるため Stackelberg 構造の前提を壊す。本研究の報酬設計（4.1.2 項）はこの規定に従う。

## 3.3 方策のアーキテクチャ

方策ネットワークは、形態を木構造（ボディグラフ）として扱う Transformer ベースの構成であり、グラフ構造を意識した位置符号化を用いる。各ボディがノードとして観測（深さ・設計パラメータ・シミュレーション状態）を持ち、行動（形態編集・制御）もノード単位で出力される。この構成の実用上の帰結として、**リンク数の異なる形態を同一のネットワークが透過的に扱える** — 本研究で生成メッシュ由来の3関節アームがコード変更なしに受理されたのはこの性質による（4.3.1 項）。

## 3.4 本研究で用いる実装上の構成

本研究の実験は、上記の枠組みに次の構成を加えて実施する（いずれも原論文の枠組みの範囲内の設定である）。

- **形態フェーズの分割**: 実装では Leader フェーズがさらに骨格変換（リンクの追加・削除）と属性変換（リンク長・ギア比等の連続量編集）に分かれる。本研究ではトポロジーをスケッチ由来の構造に固定するため骨格変換を無効化する。骨格変換の段は 1 ステップで素通りし、属性変換を 5 回行う
- **設計パラメータの写像**: 属性変換の行動は正規化空間 $[-1, 1]$ 上で行われ、正弦写像により実パラメータの探索範囲へ変換される。探索範囲は表 4.1・表 4.2 の通りである。1回の編集の歩幅は係数で制御され、これは探索範囲の制限ではなく更新の刻み幅である
- ⭐ **設計フェーズの報酬**: 骨格変換・属性変換のいずれにも**即時報酬を与えない**（$r = 0$）。設計行動の良否は、**同一エピソードの実行フェーズで得られたリターンが割引を通して遡って帰属する**ことで評価される。⭐ **この構成の帰結として、形態の良否の見込みは価値関数の推定を通じてのみ得られ、学習の進行に依存する**
