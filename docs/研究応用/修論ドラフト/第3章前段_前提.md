## 3.1 問題設定: 階層ゲームとしての co-design

Stackelberg PPO は、形態と制御の同時最適化を Stackelberg ゲームの変種として定式化する。Stackelberg ゲームとは、先導者（Leader）が追従者（Follower）の最適応答を見越して意思決定を行う階層ゲームである。Leader は形態を編集する方策 $\pi^L(\cdot \mid s^L_t; \theta^L)$ であり、Follower は確定した形態のもとで制御を行う方策 $\pi^F(\cdot \mid s^F_t; s^L_T, \theta^F)$ である。

ここで $\pi(\cdot \mid \ldots)$ は、縦棒の右の条件のもとで各行動をとる確率を出力する関数を表し、セミコロンの右はその方策を用いる間は固定される量である。各記号の意味を表 3.1 に示す。すなわち $\pi^F$ は、形態 $s^L_T$ と重み $\theta^F$ を固定したうえで、各時刻の状態 $s^F_t$ から制御行動の確率を出力する。本研究の実装では、確定した形態の設計パラメータを Follower の観測にも含めており、これによって Follower は形態に条件づけられる。

**表 3.1**: 方策の記号

| 記号 | 意味 |
|---|---|
| $\pi$ | 方策。状態を入力とし、各行動をとる確率を返す |
| 上付きの $L$・$F$ | Leader と Follower のどちらの量かを示す添字（べき乗ではない） |
| $(\cdot \mid \ldots)$ | 条件付き確率の表記。縦棒の右が条件、左の $\cdot$ が確率を割り当てる行動 |
| $s^L_t$ | 時刻 $t$ における形態（各リンクの設計パラメータ） |
| $s^L_T$ | Leader が時刻 $T$ に確定させた形態 |
| $s^F_t$ | 時刻 $t$ における制御側の状態（各関節の角度と角速度、手先から見た対象物の相対位置） |
| $\theta^L$・$\theta^F$ | それぞれの方策ネットワークの重み。学習で更新される |
| セミコロン（;） | 右側は確率変数ではなく、方策を用いるあいだ固定される量 |

1 エピソードは二つのフェーズに分かれる。前半（$t = 0, \dots, T-1$）では Leader が形態編集行動 $a^L_t$ を実行し、終端形態 $s^L_T$ を確定させる。後半（$t \ge T$）では Follower が形態 $s^L_T$ に条件づけられた制御行動 $a^F_t$ を実行し、タスク報酬 $R^F$ を得る。

両者の目的関数は次で与えられる。

$$J^F(\theta^L, \theta^F) = \mathbb{E}\left[\sum_{t=T}^{\infty} \gamma^{t-T} R^F(s^F_t, a^F_t; s^L_T)\right]$$

$$J^L(\theta^L, \theta^F) = \mathbb{E}\left[\sum_{t=0}^{T-1} \gamma^t R^L(s^L_t, a^L_t) + \sum_{t=T}^{\infty} \gamma^{t-T} R^F(s^F_t, a^F_t; s^L_T)\right]$$

本研究にとって本質的なのは $J^L$ の第2項である。Leader の評価には、Leader 自身が編集を行わない実行フェーズにおける Follower のリターンがそのまま引き継がれる。すなわち、形態は運動学的な理論上の妥当性によってではなく、その形態を制御方策が実際にどの程度活用できたかによって評価される。この性質が、co-design を形態の検証エンジンとして用いる本研究の根拠である。

Leader の更新は、Follower の最適応答の感度を考慮した Stackelberg 勾配によって行われる。この勾配は Follower 側の損失の Hessian を含み、共役勾配法を用いた陰関数微分によって近似される。正則化係数 $\lambda$ は、Stackelberg 勾配（$\lambda \to 0$）と通常の方策勾配（$\lambda \to \infty$）の間を内挿する。制御と形態の双方の方策更新には PPO を用いる。詳細は原論文に譲る。

## 3.2 役割別の報酬設計に関する原論文の規定

原論文の付録は、報酬項を Leader と Follower に選択的に割り当てる役割別の報酬設計を明示的に許容している。例えば、材料コストや複雑さに対するペナルティを Leader の更新のみに適用し、制御の学習には干渉させないという使い方である。重要なのはその境界である。Leader 専用の報酬項を $J^L$ に加算することは、枠組みの想定内である。一方、$J^L$ の第2項（Follower のリターンの引き継ぎ）を別の量に置き換えると、Leader が Follower の実際の応答を参照しなくなるため、Stackelberg 構造の前提が崩れる。本研究の報酬設計（4.1.2 項）はこの規定に従う。

## 3.3 方策のアーキテクチャ

方策ネットワークは、形態を木構造（ボディグラフ）として扱う Transformer ベースの構成であり、グラフ構造を考慮した位置符号化を用いる。各ボディはノードとして観測（深さ、設計パラメータ、シミュレーション状態）を持ち、行動（形態編集と制御）もノード単位で出力される。この構成により、リンク数の異なる形態を同一のネットワークで扱うことができる。本研究において、生成メッシュに由来する 3 関節アームがコードの変更なしに受理されたのは、この性質による（4.3.1 項）。

## 3.4 本研究で用いる実装上の構成

本研究の実験は、上記の枠組みに次の構成を加えて実施する。いずれも原論文の枠組みの範囲内の設定である。

- **形態フェーズの分割**: 実装では、Leader のフェーズがさらに骨格変換（リンクの追加・削除）と属性変換（リンク長やギア比等の連続量の編集）に分かれる。本研究ではトポロジーをスケッチ由来の構造に固定するため、骨格変換を無効化する。骨格変換の段は 1 ステップで通過し、属性変換を 5 回行う
- **設計パラメータの写像**: 属性変換の行動は正規化空間 $[-1, 1]$ 上で出力され、正弦写像によって実パラメータの探索範囲へ変換される。探索範囲は表 4.1・表 4.2 のとおりである。1 回の編集の歩幅は係数によって制御される。これは探索範囲の制限ではなく、更新の刻み幅である
- **設計フェーズの報酬**: 骨格変換と属性変換のいずれにも即時報酬を与えない（$r = 0$）。したがって、設計行動は $J^L$ の第2項（3.1 節）のみによって評価される。形態の良否の見込みは価値関数の推定を通じてのみ得られ、学習の進行に依存する
