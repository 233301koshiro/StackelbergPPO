## 5.1 タスク識別の解釈: 形態の分化要因

### 5.1.1 識別は機能量の水準で現れる

タスク別の収束形態の分離（第4章 4.3.2 節）は、「co-design はタスクに適した形態を識別する」という問いに対し、識別の**現れ方**まで含めた答えを与える。Pusher と Reach の間で一貫して分離したのは個別の設計パラメータではなく、機能量 — ギア比のプロファイル（Reach: 肩下限 20 / Pusher: 肘上限 400）とリーチ帯（Reach: 0.9〜1.1 m / Pusher: 1.2〜1.7 m）— であった。Target-Pusher は形態上 Pusher に近い領域（高ギア・中リーチ）に収束し、その識別は形態ではなく行動類型（打撃的方策・押下・保持方策・サブミリ静止保持）において現れた。一方、タスク内の個別パラメータ（リンク長の配分、片側の関節のギア比）はシード間で大きく分散した。

事前に設定した予測（Reach は内部解、Pusher は高ギア・長腕）との照合では、Reach は2シードとも目標 0.8 m を超えつつ探索上限 1.44 m に接触しない内部解（0.905 / 1.103 m）に収束し、肩ギアも両シード下限 20 に収束した。Pusher は肘ギアが両シード上限 400 に収束し、リーチ帯は Reach と不重複の帯に分布した。予測との主な差分は Pusher のリンク長で、「最大長」という予測に対し実際にはシード依存（1.230 対 1.722 m）であり、長腕型・中庸型という複数の戦略実装が共存することが分かった。

この構造は「タスク → 単一の最適形態」ではなく「**タスク → 機能的性質を共有する戦略ファミリー**」と要約できる。同じ Reach でも上腕型と前腕型という異なる配分が同水準の性能を達成しており、設計空間には機能的に等価な解が多数存在する。したがって、co-design を設計判定器として用いる際に読み取るべき出力は、収束した形態の個別パラメータではなく機能量である。この知見は判定システムの出力設計（第3章 M6）に直接反映される。

### 5.1.2 各タスクの形態選好の力学

- **Pusher が肘ギア上限を選ぶ理由**: 速度報酬の総和はテレスコーピング（望遠鏡和）により最終移動距離に比例するため、最適戦略は一撃で最大の運動量を与えること（打撃的方策）に帰着する。先端速度はリンク長と角速度の積で決まり、トルク上限がそのまま打撃力を規定する
- **Reach が肩ギア下限を選ぶ理由**: 決定論的な到達精度はギア比に依存しない（実測: 肘ギア 207 でもサブミリ着地）が、確率的な方策のもとでは高ギアが行動ノイズを増幅し、誤った位置への整定を引き起こす（n=10 で 5/10 が 23〜38 mm の誤着地）。すなわち低ギアの利得は精度ではなく**ノイズ下の頑健性**である。学習は確率的ロールアウトで進むため、Leader は頑健な低ギア形態を選好する
- **Target-Pusher が高ギアを保ったまま行動で分化する理由**: トルクコストは行動の2乗 $a^2$ に課されるため、高ギアは同じトルクをより小さい行動で出せる（= コスト上むしろ有利）。したがってギアを下げる圧力は生じず、オーバーシュートの抑制は形態ではなく**制御側**（小さい行動で緩やかに押し、目標で止める）が担う。形態の適応が飽和する領域では行動の適応が識別を担う、という補完関係を示す例である

### 5.1.3 評価方式による優劣の逆転

転用成分の分解実験（第4章4.3.4.1節）では、形態ネットワークを含む転用（形態のみ・全成分）が転用元の到達点を上回った一方、制御方策ネットワークのみの転用は下回った。制御方策のみを転用した条件でも、Leader は高ギア・長リーチという形態へ探索しており、形態探索が停止したわけではない。それでも性能が転用元を下回ったことから、転用された制御方策が転用元の形態に特化し、形態が変化した後の共適応が崩れたと解釈できる。

形態ネットワークを含む転用では、転用元の形態に近い領域から探索を始めるため、転用された制御方策との適合が保たれやすい。したがって、本実験系で設計候補を判定する場合は、形態ネットワークを含む転用が妥当であり、制御方策のみの転用は推奨しない。ただし、この結果は Pusher の各1試行に基づくため、他タスクでの再現性は未検証である。
形態が設計空間の境界（角）へ収束した場合、その形態は「タスクの選好」ではなく「探索範囲の大きさ」を測っているに過ぎない。第一世代の Reach は目標が到達可能範囲の外にあり、最適形態が必然的に境界に決まってしまうため、タスク比較として解釈不能であった（幾何学的床、実測 6.02 cm）。是正は目標を範囲の内側へ移すことであり、是正後の Reach は境界に接しない内部解へ収束した。**形態比較の実験は「各タスクの理論最適が設計空間の内部で分かれる」ことを事前に確認して設計しなければならない**。

なお、収束形態の解釈には報酬だけでなくペナルティ・探索範囲を含めた拘束の全体を考慮する必要がある（初期接触ペナルティの幾何学的境界は設計空間の一部を実質的に禁止領域にする）。

**境界値への収束は、どこまでがタスクの選好を反映し、どこからが探索予算の産物か**: 本研究の設定では、
骨格を固定したことで属性編集の回数が原論文の 1 回から 5 回へ増えている（骨格変換の予算をそのまま
属性変換が使うため）。Leader は 1 回あたり一定量しか設計変数を動かせないので、**編集回数そのものが
「探索範囲の端まで到達できるか」を決めうる**。これを確かめるため、編集回数のみを 5・2・1 と変えた
3 条件を同一エポックで比較した（第4章の主実験とは独立の補助実験）。

結果は二層に分かれた。**どの条件でもギア比は 3 関節中 1 つが上限付近（398〜400）へ収束する。**
編集を 1 回しか許さなくても Leader はその 1 関節を上限まで振り切るため、**上限への収束それ自体は
編集回数では説明できない** — 押しタスクにおいて少なくとも 1 関節の最大トルクは実際に最適に近いと
解釈される。一方で**多数の設計変数が同時に端へ寄る現象は編集回数に依存する**: リンク太さの
境界値への収束は 3 個中 2 個（5 回）から 0 個（2 回）・1 個（1 回）へ減り、正規化した設計変数全体でも
20 個中 9 個（5 回）から 3〜5 個（2・1 回）へ減った。

したがって収束形態を読む際は、**「特定の変数が端にある」ことと「多数の変数が同時に端にある」ことを
区別する必要がある**。前者はタスクの要求を反映しうるが、後者は探索予算が生んだ見かけの可能性がある。
なお 3 条件の最終性能は 1 回 138.92・5 回 131.00・2 回 116.96 と単調ではないが、各条件 1 シードであり、
本研究で観測されたシード間変動（0.6〜20 %）の範囲に入りうるため、性能の順序は主張しない。

### 5.2.4 ペナルティ設計の原則

不正な状態（初期接触）をエピソードごと棄却すると、Leader が設計空間から脱出する勾配を失う。したがって不正状態は棄却ではなくペナルティとして扱い、その大きさは正常なエピソードの報酬スケールから導出する。この設計により、不正状態からでも形態を修正する方向の勾配を保持できる。

### 5.2.5 長期学習の運用

プラトー到達後の継続学習による方策崩壊は発生条件が未特定である。したがって、学習終了時にはプラトー検知による打ち切りと最良チェックポイントの採用を行う。これは学習結果の評価を安定させるための運用上の保険である（第4章4.3.6節）。

## 5.3 転用の構造

第4章 4.3.4.1 節の結果は、**転用で効くのは形態側の重みである**ことを示した。本節はその機序を述べる。

**形態の直接比較**: 形態のみ転用（K2）・全成分転用（I1）・転用元（H1）の収束形態を比較すると、第1リンクは 3 条件で完全に一致し（長さ 0.539 m・ギア比 400）、第2リンクもほぼ一致する（0.652 / 0.686 / 0.702 m）。**K2・I1 は転用元と同じ形態に収束している。**形態ネットワークの転用は、探索の出発点を転用元の近傍に置くだけでなく、そこからほぼ動かさない。

**制御方策のみを転用した条件（K1）の形態推移**: 「形態探索が非効率だった」という説明を確かめるため、チェックポイントを 100 エポックおきに読み込んで追跡した。K1 の Leader は **第110エポックまでに探索上限のギア比へ到達し、以降も緩やかにリンク長を伸ばし続けている**。最終形態（総リーチ 1.675 m）は**転用元（1.241 m）よりも長く**、ギア比も遜色ない。にもかかわらず性能は転用元を下回る。**したがって形態探索が停滞したという説明は支持されない。**

**解釈**: 転用された制御方策は転用元の特定の形態に適応したものであり、**Leader がそこから離れた形態へ到達した時点で、その制御方策は新しい形態に対して最適とは限らない**（制御と形態の共適応）。K2・I1 は形態ネットワークも転用されるため探索が転用元の近傍に留まり、制御方策との適合が保たれる。一方 K1 は形態が独立に動くため適合が崩れる。すなわち**この設定で効いているのは「良い形態を早く見つけること」よりも「転用した制御方策と形態を一致させ続けること」であり、形態ネットワークの転用はその一致を自動的に保証する。**

⚠️ **当初の実験は無効であった。**読み込み対象エポックの指定が欠落しており、4 条件すべてが実質的にランダム初期化から開始されていた。当時観測された順位は、設定が完全に一致する試行間の実行揺らぎ（第199エポックで 97.8〜131.2 の範囲）に過ぎない。⭐ **その無効な結果は「制御の転用が有効」を示唆していたが、再実験の結論はその逆である。**

**実用上の帰結**: 設計候補の判定では、可能であれば形態ネットワーク（少なくとも全成分）を転用するのが妥当であり、制御方策のみの転用は推奨できない。⚠️ **ただし本実験は押しタスク単一・各条件 1 試行であり、他タスクでの再現性は未検証である**（6.4.2 節）。

## 5.4 形態パラメータの成分分解（M 系 ablation）

リンク長とギア比のどちらがタスク達成に本質的に寄与するかを分解するため、Pusher タスクで属性を個別に可変としたアブレーション実験を実施した（M1: リンク長可変・ギア比固定、M2b: ギア比可変・リンク長固定 + 非接触初期化、L2: 両方可変）。

なお、いずれの条件でもリンク太さ（カプセル半径）と `ext_start` は最適化対象に含まれている（凍結されるのはM1ではギア比、M2bではリンク長のみである）。両条件がこれらを共通して持つため、M1 と M2b の差分は依然としてリンク長とギア比の対比を分離しているが、形態凍結条件（C）を基準とした寄与率の算出には太さの寄与が混入する。この点も、後述の通り寄与率を百分率で提示しない理由の一つである。

各条件の seed=0 ベストを比較すると（表 5.4.1）、形態凍結条件（C: 16.8）に対し M1（長さのみ）は 55.9、M2b（ギア比のみ）は 33.2、L2（両方）は 102.2 であった。この値から寄与率を試算すると、C→L2（seed=0, ep999）の総伸び 85.4 を基準に長さのみ 46%・ギア比のみ 19%・残り 35% が相互作用項となるが、この試算には2点の留保がある。第一に、M1・M2b は 200 エポックで打ち止めであり、L2 の ep999 値を分母とすることは学習量の差を寄与率に混入させる。エポック数を揃えた参考計算（L2@200ep ≈ 75 を基準）では長さのみ約 67%・ギア比のみ約 28% となり、数値は大きく変動する。第二に、より根本的な問題として、**M2b（ギア比のみ）は 200 エポック打ち切り時点で学習曲線がなお明確な上昇を続けており（ep196〜199 で 24.4 → 33.2 と継続的に増加）、収束前に打ち切られている**。M1（長さのみ）は同時点で 53〜55 の範囲で安定しており対照的である。したがって、ギア比のみの寄与率（19%、参考値では 28%）はいずれも過小評価となっている可能性が高く、両者の具体的な比率は確定した値として扱わない。本節で確認できる事項は「長さの寄与がギア比の寄与を上回る」という順序関係のみであり、この順序はシード間で高い再現性を示す（M1・M2b とも 2 シードで値がほぼ一致、それぞれ ±0.2・±0.8）。**1000 エポックへ延長した再実験の結果（表 5.4.2）**: M1・M2b とも 2 シードで完走し、best exec_R_eps は M1 が 41.4（seed=0）・62.1（seed=1）、M2b が 39.7（seed=0）・37.9（seed=1）であった。

この再実験により、上記の懸念——ギア比の寄与が 200 エポック打ち切りによって過小評価されていた——は定量的に裏付けられた。判定に用いる代表値（第 0 〜 E エポックの最良値、4.1.4）で見ると、第 200 エポックから第 999 エポックにかけての伸びは M2b が +21 %（32.68 → 39.69、seed=0）・+20 %（31.69 → 37.91、seed=1）であるのに対し、M1 は +0 %（41.41 → 41.41）・+11 %（56.13 → 62.06）に留まる。すなわち両条件は収束の速さが異なり、**200 エポックという同一の打ち切り点は M2b にとってのみ不利に働いていた**。

その結果、両条件の差は縮まった。同一コード上で完走した値で比較すると、M1 の平均 51.7 に対し M2b の平均 38.8 であり、比は約 1.34 倍である。第 200 エポック時点で同じ代表値（最良値）を用いて比較すると約 1.52 倍であり、打ち切りによる差の誇張は 1.52 倍から 1.34 倍への縮小に相当する。なお各エポックの生値で比較すると第 200 エポック時点の比は約 1.97 倍となるが、生値は揺らぎが大きく代表値の定義とも整合しないため用いない。とりわけ seed=0 では M1 41.4 対 M2b 39.7 とほぼ拮抗しており、**「長さの寄与がギア比の寄与を上回る」という順序関係は平均では維持されるものの、シードによっては差がほぼ消える**。加えて M1 のシード間のばらつきが 41.4 対 62.1 と大きく（200 エポック世代では 55.9 対 55.6 とほぼ一致していた）、シード数 2 では平均の差を確定的なものとして扱えない。

寄与率を百分率として算出するには、基準となる形態凍結条件（C）と両方可変条件（L2）が同一のシミュレーション設定で得られている必要がある。しかし本研究における両者は、M1・M2b の再実験とは実験設定（環境実装の更新）が異なる時期に取得されたものであり、同一シード・同一設定でありながら第 0 エポックの値が一致しない。**したがって異なる設定間での直接的な定量比較は控え、寄与率の百分率は提示しない。** 本節が結論とするのは、同一設定で比較可能な M1 対 M2b の順序と比のみである。表 5.4.1 と表 5.4.2 を分けて示すのも同じ理由による。

この相互作用項は、リンクが長くなることでギア比の上限が先端速度（= 角速度 × 総リンク長）としてより効果的に発現するという正の相乗効果として解釈できる。すなわち「両方可変」の本質的な価値は個別成分の足し合わせではなく、この相乗効果にある。

また、ギア比のみを可変とした初期条件（arm_safe_init=false）では全エピソードが初期接触ペナルティ（-50）に固定され学習が成立しなかった。これは初期形態が操作対象に貫通しており、そこから脱出できる手段がリンク長の変更のみであることを示す。すなわち、**リンク長の可変性は「より良い形を探す」以前に、この環境でタスクを成立させるための必要条件**である。

## 5.5 判定から診断へ: なぜ三層に分ける必要があったか

### 5.5.1 層の分け方はコストではなく確定性で決まる

診断機能（第3章 3.12 節）を幾何・収束設計・行動の三層に分けた理由は、計算コストの違いだけではない。より本質的なのは、**各層が下せる判断の確定性が異なる**ことである。

第1層が用いるのはリンク長と目標位置という運動学的な量のみであり、判断は決定論的である。「最大リーチ 0.403 m の腕は 0.800 m 先の目標に届かない」は、学習の結果によらず、乱数シードによらず成立する。したがってこの層の否定的判定は反証されない。一方で第2層・第3層が用いるのは学習の帰結であり、シードや打ち切りエポックに依存する。同じ形態でも学習が異なれば異なる設計・異なる行動に収束しうる。

この非対称性から、診断の設計原則が導かれる。**確定的な層は断定してよく、確率的な層は断定してはならない。** 実装では、第1層のみ「この形ではタスクを達成できません」という総合判定を出す権限を持ち、第2層・第3層は観察の報告と警告に留めている。

同じ理由から、第1層は「届かない」という否定的判定のみを行い、「届く」という肯定的判定は下さない設定にしている。リンク長が最適化対象に含まれる場合（設計モード）、最大リーチは学習中に伸びうるため、幾何だけで到達可能性を保証できないからである。リンク長を凍結する判定モードでのみ双方向の判定を許す。この**判定モードと設計モードの区別**は、本システムの用途を規定する重要な前提である（6.4.2 節の限界5・6）。

### 5.5.2 収束形態は「達成」と「断念」を区別しない

第2層のルールは、実装の過程で一度誤った形で定式化し、実験によって訂正した。この経緯自体が co-design を判定に用いる際の一般的な注意点を含むため、以下に記す。

当初の観察は次の通りであった。目標に到達できない短腕条件では、3関節すべてのギア比が探索下限（20）へ収束し、リンク太さも下限付近（0.039 / 0.030 / 0.030 m）へ収束した。対して到達可能な長腕条件では、ギア比が 102.3 / 35.5 / 30.6 と関節ごとに分化し、太さも根元太・先細りの構造を取った。この対比から「**ギア比と太さがともに下限へ収束することは不適合の兆候である**」というルールを立てた。解釈も自然に見えた——どの設計を選んでも報酬が改善しない状況では、Leader に残された唯一の改善方向は制御コストの最小化であり、結果として最も弱く細い設計が選ばれる、というものである。

しかしこのルールを実装して中間スケール条件に適用したところ、**同じ署名が出た**。ギア比 20/20/20、太さ 0.032 / 0.030 / 0.030 m である。この条件は目標にサブミリ精度で到達しており、3形態中で最良のスコア（−3.42）を得ている。すなわち**成功した形態と失敗した形態が、収束形態の水準では区別できなかった**。

原因は、Reach タスクにおいて「弱く細い」設計が正常な最適解でもあることにある（5.1.2 節）。確率的な方策のもとでは、強いアクチュエータは目標付近での振れを増幅して静止精度を損なうため、目標に到達できる形態は到達後の保持のために弱い設計を選ぶ。つまり同じ「下限への収束」が、**タスクを断念した結果**としても、**タスクを達成したうえで最小の駆動力を選んだ結果**としても生じる。

一般化すれば、**co-design が返す収束形態は「報酬を最大化した結果」でしかなく、その報酬が高いか低いかの情報を含まない**。形態パラメータだけを見て成否を判断することは原理的にできず、報酬の水準（スコア）か、幾何的な可否か、実際の行動のいずれかと組み合わせる必要がある。これが三層構成を採る直接の理由である。訂正後の実装では、この署名を Reach では警告に留め、強い出力が有利なはずの Pusher においてのみ不適合の兆候として報告するタスク条件付きのルールとした。

### 5.5.3 幾何が学習を代替できる範囲

第1層は 4.3.3.3 節のマトリクスにおける Reach の順位（中間 > 長腕 > 短腕）を、学習を実行することなく正しく予測した。短腕を到達不能として除外し、長腕には「到達可能だが目標に対して長すぎる」という警告を出し、中間スケールのみを無条件に適合と判定したためである。200 エポックの学習に要した時間は条件あたり約 20 時間であり、第1層は探索設定に依存するが数秒以内に完了する。

ただしこれを「幾何診断が学習を代替できる」と一般化することはできない。**同じ第1層を Pusher に適用した場合、中間スケールと長腕の優劣は予測できない。** 第1層が長腕について出力するのは「静止姿勢で対象に貫入する可能性がある」という起動時の注意のみであり、順位に関する情報を含まない。実際の Pusher の順位は長腕 > 中間であり、Reach とは逆である。

この差は、タスクが形態に課す要求の性質に由来する。Reach の要求は「目標距離への適合」であり、これは幾何量そのものである。したがって幾何だけで大部分が決まる。一方 Pusher の要求は「先端速度の最大化」であり、これは幾何量（リーチ）だけでなく、アクチュエータ出力・慣性・制御の習熟が絡む動力学量である。幾何は必要条件（対象に届くこと）を与えるにすぎず、優劣は学習を回さなければ分からない。

すなわち**幾何診断が学習を代替できるのは、タスクの要求が運動学的な量に還元できる場合に限られる**。この境界を明示せずに第1層の予測精度を一般化すると、動力学が支配的なタスクで誤った早期棄却を招く。診断の実装では、第1層は不適合の検出と警告に留め、適合と判定した形態については「学習を実行して性能を確かめてください」と明示的に促す設計としている。

## 5.6 フェーズ0 設計支援システムとしての実用性

前節までは検証エンジンと診断機能を個別に論じた。本節は、それらを結合したシステムが概念設計段階（フェーズ0）の支援としてどこまで実用に耐えるかを論じる。この段階で設計者が行うのは、寸法の精緻化ではなく「この案でタスクを達成しうるか」の見極めと、達成しえない場合の作り直しである。したがってシステムの価値は、判定の精度そのものよりも**やり直しのサイクルを何回、どれだけの費用で回せるか**によって決まる。

### 5.6.1 やり直しサイクルにおける診断機能の位置

本システムが想定するサイクルは、スケッチの作成、モデル生成、判定、そして不適合であった場合の修正から成る。このうち判定までは検証エンジンが担うが、**サイクルはそれだけでは閉じない**。エンジンが返すのはスコアという単一の実数であり、「この形態は良くない」ことは伝えても「何をどう変えればよいか」は伝えないためである。スコアが低い理由が腕の短さにあるのか、駆動力の不足にあるのか、あるいは制御の学習が足りていないだけなのかは、スコアからは区別できない。

専門知識を持つ設計者であれば、収束した設計パラメータや行動の軌跡を自ら読んでこの区別を行える。しかし本システムが想定する利用者はハードウェアの非専門家であり、その読解を要求することは前提と矛盾する。診断機能が埋めるのはこの位置である。**診断はエンジンの出力を、設計者が次に取るべき操作へ翻訳することでサイクルを閉じる。**

この翻訳が成立する条件は、提示される操作が設計者の操作可能な変数の上で表現されていること（第2章 2.4 節）に加えて、**その操作を実行すれば実際に判定が覆ること**である。後者は前者から自動的には従わない。次項で述べるように、本研究はこの点で実際に欠陥を抱えていた。

### 5.6.2 助言の実行可能性は、判定の正しさとは独立に壊れる

軸3の検証（4.4 節）が明らかにしたのは、**判定器としての正しさと、助言の実行可能性とが独立した失敗モードを持つ**という事実である。

診断は最短の形態を不適合と正しく判定していた。この判定の妥当性は、マトリクス6条件に対する事後検証（第3章 3.12.4 節）で総合判定が実測順位と全条件で一致することによって確認されている。にもかかわらず、その判定に付随して返される助言に従って形態を修正すると、**同じ診断が再びその形態を却下した**。必要な拡大倍率を小数第2位へ四捨五入した結果、提示された値が必要量をわずかに下回っていたためである。

原因そのものは丸め方向の誤りにすぎない。しかし注目すべきはその**発見されにくさ**である。判定の正しさを検証する枠組み — 既存の形態に診断をかけ、出力と実測順位を突き合わせる — では、この欠陥は原理的に検出できない。検出結果は正しく、誤っていたのは検出に付随する助言の側だからである。欠陥は、助言を適用した形態を生成して再入力する**閉ループを構成して初めて現れた**。

ここから二つの含意が導かれる。第一に、反実仮想説明や実行可能な救済（第2章 2.4 節）を返すと主張するシステムは、**出力の正しさとは別に、出力の実行可能性を検証する手順を持たなければならない**。説明可能 AI の評価は判定の忠実性や説明の妥当性に重心を置くことが多いが、救済を名乗る以上、救済を実行した結果まで確かめる必要がある。第二に、助言が返す数値は**必要量を下回らない側へ丸めなければならない**。助言が返すのは常に何らかの計算の結果であり、丸め・近似・モデル化の誤差はいずれも「わずかに足りない」方向へ働きうる。本研究では四捨五入によって提示値が必要量を 2 mm 下回り、助言どおりに直しても不適合が解消しない事例が実際に生じたため、切り上げを導入した。

ただし**「どれだけ余裕を持たせるか」は丸め方向とは別の問題であり、本研究の当初の判断は支持されなかった**。是正時には、下限では腕を伸ばしきった特異姿勢でしか目標に触れられないという理由から余裕を含めた推奨値を主として示す形に改めたが、後述のとおりこの理由づけは実験によって否定されている。丸め方向の是正（必要量を下回らせない）は残り、余裕幅の一律設定は根拠を失った。

なお、是正後の推奨倍率（2.19 倍）は、独立に用意していた適合形態の倍率（2.20 倍、best −3.42）とほぼ一致する。これは助言の較正が妥当であることを示唆するが、事後的な一致であって検証ではない。

助言に従った形態が実際にタスクを達成するかは 4.4.3 節で検証した。不適合と判定された形態に診断の指針を適用しただけで、到達タスクの平均残存距離は 397 mm から 0.33 mm へ三桁改善した（2 シード）。**閉ループは成立している**。ただしその過程で、本節の主題をもう一段深める事例が二つ得られた。

第一に、閉ループを構成する試みは**助言とは別の場所で壊れていた**。指針の値は 4.4.2 節で正しくなったが、その値を形態へ反映する生成器がリンクの描画長のみを拡大し、関節の取り付け位置を据え置いていた。結果として生成された形態はリンクが重なり、実効的な到達距離は公称値の 63% に留まった。すなわち「助言に従って作った形態」は、実際には助言に従っていなかった。ここから、**閉ループの検証は、助言・形態生成・再入力のそれぞれを独立に検算しなければ成立しない**という教訓が得られる。本研究は指針の数値は疑ったが、その数値を形態へ変換する工程の出力を一度も独立に測っておらず、生成器が自ら申告する公称値を信頼していた。反実仮想的な救済を返すシステムにおいては、救済の**記述**が正しいことと、記述どおりの状態を**構成できる**こととは別の主張であり、後者は前者から導かれない。

第二に、そして本研究が最も高い代償を払って学んだ点として、**再現性の高さは正しさの証拠にも、共通の欠陥の証拠にもなりうる**。当初、二つの seed が小数第2位まで一致した事実を、結論が学習の揺らぎに依存しないことの強い証拠と解釈した。しかし同一の欠陥を共有する条件どうしは、seed によらず同じ壁に到達する。実験計画において seed 間の一致は独立な確認として扱われるが、それが独立性を保証するのは**条件の構成そのものが正しい場合に限られる**。異常なほど精確な一致は、確証ではなく点検の合図として扱うべきであった。実際、取り直した結果は当初の結論と正反対であり、「下限では達成できない」ではなく「下限で十分であり、むしろ最良である」が事実であった。

この訂正は、是正時の設計判断そのものにも及ぶ。4.4.2 節では、必要量ちょうどでは特異姿勢でしか目標に触れられないという理由から、余裕を含めた値を推奨値として示すことにした。しかし到達タスクでは**下限が最良**であり、しかも余裕 0 %・5.3 %・10 % の三点で**単調に悪化する**（各 2 シード、隣接条件の範囲も重ならない）。余裕を加えるという判断は、押しタスク（腕が長いほど単調に有利）では無害だが、到達タスクでは精度を損なう方向に働いた。**必要な余裕はタスクに依存し、一律の推奨値には根拠がない**。

この単調性は、是正時に述べた理由づけそのものを否定する点で重要である。「必要量ちょうどでは特異姿勢でしか触れられない」という理由が正しければ、不利益は下限においてのみ現れ、余裕を少しでも取れば解消するはずであった。実際には余裕を取るほど悪化しており、**是正の根拠として挙げた機序は成立していない**。観測される単調性は腕の長さに連続的に依存する要因（慣性、制御コスト）と整合するが、この二つは互いに分離していない。

これらを総合すると、診断が返す反実仮想的な救済について本研究が示せたのは、**救済の方向が正しく、それに従えば不適合は解消される**ことまでである。救済の量（どれだけ余裕を持たせるか）をタスク非依存に定めることは、本研究の証拠では正当化されない。

### 5.6.3 コスト構造がサイクルの実用性を決める

サイクルを何回回せるかは、1周あたりの費用に支配される。本システムの費用は**二極化している**（4.5.2 節）。モデル生成・幾何診断・三層診断はいずれも秒単位で完了する一方、判定のための学習は候補間の隔たりに応じて4時間から16時間を要する。

この二極化は、システムの使い方を規定する。**幾何的に破綻した案は学習を待たずに棄却でき、修正指針まで数秒で返る。** マトリクス判定の6条件のうち2条件は第1層が不適合と断定しており、これらについて学習は不要であった。すなわち候補の3分の1は秒単位で処理されている。設計者にとってこれは、明らかに届かない案を何度描き直しても費用がほとんど増えないことを意味する。

一方、第1層を通過した案の優劣を知るには学習が要る。ここが対話的な設計支援としての限界である。ただし本システムが対象とするのは概念設計段階であり、実機を試作して確かめる経路と比較するならば、材料調達と組立の時間を要しない分だけ本質的に短い。この比較は本研究では定量化していない。

もう一点、コスト面で実用上の意味を持つのは、**第1層が形状の再生成を要求しない**ことである。第1層が用いるのはリンク長と目標距離のみであり、返す助言も「腕全体を N 倍に伸ばす」という単一のスカラー操作である。したがって設計者はスケッチを描き直すことなく、生成済みのモデルに倍率を掛けるだけで次の判定へ進める。三次元形状生成が外部サービスへの依存を含み、かつ出力が確率的である（4.2.2 節）ことを踏まえると、**再生成を挟まずにサイクルを回せる**という性質は費用と再現性の双方で利点となる。

### 5.6.4 実在の設計空間で判定器は成立するか

フェーズ0 の支援という位置づけが成り立つためには、**判定が実在しうる設計空間の上で行われている必要がある。**本研究の設計空間は当初、リンク密度もアクチュエータの出力範囲も原論文の移動ロボットから引き継いだ値であり、**45 g の腕を 400 N·m の駆動系が動かすという、機構として成立しない解を含んでいた**（4.6.1 節）。

実在部材と実在アクチュエータから設計空間の境界を導き直すと、**性能は 36 % 低下する**（4.6.3 節）。**この低下は手法の欠陥ではなく、従来値が実在しない設計を許容していたことの帰結である。**従来の上限は出所を持たず、しかも最適化は常にその上限へ収束していた。すなわち**従来の成績は、実在しないアクチュエータを前提として得られた値である。**

**重要なのは、この現実化によって判定器の中核が損なわれないことである。**検証エンジンに課した要求のうち、タスクの要求が形態に反映されること（R2）と、与えられた形態集合を正しく順序づけること（R3）は、いずれも実在条件で成立する（4.6.4・4.6.5 節）。

**さらに R2 については、識別の質が向上している。**従来条件では到達タスクのギア比が全関節で探索範囲の下限に収束しており、識別は「一方のタスクが範囲の端に落ちる」という形で成立していた。**範囲の端は人が置いた値であるから、この形の識別は設計空間の設定に依存する。**実在条件では到達タスクの全関節が範囲の内点に収束し、**識別は範囲の端ではなく値の違いによって成立する。**すなわち**設計空間を現実化したことで、識別の根拠が人為的な境界から離れた。**

⚠️ **ただし現実化は完全ではない。**接触係数は記述しても学習側へ届かず（4.6.8 節）、台座リンクの探索変数は運動学に寄与しないまま最適化の対象であり続けている（4.6.7 節）。**本研究が示したのは「設計空間の境界を実在機体から導く手続き」であって、設計空間が完全に現実的になったことではない。**

### 5.6.5 「専門知識を持たない利用者」に対する主張の範囲

本研究は専門知識を持たない設計者を想定利用者として掲げているが、**実際の利用者を対象とした評価は行っていない**。したがって「非専門家がこのシステムを使えた」という主張は本研究の範囲外である。本研究が示したのは、システムが返す出力が専門用語を用いず、設計者が直接操作できる変数の上で数値的な操作を指定する形式になっていること、およびその操作が判定を覆すよう設計されていることに留まる。実際の設計行動を改善するかは、利用者実験によって別途確かめられなければならない。

主張の範囲を限定すべき理由はもう一点ある。本研究が閉ループを構成した際、助言の適用はスクリプトによる機械的なスケーリングとして実装した（4.4.1 節）。しかし想定する利用経路において助言を受け取るのは人間であり、**手描きのスケッチを描き直して総リーチを指定倍率に正確に一致させることは容易でない**。すなわち本研究が検証したのは「助言が正しければ形態は改善する」という因果の後半部分であって、「人間が助言を正しく実行できる」という前半部分ではない。この接続を担保するには、助言に従った形態をシステムの側で生成して提示する機構、あるいは倍率をスケッチへ反映する支援が要る。いずれも今後の課題である。

最後に、診断が助言を返せる範囲そのものが限定的である点を再確認しておく。反実仮想的な助言を構成できているのは幾何が支配する第1層のみであり、第2層・第3層は現象の報告に留まる（第3章 3.12.6 節）。したがって「届かない」という失敗に対してはサイクルが閉じるが、「届くが遅い」「届くが対象を思った位置に止められない」といった失敗に対しては、システムは原因を報告するのみで修正の方向を示せない。フェーズ0 支援として最も価値があるのは前者の早期棄却であり、後者への対応は本研究の到達点の外側にある。

## 5.7 本研究の限界

### 5.7.1 研究スコープの宣言

本研究はシミュレーション環境における形態のタスク適性の初期判定・評価に特化する。本手法が生成するシミュレーションモデルは、抽出したリンク長・関節位置等のパラメータに基づくカプセルおよび球体等の幾何学的プリミティブ（geometric primitives）により構成される。したがって、物理的なロボットハードウェアの構築、実世界における接触力学・アクチュエータ特性・センサノイズ等を含む複雑な現実的制約（sim-to-real gap）の解決は、いずれも本研究のスコープ外である。本研究が主張するのは「シミュレーション上で、co-design がタスクに応じて異なる形態・行動へ収束することを介した設計適性の相対比較」であり、実機での動作を保証するものではない。

本研究が用いる「妥当」の語は、想定利用者が同じ語で意味するものと必ずしも一致しない。この差は範囲の宣言に先立って明示しておく必要がある。

**本研究の「妥当」はタスクを達成できるかを指す。**すなわち、与えられた形態がそのタスクの要求（到達すべき距離、対象へ与えるべき運動量）を満たしうるかであり、判定は制御の習熟まで含めた学習結果によって下される。

**一方、利用者が求める「妥当」には機構として製作できるかが含まれる。**本研究が掲げる利用経路は、専門知識を持たない設計者が自ら検証を済ませ、妥当と判断した案を製作者へ引き渡すというものである（5.6.4 節）。この経路において「妥当」と判定された形態が実際には製作できない場合、判定そのものは正しくとも利用経路は成立しない。製作可能性は少なくとも三つの要素からなる。**関節の種別と可動域**（本手法が出力するのは一自由度の回転関節のみであり、球関節のように記述できても実装が困難な機構は扱っていない）、**駆動系の物理的整合**（第6章 6.5 節に述べるとおり、現在の設計空間はリンク質量とトルク上限が三桁の隔たりを持つ解を含む）、**部材の強度と組立可能性**（本手法はリンクを幾何学的プリミティブとして扱い、荷重に耐えるかを判定しない）である。

**本研究はこのうちいずれも判定しない。**⚠️ **したがって本手法の出力は「このタスクに向く形態の候補」であって「製作してよい設計」ではない。**両者の距離を埋める道筋は第6章 6.5 節に段階として述べる。

⚠️ **この区別は本研究の主張を弱めるものではない。**主張は共通の物理条件下で形態集合を順序づけることであり、製作可能性の判定を含まない。影響を受けるのは主張ではなく、判定を経た形態を製作へ引き渡せるという**利用経路の完結性**である。

### 5.7.2 個別の限界

1. **形態クラスの単一性**: 検証は平面2関節の固定根本アーム（+ 生成メッシュ由来の3関節）に限られる。タスク識別の結論が高自由度・立体・移動型の形態クラスへ一般化するかは未検証である
2. **統計的規模**: 各条件 1〜2 シードであり、**「頑健」という語は用いない。** 統計的検定は行っていない。タスク間分離はシードを跨いで一致したが、主張は「2 シードの間で一貫性が確認された」に留まる。シード間一致の解釈については 5.1.4 節の力学的合理性による補強を参照
3. **判定の所要時間**: 設計が明確に異なる候補どうしでも順位確定に 30 エポック（本環境で約 4 時間）を要し、「数分での即時検証」には達していない。候補が拮抗する場合は 120 エポック（十数時間）に延びる。ビジョンとの差は将来の高速化課題である
4. **シミュレーションと実機の乖離の技術的詳細**: 5.7.1 節で宣言したスコープに関連し、打撃的方策の高先端速度（11〜23 m/s）は現在の物理設定（関節ダンピング係数・摩擦係数）に依存している可能性があり、これらのパラメータを実機相当の値へ変更した場合に方策が変容するかは確認していない。ただし、本研究のコア主張（タスク間の相対的な行動分化）は物理設定が全タスクに対称に作用する限り成立する
5. **自動化の例外**: 関節可動域・ギア比の初期既定値、エンドエフェクタ向きの補正指定は、現状人手の設定を残している（検出目標色は自動キャリブレーションを実装済みで例外から除外、第3章 M3）。加えて、M1（Gemini）・M2（Tripo3D）は現行実装では Web インタフェース経由の対話的利用に留まる。本パイプラインのアーキテクチャ自体は API 呼び出しによる全自動化・決定論的パラメータ指定（temperature 等）を前提として設計されているが、現行のプロトタイプ実装では外部 API 利用の制約により、この2モジュールに限り Web インタフェース経由のバッチ処理で代替している。したがって「モジュール間の受け渡しに人手を要しない」という第3章の主張は、M3 以降の決定論的処理と M6 の学習プロセスに対しては厳密に成立するが、M1・M2 の生成物取得については実装上の妥協であり、理論上の自動化設計と実装上の制約を区別して理解されたい
6. **生成AIサービスの再現性**: Web インタフェース経由の利用であるため、ベンダー側のモデル更新やサイレントな仕様変更により生成結果が将来的に変化しうる。API 経由での決定論的パラメータ固定による再現性担保は今後の課題とする
7. **設計空間の境界収束（ギア比）**: 主実験において Reach の肩ギア比は両シードとも探索下限（20）に、Pusher の肘ギア比は両シードとも探索上限（400）に収束した。リンク長については是正版（4.3.2.2）で「内部解」への収束を確認したが、ギア比については真の最適値が探索範囲の外にある可能性が排除できておらず、「タスクによる選好」と「探索範囲の上下限」の区別が残る（5.2.3 参照）。**この点は属性編集の回数のみを変えた補助実験（5.2.3）で部分的に切り分けた**: 編集回数を 1 回まで減らしてもギア比は 3 関節中 1 つが上限付近（398）へ収束するため、**その 1 関節の上限への収束は探索予算の産物ではない**と言える。一方、多数の設計変数が同時に端へ寄る現象は編集回数とともに減衰する（リンク太さの境界値への収束は 2/3 → 0/3、正規化設計変数では 9/20 → 3/20）ため、**そちらは予算の影響を含む**。ただし補助実験は各条件 1 シードであり、真の最適値が探索範囲の外にある可能性そのものは依然として排除できていない
8. **再現性情報**: PPO の主要ハイパーパラメータ（学習率・γ・λ・ロールアウト長等）は学習時の設定ファイルに保存されている。計算環境の詳細は第3章 3.13 節に記載した
9. **マトリクス判定の規模**: タスク間の順位反転（4.3.3.3）は 3 形態 × 2 タスクの観察である。反転の要となる中間スケール対長腕は両タスクとも 2 シードでスコア域が重ならないことを確認したが、両タスクの短腕は seed = 0 の 1 シードである。形態側の変化軸については、スケールに加えて**リンク長の配分**を別途検証しており（4.3.3.4）、総リーチが同一で配分だけが異なる形態対でも2 シードで順位が確定した。**未検証なのは関節配置の偏りの軸**である。また配分の検証は Reach の 1 タスクのみで、押しタスクで優劣が逆転するかは確かめていない。
10. **利用者を対象とした評価の不在**: 想定利用者は専門知識を持たない設計者であるが、実際の利用者による評価は行っていない。示したのは出力の形式が専門用語を用いず操作可能な変数の上で指定されていることに留まり、非専門家が実際に使えるかは検証していない（5.6.4 節）
11. **助言の実行経路の未検証**: 閉ループの検証において助言の適用はスクリプトによる機械的なスケーリングとして実装した。手描きスケッチを描き直して総リーチを指定倍率へ正確に一致させる経路は検証していない（5.6.4 節）
12. **助言を返せる層の限定**: 反実仮想的な助言を構成できるのは幾何が支配する第1層のみであり、「届くが遅い」「届くが目標位置に止められない」といった失敗に対しては原因の報告に留まる（第3章 3.12.6 節、5.6.4 節）
13. （空欄: 手描きスケッチからの E2E 実走の結果を受けた限界の追記）
