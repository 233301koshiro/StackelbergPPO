## Q1: 「Pusher に長い腕が良いのは自明では？ 原論文の貢献の主要部は関節を増やせること（トポロジー探索）で、リンク長だけの最適化なら既存のもっと簡単な手法があるのでは？」

（出典: ユーザー自身の疑問、2026-07-15。トポロジー固定 = fix_skeleton=true を本線とする本研究の急所を突く質問）

### 認める部分（正直に認めるのが最善）

- **「Pusher に長い腕」は自明**。先端速度 = 角速度 × 総リンク長という力学から紙の上で導ける。L 系 Pusher のリーチが伸びたこと自体に発見の価値はない
- **属性（連続パラメータ）のみの形態最適化は既存領域**。Ha 2019（design パラメータの RL 同時最適化）、Schaff et al. 2019（設計分布と方策の同時学習）、進化計算で候補ごとに制御を学習する系譜など [要文献確認]。「パラメータ数個を最適化できる」ことを貢献に据えたら本研究は弱い
- 原論文の新規性にトポロジー探索が含まれるのも事実（本研究はそれを意図的に使わない）

### データによる反論 — 属性のみの世界でも非自明だった実測結果

1. **gear の分岐は事前予測を外した**。構造分析の当初予測は「トルクコストほぼ無料なら両タスクとも gear 上限」。Reach の下限 20 収束は**反証として発見**され、その機構（決定論の到達精度は gear に依存しない・確率的ロールアウトの誤着地を 10/10 vs 5/10 で抑制する頑健性）は n=10 の検証を要した。解析で自明に導ける範囲の外にある
2. **Reach の内部解**（総リーチ 0.9〜1.1、探索上限 1.44 に非接触、2 seed）は「長いほど良い」の否定形 = 「必要十分で止まる」ことの実証
3. **同じ Pusher 内でも自明でない構造**: 中庸型 102.2 vs 長腕型 145.4（1.4 倍、n=2、L2/L2_s2）— 同じタスク・同じ報酬でも局所解が割れる。さらに**転用成分の分解実験（K1_v2/K2_v2/I1_v2、1000ep、2026-07-29 確定）でも非自明な構造が出た**: 転用元 H1(140.47) に対し、**形態ネットワークを含む転用は上回る**（形態のみ K2_v2=193.69・全成分 I1_v2=210.58）のに、**制御方策のみの転用は下回る**（K1_v2=93.82）。「学習済みの制御を引き継げば有利」という直感の逆で、形態が探索で動く最中に転用済み制御が追従できない co-adaptation の崩れが主因と解釈される（実験系譜.md 4-4、第5章5.3）。属性のみの世界でも、何を転用するかで結果の符号が変わる（旧 K1/K2 による当初の記述は Bug 12 で無効化され撤回済み）
4. **Target-Pusher は形態がほぼ Pusher と同じ（高 gear・中リーチ）なのに行動で分化**（押して止める vs 吹き飛ばす）。つまり「形態が自明かどうか」と独立に、**制御の習熟込みの評価でなければタスク適性は判定できない** — 形態だけ見たら TP と Pusher は区別不能。これは Stackelberg の return 継承（Leader が Follower の実応答で評価される）を判定に使う本研究の設計の直接の根拠になる

### 貢献の位置づけ（防御線）

本研究は co-design を「より良い形を設計する道具」ではなく「**人間が描いた形の筋の良さを、制御の習熟込みで判定する検証器**」として使う（B 軸、論文骨子）。この用途では:

- **トポロジー固定は制約ではなく仕様** — スケッチが決めた構造を尊重して評価するのが目的で、「関節を増やせる」能力はむしろ使ってはいけない
- 問われる性質は「最適解を見つける力」ではなく「**判定の妥当性**（タスクの要求を正しく反映するか = C2、原論文はタスク間比較をしていない空白）と**判定の速度**（転用設計則・ep100 較正 = C3）」
- 「リンク長最適化ならもっと良い手法がある」は真でも、**判定器としての妥当性検証・スケッチ入力の E2E システム・タスク間比較は先行研究にない**

### 裏付け実験（計画済み）

**属性成分の分解 ablation**（M 系、07-15 起動済み）: fix_skeleton=true のまま (a) M1 = 長さのみ可変（gear 凍結）(b) M2b = gear のみ可変（長さ凍結 + 非接触スタート）(c) 両方 = L2 実績、の3条件 × Pusher 200ep。

**起動前に確定した部分回答**: gear のみ・素の条件（M2）は全エピソードが初期接触ペナルティに張り付き学習不能だった。デフォルト形態は対象に最初から貫通しており、そこから脱出できるのはリンク長の変更だけ — すなわち**リンク長の可変性は「より良い形を探す」以前に、この環境でタスクを成立させるための必要条件**である。「長い腕が良いのは自明」という批判に対し、「自明な方向に動けること自体が学習成立の前提であり、それを踏まえた上で gear・行動の非自明な分化が乗る」という2層の答えになる。**M1/M2b 完走結果（07-16）**: M1(長さのみ)=55.9 / M2b(gearのみ)=33.2 / L2(両方)=102.2 / C(凍結)=16.8。長さ寄与 46%・gear 寄与 19%・相互作用 35%。gear 単独（非接触スタートなし）は全エポード -50 で学習不能 = リンク長はタスク成立の必要条件

### 想定される再反論への備え

- 「gear も自明では（強いモーターが良いに決まっている）」→ Reach は**下限**を選んだ（2 seed + 旧世代2 run の計4本）。「強いほど良い」はタスク依存で、その依存の仕方（確率的頑健性経由）が非自明
- 「n=2 で言えるのか」→ **認める。ただし力学的合理性で補強する**。Pusher の高ギア・長リーチは「先端速度 = 角速度 × リンク長、一撃で最大運動量」という力学から必然的に導かれる収束先であり、Reach の低ギアは「確率的方策下のノイズを高ギアが増幅しオーバーシュートを招く、その防御」という制御的合理性による。シード間でこれら機能的性質が一致したことは、偶然の揺らぎではなくタスク要求への適応を強く示唆する。主張は「2 シードの間で一貫性が確認された」に統一する（修論の限界節）。**「頑健」「再現性」「有意」の語は口頭でも使わない**（本ファイル Q7 の「やってはいけない防御」を参照）。**なお4軸が物理的に相関（先端速度 = ギア × リンク長という一本の式で縛られている）しているため、確率計算（例: 4軸独立仮定の (1/2)^4 = 6.25%）は独立事象の前提が崩れており使用禁止。審査で致命的な欠陥として追及される。**
- 「判定器なら比較対象は他の判定手法（IK 解析・幾何チェック）では」→ 正しい比較軸。幾何チェック（リーチ判定等）は「届くか」しか答えられず、「押して止められるか」のような制御依存の適性は学習ベースでないと判定できない、が答え。TP の形態同一・行動分化がその実例

## Q2: 「タスク自体が似ているから、動画では形態最適化の違いが分かりにくい。同じタスクでもパラメータ次第で形態に多少差は出るのだから、観測された差はその範疇を出ていないのでは？」

（出典: 指導教員、2026-07-17。詳細な回答資料: [タスク間形態差の定量比較.md](タスク間形態差の定量比較.md)・図 [morphology_task_separation.png](../morphology_task_separation.png)）

### 認める部分

- **動画では違いが分かりにくいのは事実**。gear（トルク倍率）は見た目に出ないし、リンク長の比の差は一目では伝わらない。見せ方の失敗であって主張の失敗ではない
- **同タスク内のシード差も実在する**。Pusher のリーチは 1.23 vs 1.72、肩 gear は 98 vs 400 とシードで大きく振れる。「同条件でも形態は揺れる」という指摘自体は正しい

### データによる反論

- **設計上、この批判は検証可能**: 6 run はハイパラ完全同一・変えたのは報酬とシードのみ。シード対がそのまま「同条件の揺らぎ幅」の実測になっている
- **「シードで動く軸」と「タスクでしか動かない軸」が分離している**: Reach の肩 gear は 2 seed とも下限 20 ぴったり（揺らぎ幅 0）、Pusher の肘 gear は 2 seed とも上限 400 ぴったり。この署名軸がタスクを跨ぐと正反対の端に飛ぶ（20 ⇄ 400）。シードで揺れるのは署名以外の自由軸だけ
- **境界張り付きの向きは質的な差**: 連続的な揺らぎは「下限に張り付くか上限に張り付くか」を反転させない。2/2 シードで再現
- **形態差は成績に因果的に効く**: gear(20,20) は n=10 着地 10/10、肘 gear 207 は 5/10（3.6 倍悪化）。M ablation で長さ 46%・gear 19%・相互作用 35%
- **方向が力学と一致**: 低肩 gear = ジッタ抑制（到達精度）、高肘 gear + 長リーチ = 先端速度（打撃）。偶然の散らばりに系統的な向きは出ない

### 貢献の位置づけ

「タスクが似ているのに署名軸が正反対に分かれる」ことこそ、判定器としての感度の証拠。全く違うタスク（歩行 vs 操作）で形態が分かれても自明だが、同じアーム・同じ環境・報酬定義だけの違いで分岐する

### 想定される再反論への備え

- 「n=2 で揺らぎ幅 0 は偶然では」→ 正しい。統計的主張はしない。ただし張り付き先が探索範囲の端（20/400）であること + 力学的説明 + n=10 行動検証の三点で支える。シード追加（s3）は学習コスト 5h/run で可能、優先度は中
- 「リーチは Reach と TP で重なっている」→ 認める。リンク長だけでは3タスクは分離せず、gear プロファイル + 行動クラスタで分離する。これは「形態の静的検査だけではタスク適性は判定できない」という本研究の設計動機そのもの（Q1 の 4 と同じ構図）

## Q3: 「タスク識別・判定器としての妥当性は rrbot（手作りの2関節アーム）でしか検証していない。パイプラインが接続することと、判定器が実際にスケッチ由来の形態でも機能することは別の話では？」

（自己検討、2026-07-29。詳細: [実験系譜.md](実験系譜.md) 第8段「追加検証」節）

### 認める部分

- **これは正しい指摘**。実験2（タスク識別）と実験4（パイプライン実証）は別々に検証しており、両者を1本につなぐ実験（パイプライン生成形態そのものでタスク識別が機能することの直接確認）は当初行っていなかった
- 研究の最終目標（任意のスケッチ形態に対する判定器）を素直に主張するなら、この繋ぎ目こそが要になる

### データによる反論

- **既存 checkpoint の再分析（追加学習なし）で確認済み**: tripo_v2c で完走済みの3タスク（Pusher・Reach・Target-Pusher、各1シード）の best checkpoint を再プローブしたところ、rrbot で確立した分離パターンが質的に再現した——Reach は3関節すべてがギア比下限（20）・総リーチ 1.563 m、Pusher・Target-Pusher はギア比上限寄り（368〜400）・総リーチ 2.0 m 台
- 特に Reach の「3関節ともギア下限に張り付く」という署名は、rrbot Reach の「肩ギア下限張り付き」と同じ力学的機構（確率的方策のノイズ×gear によるホバー時ジッタ回避）で説明でき、偶然の一致ではないと解釈できる

### 貢献の位置づけ

手作りの2関節アーム（rrbot）で確立したタスク識別のメカニズムが、パイプラインが生成した別クラスの形態（tripo_v2c）でも同じ形で機能することを、追加学習なしの再分析で示せた点は、判定器の汎用性を主張する一次的な裏付けになる

### 想定される再反論への備え

- 「1シードでは頑健性が言えない」→ **認める**。tripo系は各タスク1シードのみで、rrbotのような2シード一致の頑健性検証は行っていない。主張は「質的な再現を確認した」に留める
- 「これはタスク間の分岐（形態がタスクで変わるか）の確認であって、同一タスクで良い/悪いスケッチを判別できるかの確認ではないのでは」→ **正しい、これは別の主張**。同一タスク・複数形態でのスコア順位付けは rrbot の PJ 実験（4.3.3.1）に加え、**tripo 系（パイプライン生成形態）でも 2026-08-03 に確認済み**（4.3.3.2: 到達可能な長腕 best −12.48 が到達不能な短腕 best −396.92 を 384 ポイント上回った）。したがって「最も本質的なギャップ」は解消された。**2026-08-04 に残っていた2つの限界も解消された**: (i) 適合側は seed=1 でも best −10.27（seed=0 の −12.48 と 0.6% 差）で**シードに頑健**、(ii) 到達可能性が同等な中間スケール（0.887 m）と長腕（1.451 m）の間でも −3.42 対 −12.48 と 3.6 倍の差が付き、**判別解像度も十分**であった（第4章 4.3.3.3）。なおこの実験では**ep26まで悪い形態の方が高スコアだった**（ep27で逆転）ため、「判定は早期に打ち切れる」という主張はしないこと

## Q4: 「結局このシステムは『長い腕ほど良い』と言っているだけではないか？ 到達できる長さがあれば勝つのは当たり前で、co-design を使う必要がない」

### 認める部分

- Q3 までの証拠（4.3.3.1・4.3.3.2）は**確かにこの批判に対して弱い**。短腕は届かず長腕は届く、という設定なので、「長い方が勝つ」以上のことを示していない
- 単に「届くか」を判定するだけなら、リンク長の総和を目標距離と比べれば済み、学習は不要である（実際それは診断の第1層としてそのまま実装した、第3章 3.12）

### データによる反論 — 順位が反転する

同じ3形態を Reach と Pusher の2タスクにかけたところ、**最良形態がタスクによって入れ替わった**（第4章 4.3.3.3、表4.10）。

| 形態 | 総リーチ | Reach | Pusher |
|---|---|---|---|
| short | 0.403 m | −396.92（3位） | −0.00（3位） |
| mid | 0.887 m | **−3.42（1位）** | 34.32（2位） |
| long | 1.451 m | −12.48（2位） | **96.18（1位）** |

- 変えたのは**タスクだけ**（形態集合・最適化器・エポック数・シードはすべて同一）
- 「長いほど良い」なら long が両方で1位になるはずだが、Reach では mid に負けている
- 機構も説明できる: Reach は「目標距離への適合」を要求するため余剰長 0.65 m が慣性と姿勢自由度の増加として不利に働く。Pusher は先端速度がリーチに比例するため長さがそのまま有利になる

### 貢献の位置づけ

この結果は、判定器が**形態の絶対的な大きさではなくタスクの要求に照らして評価している**ことの直接的な証拠である。同時に、幾何だけでは決まらない領域が存在することも示している——short の除外は幾何（第1層）で学習なしに判定できるが、mid と long の優劣は学習を回さないと分からない。これが co-design を使う必然性そのものになっている。

### 想定される再反論への備え

- 「各条件1シードでは反転が偶然かもしれない」→ **反転の要については反論できる**。反転が成立するには Reach 側で mid が long を上回ることが必須なので、この1組を2 seed で押さえた:

  | 形態 | seed=0 | seed=1 | 最悪値 |
  |---|---|---|---|
  | mid | −3.42 | −1.66 | **−3.42** |
  | long | −12.48 | −10.27 | −10.27 |

  **mid の最悪値が long の最良値を上回っており、2 seed の範囲でスコア域が重ならない**（差 6.85）。平均の比較ではなく域の非重複なので、seed の揺らぎでは説明できない。Pusher 側についても中間スケールと長腕の seed=1 が揃い、**mid 34.32〜44.94 対 long 96.18〜99.37 で域が重ならない**（第4章 4.3.3.3）。したがって反転の両側が 2 seed で裏づけられている。**認めるのは両タスクの short が seed=0 のみ**である点だが、これは物理的に到達不能で結果が飽和しており（−396.92 / −0.00）seed 依存の余地は小さい
- 「Pusher の 2.8 倍という数字は 200ep 打ち切りの産物では？」→ **正しい指摘であり、だから比率は主張しない**。mid は ep100 の 14.93 → ep199 の 28.71、long は 54.46 → 92.90 と両方とも学習後半でなお伸びており、200ep では未収束である（mid は末端10epだけで +20%）。**主張するのは順位のみで、比率は暫定値として扱う**。確定させるため 1000ep 版を実験キューに投入済み。なおこの研究は「200ep 打ち切りが条件間で不公平に働く」ことを M 系アブレーションで既に実証しており（第5章 5.4）、その教訓を自分の実験に適用した形である
- 「Reach と Pusher でスコアの絶対値が比較できていない」→ **その通りで、比較していない**。報酬の定義が違うため同一尺度では比べられず、**有効なのは各タスク内の順位のみ**である。この点は第4章 4.3.3.3 の限界に明記した
- 「形態の違いがスケールだけで、リンク長の配分や関節配置を変えていない」→ **配分については検証済み**。総リーチを 0.887 m に固定して配分だけを反転させた 2 形態（根元重 対 先端重）を Reach で比較すると、根元重 −1.65〜−1.81 対 先端重 −4.39〜−5.75 で 2 シードともスコア域が重ならない（第4章 4.3.3.4）。**この 2 形態は最大リーチが同一なので第1層は同一の出力しか返せず**、幾何では区別できない対を判定器が順序づけた事例になる。**認めるのは関節配置の偏りの軸**で、こちらは未検証（第5章 5.7.2 の限界9）

## Q5: 「不適合と判定された後、ユーザーは何をすればいいのか？ 『向いていません』だけならシステムとして役に立たないのでは」

### 認める部分

- **完全に正しい指摘**であり、これは本研究自身が途中で気づいた課題である。判定器のままでは、ユーザーが形態を直して再投入し、また「向いていません」と言われる試行錯誤を繰り返すだけで、システムは実質的に何も支援していない

### データによる反論 — 診断機能（M7）を実装した

判定結果を人間可読な指摘へ翻訳する診断機能を、幾何・収束設計・行動の三層で実装した（第3章 3.12、`scripts/diagnose_morphology.py`）。

- **第1層は学習不要・約1秒**で不適合を検出し、**必要な拡大倍率を数値で返す**（例:「腕全体を 2.19 倍に伸ばしてください」）。同じ結論を学習で得るには約20時間かかる
- 実際に 4.3.3.3 の3形態へ適用したところ、**第1層だけで Reach の順位を的中させた**（short ❌到達不能 / mid ✅余裕10% / long ⚠️長すぎ）
- Pusher では long に「静止姿勢で対象に貫入する可能性」と `arm_safe_init` の付与を提示し、これは人手で決めた起動設定と一致した

### 貢献の位置づけ

「co-design は良い形態と悪い形態を判別できる」から「**co-design はなぜ悪いかを説明し、次の一手を示せる**」への拡張であり、専門知識のいらない設計支援という研究目標に直接対応する。

### 想定される再反論への備え

- 「第1層は単なる作業空間解析で、ロボット工学では古典的な手法では？」→ **その通りで、手法としての新規性は主張していない**（第2章 2.4 に明記）。新規なのは (a) co-design の前段スクリーニングとして配置したこと、(b) 必要倍率という行動可能な出力にしたこと、(c) 学習後の情報と階層的に組み合わせたこと、(d) 収束設計の署名が単独では判別に使えないという実験的知見、の4点
- 「幾何診断が当たるなら学習は要らないのでは」→ **当たるのは Reach だけ**。Pusher では第1層は mid と long の優劣を予測できず、実際の順位は long > mid である。幾何が学習を代替できるのは**タスクの要求が運動学量に還元できる場合に限られる**（第5章 5.5.3）
- 「**その助言に従えば本当に直るのか**」→ **最も鋭い再反論であり、実際に一度は直らなかった**。
  助言に従って形態を修正し再入力する閉ループを組んだところ、提示倍率が丸めで必要量を下回っており、
  **助言どおりに直しても不適合のままだった**（Bug 22、第4章 4.4.2）。切り上げと余裕の付与で是正済み。
  この欠陥は判定の正しさを見る枠組みでは検出できず、閉ループを組んで初めて現れた。
  「助言を返す機能は、助言に従った結果を作って再入力するまで検証したことにならない」という
  一般的な教訓として第5章 5.6.2 に記述している。**隠さずこの経緯ごと話すのが最も強い**
- 「『動きが思ったのと違う』にはどう答えるのか」→ **答えられない**。第3層で「何が起きたか」（一撃で吹き飛ばす／押して止める／静止保持）は報告できるが、意図に合わせて報酬を自動設計する機能は本研究の範囲外とした。報酬設計の複雑化が探索信号を消す事例を確認しているため（第5章 5.2.1）、意図的に踏み込んでいない（第3章 3.12.5）

## Q10. 「幾何診断（第1層）はリンク長を足すだけに見える。それで『到達可能性を判定した』と言えるのか？」

**想定される場面**: 第1層を「学習不要で確定的」と強調するほど、その単純さを突かれる。
実際に本研究では**この層が二度、確信を持って誤答している**ので、隠さず先に出すのが安全。

### 一次回答

> 単純な式であることは事実で、**その式が成り立つ前提を二つ持ちます。本論文では前提を明記し、
> 実装は前提が破れたことを検出して棄却します**（第3章 3.12.2 節）。
>
> 第一の前提は「各関節が直前のリンクの先端にある」ことです。形態を生成する工程がこれを崩すと、
> 描画上の長さと運動学的な到達距離が乖離します。本研究では実際にこれが起き、
> 実効到達距離が公称値の 63% しかない形態を第1層が「余裕 0% で到達可能」と判定しました。
> 現在は総和と関節位置の連鎖を突き合わせ、一致しない形態を不整合として棄却します。
>
> 第二の前提は「全関節が同一軸を向く平面アーム」であることです。根元に旋回関節を持つ
> 非平面アームでは、旋回軸に平行なリンクは水平方向に伸びません。実際に非平面4関節アームでは
> 総和 1.002 m に対し水平到達限界は 0.797 m でした。現在は各リンクをそれ自身の関節軸と比較し、
> 寄与しないリンクを除いた水平限界で判定します。

### 追加で聞かれたら

- **「では今の実装は一般のアームで正しいのか」** → いいえ。厳密なのは
  「平面アーム」または「旋回軸 + 単一平面内の関節列」までです。関節軸がさらに多様な腕では
  正確な到達範囲は関節可動域込みの順運動学を要し、第1層が狙う計算量（約1秒・学習不要）を超えます。
  **その場合は第1層を上限の目安として読み、判定は第3層に委ねる**設計です
- **「二度も誤ったなら層構成そのものが疑わしいのでは」** → 逆に、**誤りが二度とも
  第1層の内部で閉じ、学習を伴う層に波及しなかった**点を強調します。第1層は安価なので
  検算を追加でき、実際にどちらも検算（実効リーチの再計算）で検出しています。
  高コストな層に同じ前提を埋め込んでいたら、発見はずっと遅れていました
- **「なぜ最初から順運動学で解かないのか」** → 第1層の存在意義は
  「学習を1エポックも回さずに棄却できること」にあり、可動域を含む数値解法を持ち込むと
  その利点（約1秒・シミュレータ不要）が失われます。**厳密さと即答性の交換**を意図的に選び、
  前提が破れる場合を検出して安全側に倒す設計としています

### Q12. 「手描きと言うが、実際には AI が描いた絵を写しただけではないか」（2026-09-02 追加）

**そのとおりで、隠していない。**入力の作り方は
[E2E実走_手描き入力.md](E2E実走_手描き入力.md) に明記してある。

- Gemini が生成した参照画を**人が紙に模写**し、その紙を M1 へ渡す
- **入力は人が描いた紙**なので「手描きを入力とする E2E」の主張は成立する。生成画像が担うのは参照だけ
- 参照を固定したのは**交絡低減のため**である。A群が測るのは「描画が揺れても同じ形態が出るか」であり、
  揺らしたいのは描画の実行だけ。頭の中から3回描くと**設計意図そのものが drift** し、
  形態の変化が描画のばらつきのせいか意図のばらつきのせいか分けられなくなる

**これは弱点ではなく統制の説明として述べる。** ただし「参照画は生成物である」事実は必ず言う。
落とすと再現性の記述として不足する。
