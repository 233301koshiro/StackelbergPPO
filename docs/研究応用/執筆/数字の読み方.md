# 数字の読み方 — 表と用語の意味

**この文書の用途**: 実験系譜や総括表に出てくる数字が「何を測ったものか」を思い出すため。
用語の定義と、**間違えやすい読み方**を集めてある。

新しい知見はここに書かない（それは [実験系譜.md](../台帳/実験系譜.md)）。
ここは**読み方の説明だけ**を持つ。

> ⚠️ **2026-10-26 更新**: §3・§4 の学習の数値を実在の物理（`*_phys`、系譜 9-246）の値に差し替えた（値は各 run の `log_train.txt` の best）。⛔ 第3層の閉ループは**読みが逆になった**（旧い物理では助言が出て固定で良化、今は助言が出ないのに固定しても落ちない）。§5・§8 の学習の数値は旧い物理（撤回、[知見総括表](知見総括表.md) E 節の 1 行目）のもので、読み方の例としてだけ残す。§1・§2・§6・§7 は学習を使わない（幾何・パイプライン）ので、物理の取り直しの影響を受けない。

## 1. ✅ の横の「余裕 20 %」とは

**成長率ではない。「目標に対してどれだけ手が余っているか」**である。

```
余裕 = (水平到達限界 − 目標までの距離) ÷ 水平到達限界
```

目標は常に 0.8 m の位置にあるので:

| 形態 | 水平到達 | 計算 | 余裕 |
|---|---|---|---|
| A1v | 1.006 m | (1.006 − 0.8) / 1.006 | **20 %** |
| A2v | 1.181 m | (1.181 − 0.8) / 1.181 | **32 %** |
| B2v | 1.226 m | (1.226 − 0.8) / 1.226 | **35 %** |
| B1v | 0.680 m | (0.680 − 0.8) / 0.680 | **−18 %** → ❌ |

**「腕をいっぱいに伸ばしたとき、目標より 20 % 先まで手が届く」**という意味。
**学習前に、幾何だけで出せる。**

---

## 2. 「閾値との比較」とは

**第1層の判定は「届くか届かないか」の一本勝負**である。

```
水平到達 1.006 m  vs  目標 0.8 m  → 届く   ✅
水平到達 0.680 m  vs  目標 0.8 m  → 届かない ❌
```

**0.8 m をまたぐかどうかだけ**を見る。だから前段（絵→モデル）が 18 % ばらついても、
1.006 が 1.18 になろうが 0.85 になろうが**答えは「✅」のまま**である。
これが「**18 % のばらつきは判定を変えない**」（9-29 ①）の意味。

⚠️ **裏返すと弱点でもある。** 0.8 のすぐ近くにいる形態なら、ばらつきで答えがひっくり返りうる。
⚠️ **ただし犯人は M2 ではない**（9-39）。hockey は閾値の 6 % 上だが、
同じ M1 画像から 4 本作って**4 本とも ✅** だった（M2 の分散は ±0.4 %）。
**怖いのは M1 のばらつきと、入力の測り方**である。

## 3. 「閉ループが成立した」とは

**システムが出した助言に実際に従ってみて、本当に良くなるか確かめた**ということ。

```
① システム「この腕は目標に 397 mm 届きません。1.99 倍に伸ばせば届きます」（第1層）
      ↓
② 1.99 倍に伸ばした XML を作る（それ以外は同一。今はスクリプトが倍率を掛ける）
      ↓
③ 学習し直す
      ↓
④ −397.20 → −0.47 / −0.37（2 seed）に良くなった  → 助言は正しかった ✅
```

助言を出しっぱなしにせず **②③④まで回した**から「閉ループ」。
開いたまま（助言を出すだけ）では、本当に良くなるのかは誰にも分からない。

この repo の閉ループと、実在の物理での状態:

| 層 | 助言の向き | 検証（実在の物理） |
|---|---|---|
| 第1層 | **増やす**（腕を N 倍に伸ばせ） | 到達 −397.20 → **[−0.47, −0.37]**（読み ③、系譜 9-279・9-304）。押し 短腕 −0.00 → 2.11 倍 **[7.12, 8.66]**（読み ⑯⑰、9-280・9-306） |
| 第3層 | **減らす**（使用率 10 % 未満の関節は固定してよい） | ⚠️ **助言が出ていない**（手描き A1 の関節 3 の使用率は到達 31〜47 %・押し 48 %）。助言どおりの閉ループは回せないので、**助言が出なかった関節を固定したらどうなるか**を測った（§4） |

> ⛔ 旧い物理（撤回）では第3層が「使用率 7 %」で助言を出し、固定して −6.30 → −5.32 に良化した（9-27）。今はこの読みを言わない。

## 4. 「固定 / 可動」の表の読み方（9-273・9-293・9-305）

手描き A1 の関節 3 を動かせる腕（可動）と、関節 3 だけ動かなくした腕（固定）を比べる。

| タスク | 可動（seed 0 / seed 1） | 固定（seed 0 / seed 1） | 向き | 帯 | 第3層の助言 |
|---|---|---|---|---|---|
| **到達** | −4.08 / −3.90 | **−3.21 / −3.70** | 固定が上（落ちない） | **重ならない**（隙間 0.20） | 出ていない（使用率 31〜47 %） |
| **押し** | 63.68 / 62.64 | **45.03 / 41.50** | 固定が下 | **重ならない** | 出ていない（使用率 48 %） |

seed 1 はどちらも Bug 76（ワーカーの乱数の種の重なり）を直した後の種で回した run（到達は `_s2_ws`、押しは `_s2`）。

**「帯が重ならない」= 種を変えても順位がひっくり返る余地が無い**という意味。

- **可動** = 関節3 が普通に動く元の腕（`e2e_a1_*_phys`）
- **固定** = 関節3 だけ動かなくした腕（`e2e_a1_fix3_*_phys`）。**リンク長・太さ・質量は同一**
- **到達はマイナスが小さいほど良い**（目標までの残り距離）
- **押しはプラスが大きいほど良い**（対象物をどれだけ動かせたか）

**要点は 2 行を比べること。**

- 到達: 助言は出なかった → 固定しても**落ちなかった** → **閾値（10 %）が要らない関節を見落とした実例**（診断の外れ）
- 押し: 助言は出なかった → 固定したら**下がった** → **助言を出さなかったのは正しい**

⚠️ **到達で言えるのは「固定しても落ちない」まで。** best の帯は離れるが、50 話の中央の帯は重なる（9-305）。「固定した方が良い」とは言わない。
⚠️ **押し側が本体である。** もし押しでも落ちなかったら「関節3 はどのタスクでも要らなかった」だけの話になる。
**下がったからこそ「関節 3 の要否はタスクで変わる」と言える。**

> ⛔ 旧い物理（撤回）の表（到達 可動 −6.30 / −5.83・固定 −5.32 / −3.85、押し 可動 203.40 / 258.98・固定 179.89 / 249.66 で帯が重なる）は今は使わない。しかもその 2 シードは、途中で `e2e_a1` のリンク長が −12 % 変わっていて、実際は 2 形態 × 1 seed だった（9-105）。

## 5. 「順位」とは何の順位か（9-31・9-34 の取り下げ）

> ⚠️ この節の数値は旧い物理（撤回）のもの。**読み方（seed を変えただけで入れ替わる順位は言わない、変数を 1 つだけ振った比較かを見る）は今も同じ**なので、例として残す。

**複数の形態を、スコアの良い順に並べたときの並び順**のこと。

```
Reach（seed 0 だけ見ていたとき）        Reach（seed 1 も回したら）
  1位 A1v  −13.65                        1位 B2v  −10.60   ← 3位だったものが1位
  2位 A2v  −14.64                        2位 A2v  −10.95
  3位 B2v  −19.67                        3位 A1v  −13.65   ← 1位だったものが3位
  → 余裕 20 < 32 < 35 % と並ぶ            → 完全に逆転
```

主張したかったのは「**余裕が大きい形態ほど性能が悪い**」という関係。
**乱数の種を変えただけで順位が入れ替わるなら、その関係は言えない。**

### ⚠️ なぜ 9-11 の梯子は無事なのか

**実験の質が違う。**

| | 縦型 3 形態（9-29、取り下げ） | **9-11 の梯子（`pj_*`、有効）** |
|---|---|---|
| 比べたもの | **形が全部違う** 3 つの手描き | **同じ形態**で余裕だけ 0 / 5.3 / 10 % |
| seed | 各 2 | 各 2 |
| 条件間の差 | seed 幅（最大 **9.07**）に埋もれた | **隣接条件の範囲が重ならない** |
| 結果 | ❌ 順位を主張できない | ✅ 単調悪化と言える |

**変数を1つだけ振った統制実験かどうか**が分かれ目。
**「余裕は単調に害」の根拠は 9-11 だけ**であり、縦型 3 点を傍証に足してはいけない。

> ⛔ 9-11 も旧い物理（9-245 以前、撤回）の run で、実在の物理では梯子を取り直していない。今「余裕は単調に害」を結論として言わない。ここで残すのは「統制実験かどうかが分かれ目」という読み方だけ。

## 6. 平面と縦型で B1 の「長さ」が変わるのはなぜか

**リンクの長さは 1 mm も変わっていない。変わったのは測っている量。**

```
平面 e2e_b1    upper_arm 0.2628 + forearm 0.2435 + hand 0.2828  = 0.7891 m
縦型 e2e_b1v   base 0.5310 + 上と同じ 3 本                        = 1.3201 m
                ↑ 台座が「固定の土台」から「動くリンク」になった
```

**それなのに水平到達は 0.789 → 0.680 と減る。** 理由は 2 つ。

**① 回転軸と平行なリンクは、水平に伸びない。**

```
     │ 台座 0.531 m は鉛直
     │      ← 根元の関節はヨー（鉛直軸まわり）＝この棒と平行
     ●         いくら回しても棒は倒れず、高さを稼ぐだけ
```

**② 肩が高いと、水平に使える距離が減る。**
肩は 0.531 m の高さにあるのに目標は 0.15 m。腕を斜め下に向ける必要があり、
その分だけ水平方向の到達が短くなる。

**まとめ: 全長（1.320 m）と水平到達（0.680 m）は別の量。** 表に出しているのは**水平到達**。

## 7. 「同じように描いたのに 18 % ずれた」の出所（**2026-09-08 解決**）

A1（定規）と A2（フリーハンド）は**手描きの段階で 1.01 対 1.01 と一致**していたのに、
生成された XML の総リーチは **1.0102 m 対 1.1958 m** と 18 % ずれた（9-22）。

**同じ M1 画像を Tripo3D に 4 回入れて切り分けた**（9-39）。

| | 分散 |
|---|---|
| **M2（三次元化）だけ** | **±0.7 %** |
| A1 ↔ A2 の差 | **18 %** |

**桁が 1 つ違う。18 % はほぼ M1（画像整形）由来である。**

⚠️ **かつて「Tripo3D は 8 % 揺れる」と書いていたが、条件付きだった。**
その 8 % は **A3 の失敗 2 本**で測ったもので、どちらも腕が寝ていて姿勢の解釈が割れていた。

| 入力 | M2 の再現性 |
|---|---|
| 3/4 アングル（姿勢が曖昧） | ±8 %（失敗時） |
| **真横（姿勢が明確）** | **±0.7 %** |

**対策の当てどころ**: M2 は外部サービスで触れないが、**M1 はプロンプトで制御できる**。
ばらつきを減らすならプロンプト側を詰める。

## 8. 「描いた絵がそのまま動く」と言ってよいか

> ⚠️ この節の例（9-28）は旧い物理の run で、リンクの付き方（`bone_offset`）を設計変数にしていた頃の話。今の E2E の標準構成（`pusher_gearonly`）はリンク長を学習せず、スケッチの比で固定している（[軸6_部品ライブラリ](../設計/軸6_部品ライブラリ_2026-10-02.md) §8）。言い方の注意は今も同じ。

**言い方には注意が要るが、大した話ではない**（9-28 ④、2026-09-08 トーンダウン）。

- **動いて曲がるのは当たり前**。それは指していない
- 指しているのは **`bone_offset`＝静止時の骨格の形**が変わること。
  設計図では body 11 が body 1 の真上 (0, 0, 0.2195) に付くが、収束後は
  横下 (−0.5, 0, −0.097) に付く。**組み立て図が別物**になっている
- ただし **co-design とは形態を変えるものなので、これ自体は発見ではない**

**発表での言い方**: 「あなたのスケッチが動いています」ではなく
**「スケッチから出発して、システムがタスクに合わせて作り替えた形が動いています」**。

⚠️ 修論の記述（「比率は **XML まで** 保存される」）は**元から正確**なので変更不要。

**9-28 で本当に意味があるのは別の 2 点。**

1. **x オフセットが探索範囲の上限 ±0.5 に張り付いている**（Pusher で 3 本）。
   **「これが最適」ではなく「これ以上曲げられなかった」。**
   角度や倍率を主張に使うなら上限を広げた再走が要る
2. それまで**リンク長（ノルム）しか見ていなかった**ので向きの変化に気づいていなかった。
   **観測の穴**であり、動画にして初めて見えた

## 用語ミニ辞典

| 言葉 | 意味 |
|---|---|
| **水平到達（限界）** | 腕をいっぱいに伸ばしたとき、目標の高さで水平方向にどこまで手が届くか。**全長とは別** |
| **余裕** | 目標に対して手がどれだけ余っているか。`(水平到達 − 0.8) ÷ 水平到達` |
| **第1層 / 第2層 / 第3層** | 診断の三層。①幾何だけ（学習不要）②収束した設計 ③実際の動き |
| **閉ループ** | 助言に従った形態で学習し直し、本当に良くなるか確かめること |
| **seed** | 乱数の種。同じ設定でも seed が違えば結果が変わる。**幅が大きいと順位が主張できない** |
| **順位** | 複数の形態をスコア順に並べた並び。「余裕が大きいほど悪い」等の関係の根拠になる |
| **統制実験** | **変数を 1 つだけ振った**比較。9-11 の梯子がこれ。形が全部違う比較（9-29）とは質が違う |
| **co-design** | 形態（Leader）と制御（Follower）を同時に最適化すること。**形は変わる** |
| **bone_offset** | リンクの付き方。長さと向きの両方を持つ。**静止時の骨格の形**を決める |
