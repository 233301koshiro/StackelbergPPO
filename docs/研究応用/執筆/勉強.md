# 勉強 — 自分の研究を自分の言葉で説明できるようになるまで

> 2026-10-21 作成（ユーザー「この勉強手順は勉強.md にまとめて」）。
> **目的**: 修論の執筆とゼミ・輪講・予備審査の発表のために、研究の中身を自分の言葉で説明できるようになる。ゴールは「何も見ずに 1 分で研究を説明できる」（第 2 部の白紙テスト）で、そこまで来たらスライドを作る。
> **いつやるか**: Claude のセッションが上限に達して使えない時間（2026-10-21 ユーザー）。使える間は Claude を使う作業を優先する。
> **読む人**: 自分（研究の本人）。ここは手順と読む順番だけを持つ。中身はリンク先にあり、ここには書き写さない。

---

## ⚠️ 先に知っておくこと（2026-10-21 時点）

- **数字は覚えない。筋と仕組みを覚える。** 修論の数値は、旧い物理（撤回済み、[実験系譜.md](../台帳/実験系譜.md) 9-246）から実在の物理の値へ書き換えている途中（進捗の D-6、判定がそろうのは 10 月末）。いま md に載っている数値には、旧い物理のものが混ざっている。
- **「言ってはいけない読み」を先に知っておく。** 撤回した主張が、古い md の中では正しい顔をして残っていることがある。段 3 で [知見総括表.md](知見総括表.md) の E 節を必ず読む。
- 分からない語が出たら、その場で調べずに**メモに書いて先へ進む**。段の終わりにまとめて [修論の読み方ガイド.md](修論の読み方ガイド.md) の 8 節（用語ミニ辞典）・[数字の読み方.md](数字の読み方.md)・実験系譜の「用語ミニ辞典」で引く。それでも分からなければ Claude に聞く。

## 第 2 部 白紙テストからスライドへ

第 1 部の確認の問いに、だいたい答えられるようになったら進む。

1. **白紙で 1 文**: 「この研究は何を問い、何が分かったか」を何も見ずに書く
2. **白紙で 1 分**: 問い → 方法 → 結果 → 限界の 4 段で、口で言えるところまで広げる
3. **照合**: 書いたものを Claude に送る。知見総括表と E 節に当てて、ずれている所を返してもらう（撤回した主張・旧い物理の数値が出やすい）
4. **主張を並べる**: 言いたいことを 8〜12 個の主張に分け、それぞれに証拠を 1 つ（表・図・run）付ける。証拠が付かない主張は、理解が浅いか、まだ示せていないかのどちらか
5. **口頭試問**: Claude に質問してもらう（想定問答.md の質問を使う）。答えられなかった所は 4 か第 1 部に戻る
6. **スライドにする**: 1 枚に主張 1 つと図 1 つ。主張の文をそのままスライドの題にする。スライドは自分が PowerPoint で作り、スクショを Claude に貼って照合してもらう

## 第 5 部 道具の層を、大きい粒度から理解する（予備審査の質疑の準備）

> 2026-11-16 追加（ユーザー「env とかプラグインとかの話してて思ったけど予備審査対策のためにそこら辺の勉強もしておかなくちゃいけないよね。いちばん大きな粒度から学ぶためにはどの順番でなんの概念を理解したらいい？」）。
> **目的**: 審査で「シミュレータは何で、物理はどこまで本物か」「学習の中で何が起きているか」と聞かれたときに、層を指さして答えられるようになる。第 1 部の段 2（システムの仕組み）の、1 段下の層にあたる。
> **進め方**: 上の層から順に読む。下の層は、上の層の「どこの部品か」が分かってから読む。各層の **確認の問い**に口で答えられたら次へ進む。コードは読まなくてよい（審査ではコードの行ではなく、役割と限界を聞かれる）。

### 全体の地図（この順に降りていく）

```
層 A  研究のシステム      絵 → 3D → ロボットのモデル → 判定・助言（M1〜M7）
  └ 層 B  学習の枠組み      方策（エージェント） ⇄ 環境（env）を何万回も往復する（強化学習）
      └ 層 C  共設計          方策が「形を決める役（Leader）」と「動かす役（Follower）」に分かれる（Stackelberg PPO）
          └ 層 D  env           方策とシミュレータのあいだの通訳。観測・行動・報酬・終わりの条件を決める
              └ 層 E  シミュレータ   Choreonoid（入れ物のアプリ）＋ 物理エンジン（AIST。差し替えられる部品＝プラグイン）
                  └ 層 F  物理エンジンの 1 tick   当たり判定 → 接触の力 → 運動の積分
                      └ 層 G  ロボットのモデルの値   長さ・質量・ギア比・トルク上限・回転子の慣性・減衰・可動域（実在の部品から導いた値）
```

上から読むと「何のためにあるか」が分かり、下から読むと「どこが本物でどこが近似か」が分かる。審査ではこの 2 つを聞かれる。

### 層 A〜C 研究と学習の枠組み（第 1 部の段 2 が済んでいれば復習）

| 概念 | 一言で | 読むもの |
|---|---|---|
| 強化学習 | 試して、報酬で良し悪しを知り、方策を少しずつ直す。教師データは要らない | [システム概要.md](../../リポジトリ説明/システム概要.md) の「何をしているシステムか」「学習ループの全体像」 |
| 方策・観測・行動・報酬・エピソード・step | 方策は「観測 → 行動」の関数（ニューラルネット）。1 回の試行がエピソード、その 1 コマが step | 同「1エピソードの流れ」 |
| PPO | 方策を「一度に大きく変えすぎない」ように直す、標準的な学習の手法 | [コードベース概要.md](../../リポジトリ説明/コードベース概要.md) の「ネットワーク更新フェーズ」 |
| 共設計と Stackelberg | 形（設計）を決める役が先に決め、動かす役がそれに合わせる。形の側は「動かす役がどう合わせてくるか」を見越して決める | [システム概要.md](../../リポジトリ説明/システム概要.md) の「2つの意思決定者」「Stackelberg 戦略とは」 |
| エピソードの 3 段階 | 骨格を決める → 属性（長さ・太さ・ギア比）を決める → 実行（動かす）。形を固定した run（`fix_skeleton`）は前の 2 段を飛ばす | 同「1エピソードの流れ」 |
| seed | 乱数の種。同じ設定でも seed で結果がぶれるので、順位は seed をまたいだ帯で言う | [数字の読み方.md](数字の読み方.md) |

確認の問い:
- 「方策」と「env」はそれぞれ何で、1 step のあいだに何を渡し合うか
- 形と動かし方を同時に学習すると、なぜ順番（どちらが先に決めるか）が問題になるのか
- 判定器として使うとき、学習の結果のどの値を見ているか（[修論の読み方ガイド.md](修論の読み方ガイド.md)）

### 層 D env（環境）— 方策とシミュレータの通訳

| 概念 | 一言で | 読むもの |
|---|---|---|
| env の役割 | 行動をトルクに直してシミュレータへ渡し、結果の状態から観測と報酬を作って方策へ返す | [choreonoidシミュレーション.md](../../リポジトリ説明/choreonoidシミュレーション.md) の「1 ステップの物理進行」「学習ループ全体の流れ」 |
| タスク（Reach・Pusher・Target-Pusher・四脚の歩き） | タスクの違いは、ほぼ env の報酬と終わりの条件の違い | [システム概要.md](../../リポジトリ説明/システム概要.md) の「タスク」、修論 4.1.2 |
| リセットとランダムなずれ | 毎エピソードの開始時に、関節と箱へ ±0.1 のずれを足す。どの話も、そのずれのくじの 1 本 | CLAUDE.md ⑤-3 の終わり |
| ⭐ env が物理エンジンの外で足しているもの | AIST が扱わない量（関節の減衰・速さの上限・可動域・壁の跳ね返り）を、env が毎 step 自分で掛けている | [choreonoidシミュレーション.md](../../リポジトリ説明/choreonoidシミュレーション.md) の「本研究が実際にやっていること」 |

確認の問い:
- 報酬を変えるのと、物理を変えるのとでは、どちらが env の仕事か
- 「壁の跳ね返りは物理エンジンではなく env で計算している」とは、具体的に何をしているのか。修論ではそれをどう書くか

### 層 E シミュレータ — 入れ物（Choreonoid）と部品（物理エンジン）

| 概念 | 一言で | 読むもの |
|---|---|---|
| シミュレータと物理エンジン | Choreonoid は画面・モデルの読み込み・時間の管理をする入れ物。力と動きを計算するのは、差し替えられる部品の物理エンジン（本研究は AIST） | [choreonoidシミュレーション.md](../../リポジトリ説明/choreonoidシミュレーション.md) の冒頭「Choreonoid / AIST / Bullet の関係」 |
| プラグイン | Choreonoid に後から足す部品。物理エンジン（AIST・Bullet・ODE…）も、RobotAssembler（軸6）もプラグイン | 同上 |
| MuJoCo と Choreonoid の二重構造 | ロボットは MuJoCo の形式（XML）で書き、学習のときに Choreonoid の形式へ変換して動かす。解析・プローブには MuJoCo を使うこともある。両者で物理が違う | CLAUDE.md §⑤-3「プローブが本番と同じシミュレータで回っているか」、[choreonoidシミュレーション.md](../../リポジトリ説明/choreonoidシミュレーション.md) の「ロボットモデルの読み込み」 |
| なぜ Choreonoid か | 研究室で使っているシミュレータだから（RobotAssembler もその上で動く）。GPU で何千体も並列に回すシミュレータより並列の数は桁で少ないが、いまの律速は物理ではなくネットワークの更新（GPU）。言ってはいけないことも Q60 にある | [想定問答.md](想定問答.md) Q60、[choreonoidシミュレーション.md](../../リポジトリ説明/choreonoidシミュレーション.md) の「なぜ Choreonoid を使うのか」 |
| エンジンを替えない理由 | 替えると接触がすべて変わり、これまでの結果と比べられなくなる。さらに、この環境の Bullet は動かない（2026-11-16） | 同「では Bullet に替えればいいのでは？」 |

確認の問い:
- 「Choreonoid で学習した」と言うとき、物理を計算しているのは誰か
- 物理エンジンを替えると、何が変わり、何が変わらないか

### 層 F 物理エンジンの 1 tick — 当たり判定・接触の力・積分

| 概念 | 一言で | 読むもの |
|---|---|---|
| 時間の刻み（timestep・刻みの分割・frame_skip） | 物理は小さな刻みで進め、方策は数刻みに 1 回だけ行動を決める（本研究は制御 1 回 = 0.04 s） | [シミュレーションの値の変更表.md](../設計/シミュレーションの値の変更表.md)、Bug 68 |
| 当たり判定（衝突検出） | 物どうしが重なったかを、形（箱・カプセル・三角形の集まり）から調べる | [デバッグ戦記.md](../../デバッグ戦記.md) Bug 103 の冒頭 |
| 接触の力（拘束ソルバー） | 重なった所に、めり込みを押し戻す力と摩擦の力を、反復計算で決める | Bug 57（接触を捨てる深さ）・Q22 |
| 摩擦・反発 | 摩擦は材質の組ごとに効く。AIST は反発（跳ね返り）を扱えない | [choreonoidシミュレーション.md](../../リポジトリ説明/choreonoidシミュレーション.md) の「一番大事な違い」 |
| めり込み・取りこぼし | 当たり判定が接触を返さないと、物が床を通り抜ける（四脚の脚で実際に起きた） | Bug 103、系譜 9-348 の追記 |

確認の問い:
- 1 step（0.04 s）のあいだに、物理エンジンは何回、何をするか
- 「床にめり込む」は、当たり判定と接触の力のどちらの失敗でありうるか。四脚の場合はどちらだったか

### 層 G ロボットのモデルの値 — どこまで本物か

| 概念 | 一言で | 読むもの |
|---|---|---|
| リンク・関節・アクチュエータ | 棒（リンク）を回転の関節でつなぎ、関節ごとにモーター（アクチュエータ）がトルクを出す | [システム概要.md](../../リポジトリ説明/システム概要.md) の「ロボットの表現方法」 |
| ギア比・トルク上限・速さの上限 | 設計変数のギア比が、出せるトルクと速さを決める。上限は実在のアームの定格から | [研究方針.md](../方針/研究方針.md) の「修論の全実験を実在の物理の値で行う」 |
| 質量・慣性・回転子の慣性（armature） | 動かしにくさ。回転子の慣性はモーターの中の回る部分の分で、根元の関節では効きが大きい | CLAUDE.md §⑤-3「形態の差を慣性で説明しようとしたら」 |
| 減衰・可動域 | 根拠の無いまま残る値。修論では「宣言して使う」と書いている | [想定問答.md](想定問答.md) Q15・Q33 |
| 実在の物理の値（`*_phys`） | 密度・トルク・速さ・回転子の慣性を UR5e とアルミパイプから導いた（系譜 9-246） | 同上、[シミュレーションの値の変更表.md](../設計/シミュレーションの値の変更表.md) |

確認の問い:
- 物理の値のうち、実在の部品から導いたものと、根拠なく決めたものをそれぞれ 2 つ挙げる
- 物理を少し変えると判定は変わるか。変わるとしたら、判定の信頼性について何と言うか（Q38）
