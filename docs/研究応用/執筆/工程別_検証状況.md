### ⭐ 「仕様の遵守率」の定義（2026-09-11）

**M1 の検証指標はこれに統一する。** プロンプトが要求している仕様を、
生成結果がどれだけ満たしたかの割合。**版ごと・項目ごと**に出す。

| 項目 | 何を見るか | 合否の基準 | 版 D の実測（n=4、Web UI） |
|---|---|---|---|
| **向き** | 腕が立っているか | **関節の Z 座標の広がり ≥ 0.25**（`check_glb_pose.py` の既存基準） | **3 / 4**（1 本が鉛直から 42.5°） |
| **マーカー数** | マゼンタの球の個数 | **ちょうど 3 個** | **4 / 4** |
| **禁止物** | 寸法線・文字・複数の視点 | **無いこと** | ⏳ 未確認 |
| **比の保存** | 指示した比が保たれたか | ⚠️ **XML まで通して測る**（画像から測らない。遠近で歪む。9-22③） | ⏳ **未確認** |

⚠️ **1 つの数にまとめない。** まとめると**どの制約が守られなかったかが分からなくなる**。
版を進める目的は「**どの制約を足せば何が直るか**」を示すことなので、**項目別でなければ意味がない**。

⚠️ **向きの基準は新設しない。** `check_glb_pose.py` が既に持つ 0.25 をそのまま使う。
**基準を増やすと、較正していない閾値がまた増える**（M4 の 9-69・第3層の 9-70 と同じ轍）。

⚠️ **版 D の値は Web UI で測ったもの。** サンプリング設定が分からないので
**温度の影響とプロンプトの曖昧さを切り分けられない**。**API 化して測り直す。**

**次**: API 化 → 版ごとに上の 4 項目を n 回測る
（[研究方針.md](../方針/研究方針.md)・[M1プロンプトの版史.md](../設計/M1プロンプトの版史.md)）

## M4: 形態パラメータ抽出（OBB）

### この工程は何をするか

**切り分けられたリンクを 1 本ずつ、直方体で囲む。** そこから 2 つの数を取る。

| 取るもの | どこから |
|---|---|
| **リンクの長さ** | ⭐ **関節の位置から**（直方体は使わない。下記） |
| **リンクの太さ** | **直方体の短い方 2 辺の平均 ÷ 2**（カプセル半径とみなす） |

### ⭐ 長さは既に直方体を使っていない（Bug 27 → 31 で移行済み）

当初は**直方体の一番長い辺**を長さにしていた。だが**マーカーの球が長さに混入**して
総リーチが 14 % 過大になった（Bug 27）。そこで**関節から関節までの距離**へ置き換えた。

**先端リンクだけは次の関節が無い**ので直方体のまま残していたが、
**B1 で +52.6 % 過大**（0.4316 m 対 実距離 0.2828 m）になり、第1層が誤って通した。
**最後の関節から最も遠い頂点までの距離**へ直した（Bug 31）。

```
現在: 中間リンク = 関節間の距離 / 先端リンク = 最後の関節から最遠点まで
     どちらも直方体を使わない
```

⚠️ **A1 の XML だけ Bug 31 より前の値**（先端 0.2763。修正後は 0.2743、差 2 mm）。
**学習中だったため再生成していない。** B1 以降は修正後。

### ⚠️ 残る問題は「太さ」— 自己点検が成立していない（9-69）

**太さは今も直方体から取る。** 直方体の一番長い辺を「長さ方向」とみなし、
**残る 2 辺を太さとみなす**。だから**一番長い辺が長さ方向でなくなると、太さが誤る。**

**どんなときに起きるか**: 先端が太い形（ホッケーのマレットのような円盤つき）。
**円盤の直径が柄の長さを超えると**、一番長い辺が「円盤の幅」を指す。

**自己点検があった**: 「一番長い辺 ÷ 2 番目の辺 < 1.5 なら警告」。
細長ければ比は大きい、ずんぐりしていれば小さい、という発想。

**⚠️ 測ったら、この比では検出できなかった**（9-69）。

| 円盤の直径 ÷ 柄の長さ | 最長辺÷2番目 | 長さ方向のずれ | |
|---|---|---|---|
| 1.24 | **1.378** | 0.0° | ✅ 正常 |
| 1.40 | 1.220 | 0.0° | ✅ 正常 |
| **1.42** | **1.362** | **29.5°** | ❌ **破綻** |

**比は破綻の直前まで下がり続け、破綻した瞬間に跳ね上がる。**
直方体が斜めに組み替わると、最長辺も 2 番目も一緒に変わるためである。
**結果、同じ比 1.36 が「正常」と「破綻」の両方で出る。閾値をどこに置いても分けられない。**

### ⭐ 直す方針

**正しい検算の材料は既に手元にある。** M3 が関節の位置を持っており、
**リンクが伸びている向きは「関節から関節への向き」そのもの**である。

| 段 | やること | 備考 |
|---|---|---|
| **1** | **直方体の最長辺と、関節間の方向を突き合わせる**。食い違ったら止める | **長さで既にやっていることを、向きにも広げるだけ** |
| **2** | さらに進めるなら、**太さも関節間方向に垂直な断面から取る**。直方体を使わない | 長さと同じく「推定をやめる」形 |
| 3 | 比 1.5 の警告は**残すが根拠にしない** | ⚠️ **消すと「昔こう判定していた」が失われる** |

⚠️ **警告ではなく例外にする。** いまは警告を出すだけで止まらない。
M3 が分割できないときに例外で止めるのと**設計思想が揃っていない**。

### ⚠️ ホッケーを守っていたのは比ではない

版 D のプロンプトに **「円盤の直径は先端リンク全体の長さの 0.6 倍以下」** という制約がある。
**破綻は 1.41 倍から**なので、**2.3 倍の余裕がある**。
**実際に効いていたのはこの制約であって、比 1.5 の警告ではない。**
