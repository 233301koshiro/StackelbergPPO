# スライド9: 各フローにおける現在の進捗

## タイトル

```
各フローにおける現在の進捗
```

## サブタイトル（1行）

```
手描き5枚を通し、「学習せずに落とす」判定と「助言に従うと良くなる」ことを確認した
```

## 本文（3ブロック）

### ブロック1 — 前段（スケッチ → モデル）

```
手描きスケッチ5枚がモデル生成まで通った
　・関節検出は5枚とも 3/3 自動
　・落ちた1枚は「斜め45度で描いた」もの。2回試して2回とも同じ失敗

→ 腕が寝ると、リンク分割（関節の高さで切る）が原理的に通らない
→ 「前段は入力の視点に依存する」という限界を、原因つきで特定できた
```

### ブロック2 — 判定（学習を回す前に落とす）

```
短く描いたスケッチを、学習せずに棄却できた

　　B1（短い）  到達範囲 0.680 m  →  ❌「目標0.8mに届きません。1.30倍に伸ばしてください」
　　A1/A2/B2    1.006 / 1.181 / 1.226 m  →  ✅

　幾何計算のみ・約1秒（学習は4時間）
```

### ブロック3 — 助言（従わせると本当に良くなる）

```
システムが返した助言に実際に従い、学習し直して確かめた

　　増やす助言「腕を1.99倍に」    −396.92 → −0.33   （残り397mm → 0.33mm、2シード）
　　減らす助言「この関節は固定可」  −6.30 → −5.32 ／ −5.83 → −3.85（2シードとも良化）
　　　　　　　　　　　　　　　　　 帯が重ならない（可動 −6.30〜−5.83 / 固定 −5.32〜−3.85）

　★ 同じ関節を、助言が出ていない押しタスクで固定すると 203.40 → 179.89 と悪化
　　→ 到達では余り、押しでは必要。診断はタスクごとに要否を判断している
```

⚠️ **主張の強さが到達と押しで違う。混ぜないこと。**

| | シード | 言えること |
|---|---|---|
| **到達（助言あり）** | **2** | **帯が重ならない**（可動 −6.30〜−5.83 / 固定 −5.32〜−3.85）。9-11 の梯子と同じ水準 |
| 押し（助言なし） | **2** | **向きだけ**。2 シードとも悪化したが、**帯が重なる**（可動 203.40〜258.98 / 固定 179.89〜249.66） |

> 話し方: 押しの話をするとき「**こちらは 2 シードとも同じ向きに動きましたが、
> 値の範囲は重なっているので、言えるのは向きまでです**」と自分から添える。
> 聞かれてから言うより強い。
>
> ⚠️ **「両方 2 シードで確認した」と一括りに言わない。** 到達は帯が分離、押しは重なる。
> ここを混ぜると、押し側で過剰主張になる（9-62）。

## ノート原稿（読み上げ用・約2分30秒）

```
各フローの現在の進捗です。

まず前段、スケッチからモデルを作る部分です。
手描きのスケッチ5枚が、モデル生成まで通るようになりました。
関節の検出は5枚とも3箇所すべて自動で成功しています。

一方で、落ちた例が1枚あります。斜め45度から描いたスケッチです。
2回試して2回とも同じ失敗をしました。
原因は、三次元化のサービスが斜めの線を「奥行き方向に伸びている」と解釈して、
腕が寝てしまうことです。本手法はリンクを関節の高さで区切るので、
腕が寝ると原理的に分割できません。
つまり「前段は入力の視点に依存する」という限界を、原因まで特定できた形になります。

次に判定です。ここが本研究の中心です。
短く描いたスケッチB1は、到達範囲が0.680メートルで、目標の0.8メートルに届きません。
システムはこれを、学習を一切回さずに棄却し、
「1.30倍に伸ばしてください」という修正指針まで返しました。
この判定は幾何計算だけなので約1秒です。学習は1本4時間かかりますから、
明らかに破綻した形は、学習の前に弾けることになります。

最後に、その助言が本当に使えるのかを確かめました。
システムの助言どおりに形を直して、学習をやり直しています。

「腕を1.99倍に伸ばせ」という増やす方向の助言では、
目標までの残り距離が397ミリから0.33ミリまで、三桁改善しました。

「この関節はほとんど使っていないので固定してよい」という減らす方向の助言でも、
性能は落ちず、むしろ良くなりました。

そして、ここが一番言いたいところですが、
同じ関節を、助言が出ていない押しタスクで固定すると、逆に性能が悪化しました。
つまり同じ関節が、到達タスクでは余っていて、押しタスクでは必要だということです。
助言が正しいことだけでなく、助言を出さなかった判断も正しかった、と言えます。
```

## ⚠️ 言えないこと（聞かれたら／時間があれば口頭で）

```
形態どうしの「どれが一番良いか」は主張しません。
シードを2本にしたら順位が入れ替わりました。
増やしても解決せず、1条件あたり718シード必要と計算しています。
なので順位に依存しない主張だけを残す方針にしています。
```

# スライド10: ゴール

## タイトル

```
ゴール — 修論で何を結論として書き、残り5か月で何をするか
```

## 本文（2ブロック）

### ブロック1 — 修論の結論として書くこと

```
1. 手描きスケッチからタスク適性を試作前に判定するシステムを構築した
　　前段の頑健性・判定の妥当性・助言の有効性を、それぞれ実験で確かめた

2. 判定は「学習せずに落とす層」と「学習して比べる層」に分かれる
　　幾何で決まる部分は約1秒、そうでない部分は約4時間 ＝ 費用の二極化

3. 助言は「増やす方向」「減らす方向」の両方で閉ループが成立する
```

### ブロック2 — 残り5か月でやること

```
① 手描きの例数を増やす
　　いまは5例。前段の頑健性を「成功率」として報告するには足りない

② 前段のばらつきを詰める
　　同じ意図で描いた2枚で総リーチが18%ずれる
　　★ 原因を切り分けた：三次元化は±0.7%しかブレない → 犯人は画像整形側
　　→ 触れない外部サービスではなく、プロンプトで直せる側だと分かった

③ 主結論の seed を増やす（両タスク完了）
　　「助言に従うと落ちない」を2シードで確認。帯が重ならず、傾向として言える水準に
　　押し側も2シードとも同じ向き。ただし帯は重なるので主張は向きまで
```

## ノート原稿（読み上げ用・約1分10秒）

```
最後にゴールです。

修論では3つを結論として書きます。
1つ目は、手描きスケッチからタスク適性を試作前に判定するシステムを構築したこと。
2つ目は、その判定が「学習せずに落とす層」と「学習して比べる層」に分かれること。
幾何で決まる部分は約1秒、そうでない部分は約4時間で、費用が二極化しています。
3つ目は、システムが返す助言が、増やす方向・減らす方向の両方で
閉ループとして成立することです。

残り5か月では3つを進めます。

1つ目は手描きの例数を増やすことです。いまは5例で、
前段の頑健性を成功率として報告するには足りていません。

2つ目は、前段のばらつきを詰めることです。
同じ意図で描いた2枚で、生成されるモデルの大きさが18パーセントずれます。
これについては先日、原因の切り分けができました。
同じ画像を三次元化に4回入れても、ばらつきは0.7パーセントしかありません。
つまり犯人は三次元化ではなく、その前の画像整形の側です。
外部サービスは触れませんが、画像整形はプロンプトで制御できるので、
直せる側に原因があると分かったことになります。

3つ目は、主結論のシード数を増やすことです。
「助言に従うと性能が落ちない」という結果について、両方のタスクで2シード目まで確認できました。
到達タスクは2シードとも良化し、しかも可動と固定で値の範囲が重なりませんでした。
押しタスクも2シードとも予測どおり悪化しましたが、こちらは値の範囲が重なっているので、
言えるのは向きまでです。
この研究では過去に2回、1シードで見えていた傾向がシードを増やすと崩れているので、
これは確かめる価値のある作業でした。今回は崩れませんでした。
```

## ⚠️ やらないと決めたこと（聞かれたら）

```
・形態どうしの順位を主張するためにシードを増やすこと
　　1条件718シード必要で、修論まで150日では届かない

・把持（ものを掴む）
　　判定の対象が腕の構造からハンドの構造へ移り、
　　リンク長と関節位置を抽出する本手法の枠組みで扱えない

・エアホッケーを4つ目のタスクとして実験に入れること
　　前提を洗い直したところ、根拠にしていた批判が実在しなかった（誰も提起していない）
　　指摘の本体は「デモで映える」なので、実験ではなくデモで応える
```
