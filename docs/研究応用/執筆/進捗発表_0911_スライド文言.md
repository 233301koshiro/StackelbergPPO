## 下段: **各段階でどこが壊れたか**（実測つき）

```
① 立体にする
　　★ 絵の中の「比」だけが効く。画素サイズや紙の実寸は効かない
　　　 （出力は必ず最長辺が 1.0 に正規化される。GLB 4件で実測）
　　　 → 当初「台座の高さを1として」と指示していたが、基準そのものが誤りだった
　　同じ絵を4回入れたときのばらつきは 関節間の合計で ±0.7 %

② 関節を見つける
　　★ 指定した純マゼンタは、そのままの色では出てこない（最大 86／チャネルずれる）
　　　 公称色に固定しきい値 → 2メッシュとも検出失敗
　　　 しきい値を手で広げる → 必要な値がメッシュごとに違い、関節位置が最大 12.8 mm ずれる
　　　 → 基準色をメッシュごとに推定して、初めて誤差 1 mm 以内

③ リンクに切り分ける
　　★ 腕が寝ると、関節がほぼ同じ高さに並んで原理的に切れない
　　　 → 検知して止まる。誤った形のまま先へ進まない

④ 寸法を測る
　　★ 関節の球がリンクの長さに混入し、総リーチが 14 % 過大になっていた
　　　 → 測った値が本当にその形で実現するかを、別経路で毎回検算している
```

> **頑健性は、外部サービスの揺らぎを「どこで吸収するか」という設計で決まる。**

## ⚠️ **「①で棄却されるのは何か」を誤解させない書き方**

**✕「その形のまま届く範囲を求める」** → **「では全部棄却されるのでは」と読まれる。**
**✅「目一杯伸ばしても届かないなら棄却する」** → **どんな関節角度でも無理、と伝わる。**

実際に棄却されたのは 5 枚中 1 枚だけ。

| | 水平到達限界 | 目標 0.8 m |
|---|---|---|
| A1 / A2 / B2 | 1.006 / 1.181 / 1.226 m | ✅ 棄却しない |
| **B1** | **0.680 m** | ❌ **棄却** |

## 「仕様の遵守率」とは（2026-09-11 定義）

**プロンプトが要求している仕様を、生成結果がどれだけ満たしたかの割合。**
**版ごと・項目ごとに出す。**

| 項目 | 何を見るか | 合否の基準 |
|---|---|---|
| **向き** | 腕が立っているか | **関節の Z 座標の広がり ≥ 0.25**（`check_glb_pose.py` が既に持つ基準） |
| **マーカー数** | マゼンタの球の個数 | **ちょうど 3 個** |
| **禁止物** | 寸法線・文字・複数の視点 | **無いこと** |
| **比の保存** | 指示した比が保たれたか | ⚠️ **XML まで通して測る**（画像から測らない。遠近で歪む。9-22③） |

**n 回生成して、各項目について「満たした回数 ÷ n」。**

⚠️ **1 つの数にまとめない。** まとめると**どの制約が守られなかったかが分からなくなる**。
版を進める目的は「どの制約を足せば何が直るか」を示すことなので、**項目別でなければ意味がない**。

**版 D（現行）で実際に測れている分**（9-68、Web UI・n=4）:

| 項目 | 遵守率 |
|---|---|
| 向き | **3 / 4**（1 本が鉛直から 42.5°） |
| マーカー数 | 4 / 4 |
| 禁止物 | 未確認 |
| 比の保存 | **未確認**（XML まで通していない） |

⚠️ **これは Web UI での値**なので、**温度の影響とプロンプトの曖昧さを切り分けられない**。
**API 化して seed と温度を固定してから測り直す**（研究方針）。

## 関節軸はどう決めているか（2026-09-11 整理）

**⭐ メッシュから測っていない。規則で割り当てている。**

| モード | 根元の関節 | それ以降 |
|---|---|---|
| 平面 | Z 軸 | **全部 Z 軸**（水平面内で回る） |
| **縦型（本線）** | **Z 軸（ヨー、±180°）** | **Y 軸（ピッチ、±90°）** |

**「固定根本アームならこう」という決め打ち**である。
生成メッシュの形から軸を推定する処理は**入っていない**。

⚠️ **Bug 29 がここだった。** 修正前は軸を Z に決め打ちし、ボーンを +X に固定していたため、
**縦型のスケッチを入れても必ず水平アームになっていた。**
いまは縦型モードで「根元ヨー + 以降ピッチ」に割り当てている。

**なぜ測らないのか**: 研究方針に 3 段階の計画がある。

| 段 | 方法 | 状態 |
|---|---|---|
| **1** | **タスク別のデフォルト軸**（固定根本アーム → 上表） | ✅ **現在ここ** |
| 2 | 主成分平面の法線から自動推定 | ⏳ 未実装 |
| 3 | 軸そのものを最適化対象に入れる（±30° 程度） | ⏳ 未実装 |

⚠️ **3 は原論文のコードに実装があるが、原論文でも未検証**である。
**単独では使わず、良い初期値（段 1・2）と組み合わせること**と方針に明記してある。

⚠️ **この決め打ちが第1層の判定にも効く。** 「関節軸に平行なリンクは水平到達に数えない」
という補正（Bug 24）は、**軸が分かっているから書ける**。測って推定していたら、
**推定を誤ったときに判定も静かに誤る**。**M1 の「推定しない」と同じ考え方。**
