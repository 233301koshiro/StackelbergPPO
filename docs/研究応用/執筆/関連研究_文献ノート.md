## 2. グループ別の要約

### 2.1 形態と制御の共同設計（co-design）

**[1] Stackelberg PPO** — Dai, Wang, Ashley, Schmidhuber, ICLR 2026
照合: 本文（arXiv HTML v1、10-19）

| 項目 | 内容 |
|---|---|
| 問題 | 従来の手法は、形態を更新するとき制御を固定とみなす。そのため形態の更新が制御の適応とかみ合わず、学習が不安定で非効率になる |
| 方法 | 形態を Leader、制御を Follower とする Stackelberg ゲームの変種として扱う。Leader が T 回の編集で形態を作り、その後 Follower が制御する（phase-separated） |
| Leader の勾配 | 直接の項と、Follower の最適応答を通る間接の項の和 |
| 間接の項の求め方 | 陰関数微分で求める（交差微分 × Follower のヘッセ行列の逆） |
| 微分できない境目への対処 | 形態と制御の境目（最終形態）は微分できないので、尤度比で期待値として書く（定理 1） |
| ヘッセ行列の扱い | Fisher 情報行列＋λI で近似し、共役勾配法とヘッセ行列・ベクトル積で解く |
| 実験 | MuJoCo（Crawler・Cheetah・Swimmer・Glider・Walker・TerrainCrosser、新設の Stepper-Regular/Hard・Pusher）。seed 7 つ。比較相手は BodyGen・ESS・NGE・Transform2Act |
| 初期形態と、できた形の扱い（10-26 照合、arXiv HTML v1） | 初期形態は環境ごとに決まっている（Crawler は根元＋4 本の枝。Stepper-Regular/Hard と Pusher は Crawler と同じ構成を使う。Cheetah は根元＋1 本で、TerrainCrosser が同じ構成を使う）。できた形は図と文で定性的に示す（図 1: Pusher で「箱を押す腕のような構造と、移動のための脚のような肢」に分化。付録 E.1・E.5「タスクに応じた付属肢の分化」）。⚠️ 同じ初期形態を使うタスクどうしで、収束した形を比べる評価は無い（seed ごとの比較も無い）。近いのは付録 E.7 の Crawler → Pusher の形態の転用だけ |
| 結果 | 最も強い比較手法より平均 +20.66 %、3D の 4 タスク（Crawler・Stepper-Regular・Stepper-Hard・Pusher）では +32.02 % |
| アブレーション | λ ∈ [0.5, 10] で頑健（λ = 0 と ∞ で劣化）。Fisher 近似は解析的なヘッセ行列より高い（6000 対 2500。論文は「ほぼ 2 倍」と書くが、比は 2.4） |
| 限界（著者） | sim-to-real |
| 輪講で突っ込める点 | λ と Fisher のアブレーションは Stepper-Regular の 1 タスクだけ。図 3 のキャプションは網掛けを「7 seed の標準誤差」、6 節の本文は「標準偏差」と書いていて食い違う |
| 本研究での使い方 | 良い形を作る道具ではなく、形の良し悪しを判定する道具として転用する（修論 2.3） |

**[2] BodyGen** — Lu et al., ICLR 2025
照合: 本文（arXiv HTML、10-19）

| 項目 | 内容 |
|---|---|
| 問題意識 | ① GNN の制御器は関節間のメッセージ集約が苦手で、伝播で情報が薄まる（GNN 系一般への指摘）。② Transform2Act は関節ごとの MLP でモデルが 19.64M になり、形態の複雑さに比例して増える。③ 素の PPO による co-design では、環境の報酬を直接受け取るのが制御段階だけで、設計段階の学習が弱い |
| 段階 | 設計段階（トポロジー設計 5 ステップ → 属性設計 1 ステップ）→ 制御段階。設計段階は自己回帰（GPT 風）、制御段階で BERT 風に切り替える |
| MoSAT | 各リムをトークンにし、全リムの間で自己注意を取る |
| TopoPE | 根から各リムまでの経路（整数の列）を、ハッシュマップで埋め込みに対応させる |
| Enhanced-TCA | 段階ごとに価値ネットワークを分ける。制御段階は GAE、設計段階はリターンから価値を引いた優位度 |
| 実験 | MuJoCo の 10 環境（Crawler・TerrainCrosser・Cheetah・Swimmer・Glider-Regular/Medium/Hard・Walker-Regular/Medium/Hard）。seed 4 つ、平均 ± 標準誤差 |
| 結果 | Crawler で 10,381.96（Transform2Act は 4,185.63）。論文は「10 タスクすべてで、最も強い比較手法に対し平均 +60.03 %」と書く |
| アブレーション（Crawler） | MoSAT を外すと 818.92、Enhanced-TCA を外すと 4,994.44、TopoPE を外すと 7,490.83、Traversal PE に替えると 8,582.24 |
| 規模 | 1.43M パラメータ（Transform2Act は 19.64M）。RTX 3090 1 枚と 20 コアで約 30 時間 |
| 輪講で突っ込める点 | 最も強い比較手法は環境ごとに違う。⭐ 10-21 に表 4 から計算した: 環境ごとの比の平均で +79.0 %（合計の比 +74.3 %・中央値 +68.2 %）で、**どの定義でも 60.03 % ちょうどにならない**（どれも 60 % より大きい）。詳細と他の突っ込みどころは [輪講_BodyGen_素材.md](輪講_BodyGen_素材.md) |
| 本研究での使い方 | Stackelberg PPO の土台。このリポジトリはトポロジーを固定している（`fix_skeleton=true`）ので、使っているのは属性設計と制御の段だけ |

**[3] Transform2Act** — Yuan et al., ICLR 2022（Oral）
照合: 要旨（arXiv）
- 1 つの条件付き方策が、形態と行動の両方を決める。
- 各話の前半で変換行動（骨格の構造と、関節の長さ・大きさ・強さなどの属性を変える）を取り、後半で変えた体を制御する。
- 方策はグラフ型で、関節ごとにノードを持つ。関節数の違う形態を 1 つの方策で扱える。
- 形態どうしで経験を共有でき、サンプル効率が上がる。

**[4] Neural Graph Evolution（NGE）** — Wang et al., ICLR 2019
照合: 本文（arXiv PDF）
- 形態の設計を、グラフ空間での進化的な探索（単純な変異の繰り返し）として解く。
- 制御器を GNN で表し、親から子へ重みを受け継ぐ（グラフが違っても共有できる）。これで新しい候補を評価するコストを下げる。
- 探索と活用の釣り合いを取る変異として、GM-UC（不確かさつきのグラフ変異）を入れている。

**[5] Evolving Virtual Creatures** — Sims, SIGGRAPH 1994
照合: 要旨と冒頭（著者 PDF）
- 物理シミュレーションの中で動く仮想生物の、形態と神経系（筋力の制御）を遺伝的アルゴリズムで同時に生成する。
- 適応度の関数を変えて、泳ぐ・歩く・跳ぶ・追いかける行動へ進化させた。
- 形態と神経回路を、ノードと接続からなる有向グラフの「遺伝言語」で表す。

**[6] Reinforcement Learning for Improving Agent Design** — Ha, Artificial Life 2019
照合: 要旨（OpenAlex）とプロジェクトページ（designrl.github.io）
- Gym の環境の一部をパラメータにし、エージェントが方策と一緒に変えられるようにした。
- 環境は RoboschoolAnt と BipedalWalker（通常版・Hardcore 版）。
- 変える量は脚の各部の長さと太さ（Ant は 36 個、元の値から ±75 %）。部品の数や接続は変えない。
- 最適化は REINFORCE を集団で回す方法（NES・OpenAI-ES に近い）。PPO ではない。
- 結果
  - 体を学習すると、点数も上がり、方策の学習も楽になった。
  - BipedalWalkerHardcore では、解けるまでの世代が約 1400 に縮んだ（元の体は約 4600）。

**[7] Jointly Learning to Construct and Control Agents** — Schaff et al., ICRA 2019
照合: 本文（arXiv PDF v3）、書誌は Crossref
- 方法
  - 形態の分布 p_φ(ω) を持つ。方策 π_θ(a|s, ω) は形態のパラメータを入力に受け、分布から引いた複数の形態で学習する（PPO）。
  - 分布はスコア関数推定（∇ log p_φ(ω) × リターン）で、良い形態の方へ動かす（式 3）。
- 設定
  - 形態は既定の構造（同じリンク数と関節）のまま、各リンクの長さと半径だけを変える（Hopper と Walker は 8 個、Ant は 25 個）。
  - 平らな地面と坂道で、Roboschool の Hopper・Walker・Ant を歩かせる。

**[8] Proximal Policy Optimization（PPO）** — Schulman et al., 2017
照合: 要旨（arXiv）。クリップの記述は要旨に無く、本文の定義（L^CLIP）は今回は開いていない
- 環境とのやり取りでデータを集め、代理目的を確率的勾配で最適化する方策勾配法の族。
- 同じデータで、ミニバッチの更新を何エポックも回せる。
- TRPO の利点を保ちつつ、実装が簡単で汎用的。ロボットの歩行と Atari で、他のオンライン方策勾配法より良い。

### 2.2 スケッチ入力・三次元形状からの構造推定

**[9] RobotSketch** — Lee, Oh, Yoon, Lee, Jin, Hwangbo, Bae, SIGGRAPH 2024 Emerging Technologies（2 ページ）
照合: 本文（KAIST の PDF）
- 入力
  - デザイナーは VR の中で、液晶タブレットにペンとマルチタッチで 3D スケッチを描き、ロボットの形と運動学的な構造を表す。
  - 必要な物理特性やメタデータは、スケッチに注記として書き込む。
- 学習と確認
  - 描いたロボットの制御（GRU-MLP）を、RaiSim の中で PPO で歩けるように学習させる。
  - 学習後は VR コントローラで実時間に動かせる。
- デモでは 2・3・4・6 脚のロボットを歩かせた。
- 修論の差分（関節の配置など物理的な整合性はデザイナー任せ、評価は歩行の 1 タスク）は、この記述と矛盾しない。

**[10] Teddy** — Igarashi, Matsuoka, Tanaka, SIGGRAPH 1999
照合: 要旨（著者 PDF）
- 画面に描いた 2D の自由曲線から、もっともらしい 3D のポリゴン曲面を自動で作る。
- 輪郭で囲まれた領域を、広い所は太く、狭い所は細く膨らませる。
- 初めて使う人でも 10 分ほどで操作を覚え、数分で模型を作れた（非公式なユーザー調査）。

**[11] Free2CAD** — Li, Pan, Bousseau, Mitra, ACM TOG 41(4) / SIGGRAPH 2022
照合: 要旨（OpenAlex）
- 最終形状をスケッチするだけで、ペンの線を簡略化した CAD 言語のコマンド列に変換する。実行すると描いた物体が再現される。
- 線のどれが同じ CAD 操作に属するかのグループ分けを新しいタスクとして立て、Transformer で列から列へ翻訳する。
- 合成データで学習したが、実物の CAD モデルのスケッチや初心者のスケッチにも汎化した。

**[12] Sketch-based modeling: A survey** — Olsen et al., Computers & Graphics 33(1), 2009
照合: 書誌のみ（要旨は出版社が非公開）
- スケッチベースモデリングのサーベイ（題名どおり）。中身の細部は確かめていない。

**[13] Deep Sketch-Based 3D Modeling: A Survey** — Tono et al., arXiv 2026（cs.GR）
照合: 要旨（arXiv）
- 深層学習によるスケッチベース 3D モデリング（DS-3DM）のサーベイ。
- Input-Model-Output の枠組みで、設計空間 MORPHEUS を提案している。分類の軸は次のとおり。
  - 人の入力の量と種類
  - モデル
  - 3D の出力（表現・部品・選択肢）
  - 評価の仕方

**[14] URDF-Anything** — Li et al., NeurIPS 2025
照合: 本文（arXiv PDF、10-19 再調査）
- 点群とテキストを入力にする 3D マルチモーダル LLM で、部品の分割と関節（運動学）のパラメータを自己回帰でまとめて予測する。
- [SEG] トークンを点群の特徴と結びつけて、部品単位の分割をする。
- 比較手法より、分割の mIoU が 17 % 高く、運動学パラメータの誤差が平均 29 % 小さく、物理的に実行できる割合が 50 % 上回る。
- 入力は単視点か多視点の画像で、点群にしてから使う。
- 評価は PartNet-Mobility（扉・引き出し・はさみなど）。学習と評価に使ったのは、**可動部品が 8 未満の物体だけ**。分布外の物体でも分割の mIoU は 0.62（最良の比較手法は 0.51）。
- 著者が挙げる限界
  - 質量や慣性モーメントは生成できない。
  - 部品の形状は外部の点群→メッシュ変換に頼っていて、完全な end-to-end ではない。
  - **数値パラメータの精度が、トークンで生成する方式のせいで限られる。**
- ⚠️ ロボットのように関節が多く密な対象は評価していない。修論第1章の「ロボット特有の複雑かつ密集した関節構造に対する推定精度には未だ限界がある」は、論文が示したことではない（§3.3）。
- ⛔ 2026-10-21: 第1章を直した後も、**表 2.1 の「密な関節構造で推定誤差が残存」と 2.2 本文の第一の限界（「密集した対象では誤りが有限の確率で残存する」）に同じ言い過ぎが残っていた**（ユーザー指摘「そもそもロボットに対して行っていない。もちろんタスク検証も」）。arXiv HTML v1 の 4 節で確かめ直した: 評価は PartNet-Mobility（分布内 5 類: Laptop・Box・Refrigerator・StorageFurniture・Table、分布外 41 類）、物理的な実行可能性は「シミュレータで関節を動かし、部品が飛ぶ・固まるなどの非物理的な挙動が出ないか」、ロボットの復元とタスクでの評価は無い。2.2・表 2.1 を対象と評価の範囲で書き直した。下の ✅「推定誤差が残ること」は、著者が述べる数値精度の限界の意味に限る

### 2.3 作業空間解析・タスク駆動設計

**[15] Capturing robot workspace structure** — Zacharias, Borst, Hirzinger, IROS 2007
照合: 要旨（OpenAlex）、書誌は Crossref（pp. 3229–3236。別のデータベースに 4490–4495 とする記載があるが、Crossref に従う）
- 腕の能力は、作業空間の領域ごとに「どの向きから届くか」という方向の構造として現れる。それを可視化して地図にしたもの（capability map）を提案した。
- この地図から、届きやすい場所を割り出せる。物を器用に扱える場所へ運ぶ、移動マニピュレータが自分の位置を選ぶ、といった使い方を示した。

**[16] Manipulability of Robotic Mechanisms** — Yoshikawa, IJRR 4(2), 1985
照合: 要旨（OpenAlex）
- 手先の位置と姿勢を決める能力の尺度として、可操作性を提案した。
- その性質を導き、いろいろなマニピュレータの最良の姿勢を示した。4 自由度の指も、この尺度から検討した。
- 可操作性楕円体（関節速度の大きさ 1 で出せる手先速度の集合）の体積が尺度になる、という定義は要旨には無い。著者の別の解説から確認した。

**[17] Task-based limb optimization for legged robots** — Ha, Coros, Alspach, Kim, Yamane, IROS 2016
照合: 本文（Disney Research の PDF、10-19 再調査）
- 脚ロボットの動きと脚の形を、性能の尺度が最適になるよう共同で設計する。
- 2 段で解く。まず重心と足だけの簡略モデルで軌道を計画し、次に全身の動きを解きながら各リンクの長さを最適化する。
- タスクは跳ぶ・歩く・段差を上る。費用（タスク中の関節トルクの二乗和）は、設計パラメータで大きく変わった。
- 結果は予備的で、単純化の仮定が多いと著者自身が書いている。
- ⛔⛔ **本文にはタスクをまたいだ比較がある（表 III）。**
  - やったこと: 歩行・バウンド・階段の各タスクで最適化した四脚の設計（＋犬に似せた基準設計）を、ほかのタスクにも当てはめた。リンク長の比だけを移し、残りは各タスクで最適化し直している。
  - 結果: どの設計も自分が最適化されたタスクで最良で、他の設計より 10〜20 % 良い。バウンド用の 2 リンク脚は、歩行と階段では最適設計の 2 倍以上のトルクを要した。
  - **つまり、設計の順位がタスクによって入れ替わることを示している。**修論 2.4 の「順位がタスク間で入れ替わることの検証も扱われていない」は、この論文については誤り（§3.3）。
  - 本研究との違いとして残るもの
    - 比べた設計は各タスクの最適化の出力で、最適性の確認として使っている。与えられた形態集合を判定する用途ではない。
    - 動力学は簡略化（重心と足先から作った軌道）で、制御の学習は無い。費用は関節トルクの二乗和。
    - 不調のときに原因を設計者へ返す機能は無い。

**[18] Task-Aware Morphology Optimization of Planar Manipulators via RL** — Mishra & Chakrabarty, arXiv 2025
照合: 本文（arXiv PDF、10-19 再調査）
- 平面アームの形態を強化学習（SAC・DDPG・PPO）で最適化し、グリッド探索やブラックボックス最適化と比べた。
- **目的は Yoshikawa の可操作性（[16]）。**
- 円の軌道で検証した。解析解（2 本のリンクが等長で、第 2 関節が直交）に全手法が届いた。
- 楕円と長方形の軌道では、行動を形態ベクトル（L1, L2, θ2）全体に広げた。強化学習は安定して収束し、他の手法は評価回数がずっと多く要った。
- ⭐ **強化学習は 1 ステップの文脈つきバンディットとして使っている。**状態は経路、行動は形態（L1, L2, θ2）で、すぐに報酬が返る。制御方策の学習も動力学も無く、運動学だけの研究だと著者自身が書いている（トルク・速度・衝突は対象外）。
- タスク間で形態の順位を比べる評価は無い。不調の原因を返す機能も無い（修論の差分どおり）。
- IFAC World Congress 2026 に付随する論文として投稿中（採録ではない）。

### 2.4 説明可能性・反実仮想説明

**[19] Counterfactual Explanations Without Opening the Black Box** — Wachter, Mittelstadt, Russell, Harvard JOLT 31(2), 2018
照合: 本文（arXiv PDF、10-19 再調査）
- GDPR の「説明を受ける権利」の議論に対し、ブラックボックスを開く説明ではなく反実仮想説明を提案した。
- 反実仮想説明とは、望む結果を得るために世界をどれだけ小さく変えればよいかを示すもの。
- 狙いは 3 つ。決定の理由を理解できる、争う根拠になる、将来良い結果を得るには何を変えればよいかが分かる。
- ⛔ **「最も近い可能世界」（望む結果を得る最小の変更）は議論の鍵となる概念だが、最小の変更がいつも最も役に立つとは限らない、とはっきり書いている。**近い反実仮想をいくつか示す方が役に立つことが多く、どれが関係するかは変数を変えられるか、変化が現実に起こりうるかにもよる、とする。修論 2.4 の「最も有用なのは判定を覆すのに必要な最小の変更であると指摘した」は、この論文の主張と食い違う（§3.3）。

**[20] Actionable Recourse in Linear Classification** — Ustun, Spangher, Liu, FAT* 2019
照合: 本文（arXiv PDF、10-19 再調査）
- 自動判定を受けた人が、実際に変えられる入力（収入など）を変えて結果を覆せることを recourse と定義した。
- **線形分類器**について、recourse があるかを整数計画で確かめ、保証する道具を示した。変えられない特徴（年齢など）と、一方向にしか変わらない特徴は制約で除く。
- 信用スコアの実験で、普通のモデル開発の慣行が recourse に大きく影響することを示した。

**[21] Explainable generative design in manufacturing for RL based factory layout planning** — Klar et al., JMS 72, 2024
照合: 要旨（OpenAlex）
- 強化学習で工場のレイアウトを生成する手法に、計画者が結果を信頼し理解するための説明手法を付けた。
- 中身は、方策の要約、摂動、状態価値の評価、そして特徴量の単位で状態価値と行動の関係を見る分析。
- 強化学習が問題の性質を学んだのか、偶然の振る舞いなのかを見分けられる。43 の機能単位からなる産業事例で確かめた。
