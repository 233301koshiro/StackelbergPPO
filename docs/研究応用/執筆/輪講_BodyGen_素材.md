## 0. 一言でいうと

**ロボットの「形」と「動かし方」を、1 つの Transformer で同時に学習する方法。**
既存の方法（Transform2Act）に比べて、①関節どうしの情報のやり取りを速くし、②形の変化に強い位置の符号化を入れ、③形を決める段にも報酬が届くように学習信号の配り方を変えた。モデルは 1.43M パラメータで、Transform2Act（19.64M）の約 1/14。

## 2. ⭐ 検算: 「平均 +60.03 %」は表 4 から再現しない（2026-10-21）

本文（p.8）の定義は「10 タスクすべてで、**最も強い比較手法**に対する平均の改善」。表 4（p.19）の平均値から素直に計算すると次のとおり。比較手法は Transform2Act・NGE・UMC-Message の 3 つ（自分のアブレーションは除く）。

| 環境 | BodyGen | 最も強い比較手法 | 改善 |
|---|---|---|---|
| Crawler | 10,381.96 | UMC-Message 6,492.90 | +59.9 % |
| TerrainCrosser | 5,056.01 | Transform2Act 2,393.84 | +111.2 % |
| Cheetah | 11,611.52 | Transform2Act 8,405.70 | +38.1 % |
| Swimmer | 1,305.17 | UMC-Message 961.20 | +35.8 % |
| Glider-Regular | 11,082.29 | UMC-Message 7,354.34 | +50.7 % |
| Glider-Medium | 11,996.82 | Transform2Act 5,573.44 | +115.2 % |
| Glider-Hard | 10,798.06 | Transform2Act 6,120.37 | +76.4 % |
| Walker-Regular | 12,062.49 | Transform2Act 8,685.47 | +38.9 % |
| Walker-Medium | 12,962.08 | Transform2Act 6,287.15 | +106.2 % |
| Walker-Hard | 11,982.07 | Transform2Act 4,645.31 | +157.9 % |

| 計算の仕方 | 結果 |
|---|---|
| 環境ごとの比の平均（本文の定義に最も近い） | **+79.0 %** |
| 合計どうしの比 | +74.3 % |
| 比の幾何平均 | +74.9 % |
| 比の中央値 | +68.2 % |
| 元の 4 環境（Transform2Act の論文にある Crawler〜Swimmer）だけの平均 | +61.3 % |

**どの定義でも 60.03 % ちょうどにはならない。**ただし、どれも 60 % より**大きい**ので、論文の主張が誇張されている向きではない。表 4 は最終性能で、60.03 % は学習曲線の別の時点から出した可能性がある（本文に書いていないので確かめられない）。
→ 輪講では「見出しの数字の出し方は本文から追えなかったが、どう計算しても 60 % 以上はある」と言えば十分。

| 2 | **誤差の種類が表によって違う** | p.9 表 1 と図 6 は「標準誤差」、p.19 の表 4 の本文は「標準偏差」 | 同じ数字（例: Crawler ±353.97）が両方に出てくるので、どちらかが書き間違い。seed 4 つなら標準偏差は標準誤差の 2 倍 |

## 4. 自分の研究（このリポジトリ）とのつながり

| BodyGen の部品 | このリポジトリでの場所 | 使い方 |
|---|---|---|
| MoSAT（自己注意の方策・価値） | `design_opt/models/bodygen_policy.py`・`bodygen_critic.py`・`transformer.py` | そのまま使う |
| トポロジー設計の段（5 step） | — | **使っていない。**トポロジーは手描きのスケッチで決まるので固定する（`fix_skeleton=true`） |
| 属性設計の段 | 同上 | リンク長・太さ・ギア比の設計変数を出す |
| Enhanced-TCA（式 4.9） | `design_opt/agents/genesis_agent.py` の `estimate_advantages`（326 行: 設計段のリターンは割引なしの和、328 行: それから価値を引く） | 式どおり。⚠️ さらに段ごとのリターンの正規化と優位度の正規化（331〜341 行）が入っているが、**論文の式には無い**（BodyGen の公開コード由来か、Stackelberg PPO が足したものかは未確認） |
| 段ごとに別の価値ネットワーク | `design_opt/models/bodygen_critic.py` の `BodyGenValue` | 論文どおり。外からは 1 つの `value_net` だが、中に段ごとの Transformer と出力層が 3 組ある（`skel_transformer`／`attr_transformer`／`control_transformer`、`*_value_head`）。各状態はその段の組だけを通る |

Stackelberg PPO（前回の輪講）は、この上に「設計がリーダー、制御がフォロワー」の順序を入れて、設計段の勾配に制御の応答を反映させた（`genesis_agent.py` の leader / follower の分割、489〜493 行）。**BodyGen の TCA は「設計段に報酬を届ける」、Stackelberg PPO は「届いた報酬で設計を動かすとき、制御がどう追従するかまで見る」**、という 2 段の改良として説明できる。
