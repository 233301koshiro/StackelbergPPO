# 作業環境とスマホからの接続（Remote Control）

**この文書の用途**: スマホから、**VSCode で動いているのと同じセッション**を触るための手順。
あわせて、**この環境で何が消えて何が残るか**をまとめる。

> **なぜ「同じセッション」にこだわるか**
> 別々のセッションで同じリポジトリを触ると、**片方が知らないうちに結論が書き換わる**。
> 実際に 2026-09-03 に踏んだ（別セッションが 4 時間前に訂正していた読みを、
> それを知らないまま古いまま話した）。対策として CLAUDE.md §2 に「手順0: 他セッションの
> 差分を確認する」を足したが、**そもそもセッションが 1 本なら起きない**。
> Remote Control はセッションを 1 本のままスマホから操作する仕組みなので、
> この問題自体が消える。

調査日 2026-09-04 / Claude Code 2.1.250 で確認した。

---

## 1. まず知っておくこと — 消えるものと残るもの

コンテナの中を調べた結果:

| 場所 | 実体 | コンテナを作り直すと |
|---|---|---|
| `/userdir` | ホストの `/home/irsl/irsl_docker_irsl_system/userdir` を**マウント** | ✅ **残る** |
| `/userdir/StackelbergPPO` | 上に含まれる。さらに GitHub にも push 済み | ✅ **残る（二重に安全）** |
| `.claude/settings.json`（リポジトリ内） | 権限モードと deny ルール。**git 管理下** | ✅ **残る** |
| **`/root/.claude`** | **マウントされていない**（130 MB） | ❌ **全部消える** |

`/root/.claude` に入っているもの:

- **会話履歴**（`projects/*.jsonl`）
- **memory**（Claude が覚えている好み・作業方針。現在 10 件）
- **個人設定**（`settings.json`。モデル・プラグインなど）

> ✅ **権限の設定は消えない。** `permissions.defaultMode: auto` と
> `single_run/` 削除などを止める deny ルール 8 件は、`/root/.claude` ではなく
> **リポジトリの [`.claude/settings.json`](../../.claude/settings.json) にあり、git 管理下**である。
> つまり**ホストマウントの上にあり、GitHub にも入っている**ので、コンテナを作り直しても残る。

> ⚠️ **一度これに気づいた形跡がある。** ホスト側に `/userdir/.claude_backup`（128 MB）が
> 置いてあるが、**最終更新が 2026-07-07 で 2 か月止まっている**。
> 当時 memory は 3 件、現在は 10 件なので、**いま消えたら 7 件失われる**。

### ただし「研究の中身」は既に安全である

CLAUDE.md §4-2 の記録ルール（知見は必ず `docs/` へ、4層 SSOT）は、
**Claude の記憶ではなく git に知識を置く**設計になっている。
だからセッションをまたいでも話が通じている。

**消えて困るのは memory と settings.json だけで、どちらも小さく作り直せる。**
つまりこれは「今すぐ止めるべき危険」ではなく「直しておくと楽」の類である。

## 2. Remote Control はこの環境で使えるか → **使える**

`claude doctor` の出力:

```
Remote Control
Control this session from claude.ai/code or the Claude mobile app
```

これは**使える状態のときの表示**である。使えない場合は、ここに理由（`disabledReason`）と
失敗した項目が並ぶ実装になっている。**どちらも出ていない。**

### 「コンテナだと入れない」という話について

**条件つきで正しい。ただしこのコンテナは条件に当たらない。**
実際に拒否される条件は次の4つで、いずれも「コンテナかどうか」ではない。

| 拒否される条件 | このコンテナ | 備考 |
|---|---|---|
| **cloud session の中**（`claude --cloud`） | ✅ 該当しない | コンテナは "local device" 扱い |
| **長命トークンでの認証** — `claude setup-token` / `CLAUDE_CODE_OAUTH_TOKEN` | ✅ 該当しない | **これが誤解の元**。下記 |
| `ANTHROPIC_API_KEY` 等が設定されている | ✅ 全部未設定 | |
| enterprise cloud gateway 経由のログイン | ✅ 該当しない | |

> Remote Control requires a full-scope login token. Long-lived tokens (from
> `claude setup-token` or `CLAUDE_CODE_OAUTH_TOKEN`) are limited to inference-only
> for security reasons. Run `claude auth login` to use Remote Control.

**2番目が誤解の出どころだと思われる。** コンテナは普通、環境変数でトークンや API キーを
渡して認証するので、「コンテナ＝Remote Control 不可」は**大半のコンテナでは実際に正しい**。

**このコンテナは違う。** 中で `claude auth login` した本物の認証情報を持っている:

```
/root/.claude/.credentials.json
  scopes: [..., "user:sessions:claude_code"]   ← セッション操作の権限がある
  subscriptionType: "pro"
```

外向き通信も通っている（`api.anthropic.com` へ到達可）。
Remote Control は **Anthropic のサーバ経由の外向き接続**なので、NAT の内側でも問題ない。

## 3. 手順

> ⚠️ **2 つを混ぜないこと。** 初版はマウントを ① に書いたため、
> 「マウントしてからでないと繋げない」と読めた。**そうではない。**
>
> | やりたいこと | コンテナ再作成 | 走っている学習 |
> |---|---|---|
> | **スマホから繋ぐ** | **要らない** | **止まらない** |
> | 履歴と memory を永続化する | **要る** | **止まる**（checkpoint から再開はする） |
>
> **繋ぐだけなら今すぐできる。** 永続化は別件で、後回しにしてよい。

### A. スマホから繋ぐ（再起動不要・いつでもできる）

**① 動いているセッションをそのまま公開する場合**（会話の文脈を残したいとき）

セッションの中で次を打つだけ。**再起動も新規起動も要らない。**

```
/remote-control
```

VSCode 拡張のセッションでも使える（拡張バイナリに `/remote-control` があることを確認済み）。

> 💡 **VSCode のセッションは意外と丈夫。** `vscode-server` はコンテナ内で動き続けるので、
> **ノート PC を閉じてもセッションは死なない**（実測で server 35 日・拡張ホスト 11 日連続稼働）。
> 死ぬのは**コンテナを止めたとき**である。

**② 新しく起動する場合**（長期間スマホ主体で使うとき）

端末から。tmux の中で起動しておくと、ターミナルが切れても残る。

```bash
tmux new -s claude
claude --remote-control StackelbergPPO
```

`Ctrl-b d` で抜ける。戻るのは `tmux attach -t claude`。

**③ スマホ／ブラウザから繋ぐ**

- スマホ: **Claude モバイルアプリ**
- PC: **claude.ai/code**

ヘルプの本文:

> Run this command in the directory you want to work in, then connect from
> your phone or a browser.

### B. 履歴と memory を永続化する（コンテナ再作成が要る）

**⚠️ 学習が走っているときはやらない。** コンテナを作り直すと学習プロセスも死ぬ。
（Bug 35 の修正後はキューを入れ直せば checkpoint から再開するので**致命傷ではない**が、
最後の checkpoint 以降のエポックは捨てになる。**キューが空いたときにやるのが素直**。）

```bash
# ホスト側で。まず今の中身を退避
docker cp <コンテナ名>:/root/.claude /home/irsl/irsl_docker_irsl_system/claude_home
```

**対策は既にリポジトリにある。ただし発動していない。**

`.devcontainer/devcontainer.json`（**経路B**）は名前付きボリュームで保持する設定を持つ:

```json
"source=stackelbergppo-claude-home,target=/root/.claude,type=volume"
```

⚠️ **しかし、いまの運用は経路A**（compose で起動 → VS Code の Attach to Running Container）で、
**この方式では `devcontainer.json` が読まれない**。だから効いていない。
経緯は [../../docker/README.md](../../docker/README.md) と
[../../.devcontainer/README.md](../../.devcontainer/README.md)。

**経路B へ移るとコンテナを作り直すことになり、学習が止まる。**
当面は**作り直す前に手で退避する**運用でよい:

```bash
docker cp akita_sp_ppo:/root/.claude /home/irsl/irsl_docker_irsl_system/claude_home
```

## 4. 注意

1. **セッションが死ぬと終わり。** コンテナ停止・VSCode 切断で消える。②の tmux は必須に近い。
2. **`/root/.claude` を逃がしていないなら、コンテナ再作成で全部消える。** ①を先にやる。
3. **クラウドセッション（`claude --cloud`）は代わりにならない。**
   クラウド側には Choreonoid も GPU も `single_run/` も無いので、
   **この repo では docs の編集しかできない**。実験を触るなら Remote Control 一択。
4. **スマホから重い操作をしない。** 学習の起動・停止は
   [引き継ぎ_再起動後.md](../研究応用/引き継ぎ_再起動後.md) の手順（PID を特定してから kill）を
   踏む必要がある。**`pkill -f` は自分ごと落とす**（Bug 19）。画面の小さい端末で焦ってやることではない。
5. **スマホで docs を編集したら、いつもどおり CLAUDE.md §4-2 の反映先を守る。**
   端末が変わっても 4 層 SSOT の規律は変わらない。
6. **コンテナを止めると、学習もキューも止まる。** Remote Control のセッションだけでなく
   **走っている実験ごと落ちる**。復帰手順は
   [引き継ぎ_再起動後.md](../研究応用/引き継ぎ_再起動後.md) の
   「⚠️ コンテナを止めると、学習もキューも止まる」を見ること。
   キューを入れ直せば **checkpoint から自動で再開する**（2026-09-04 以降。Bug 35）。

## 5. コンテナを作り直すときの引き継ぎ

`/root/.claude` をマウントしていない状態で作り直す場合、**先に退避する**。

```bash
# コンテナ内で（ホストマウントの上へコピー）
cp -a /root/.claude /userdir/.claude_backup_$(date +%Y%m%d)
```

作り直したあと:

```bash
cp -a /userdir/.claude_backup_<日付>/. /root/.claude/
claude auth login          # 認証だけは入れ直しになることがある
claude doctor              # Remote Control の行が出るか確認
```

**復旧できたか確認すること:**

| 確認するもの | コマンド |
|---|---|
| memory が戻ったか（10 件前後） | `ls /root/.claude/projects/-userdir-StackelbergPPO/memory/` |
| 会話履歴が戻ったか | `ls /root/.claude/projects/-userdir-StackelbergPPO/*.jsonl` |
| Remote Control が使えるか | `claude doctor` の "Remote Control" の行 |

⚠️ **権限の deny ルールは git にあるので復旧作業は要らない**が、
**リポジトリを clone し直した場合は `.claude/settings.json` が入っているか確認する**。
これは「復元できないもの」を止めている（`single_run/` は層①の原本、
`data/test/` は E2E の一次証拠）。飛んだまま作業すると事故が起きる。

## 用語ミニ辞典

| 言葉 | 意味 |
|---|---|
| **マウント** | ホストのフォルダをコンテナの中から見えるようにすること。マウントされていない場所はコンテナと一緒に消える |
| **Remote Control** | ローカル（この場合コンテナ）で動いているセッションを、スマホやブラウザから操作する仕組み。**セッションは 1 本のまま** |
| **cloud session** | Anthropic 側のサーバで動くセッション（`claude --cloud`）。この repo の実験環境は無い |
| **長命トークン** | `claude setup-token` などで作る、期限の長い認証トークン。推論だけに制限されていて Remote Control には使えない |
| **tmux** | ターミナルを繋ぎ直せるようにする道具。切断してもプロセスが生き残る |
| **4 層 SSOT** | ①原本（学習ログ）②台帳③派生④状態 の順で「どれが正か」を決めた運用。CLAUDE.md §4-2 |
