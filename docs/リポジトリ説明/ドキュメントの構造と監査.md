# ドキュメントの構造と監査 — 「ここを変えたらどこも変わる」を機械で答える

> **なぜこの md があるか**: 方針や結論を 1 つ変えると、それを引用している md が芋づるで古くなる。
> 手で追うと必ず漏れる。**実測**: 節を 1 つ挿しただけで **7 ファイル 13 箇所**の参照が動き
> （2026-09-13）、機序を 1 つ否定したときは**配布資料 2 件に取り残し**が出た（9-49）。
>
> 本 md は**この repo の実際の腐り方を数えたうえで**、取る手と取らない手を決めたものである。

---

## 1. まず測った — この repo の構造

| | 値 |
|---|---|
| MD 本数（archive 除く） | **51** |
| 内部リンクの総数 | 256（平均 5.0） |
| **リンクを 1 本も張っていないファイル** | **12 本。⭐ 修論の全章がここ** |
| 被参照が最多 | `実験系譜.md`（34） |

**⭐ 結論: この repo は「リンクのグラフ」ではなく「識別子のグラフ」でできている。**
修論の章どうしはリンクを張らず、**`系譜 9-49` / `修論 4.3.2` / `Bug 27` という識別子**で
参照し合う。**だから監査はリンクではなく識別子で行う。**

|---|---|---|---|---|

## 3. ⭐ 採った手 — 3 つだけ

### ① 生成物にする（型 5 に効く。**最も強い**）

**片方が他方から導けるなら、導かせる。** 手で 2 箇所書かない。

| 生成物 | 正 |
|---|---|
| 表示用 `.body` | XML（`make_hockey_court_xml.py`） |
| 修論 付録A.2 のプロンプト | `make_m1_prompt.py` |
| [構成.md](../研究応用/修論ドラフト/構成.md) の見出し一覧 | 各章の本文（`dump_thesis_outline.py`） |

⚠️ **生成物には「自動生成物。手で編集しない」と冒頭に書く。**

### ② 識別子の逆引き（型 3 に効く）

```bash
python3 scripts/doc_refs.py 9-49        # これを変えたら見る場所が全部出る
python3 scripts/doc_refs.py --hubs      # 引用が集中している＝変更の影響が広い識別子
python3 scripts/doc_refs.py --undefined # 定義が無いのに引用されている（壊れ参照）
```

**⭐ 引用が集中している識別子（＝触ると高くつく場所）**

| 識別子 | 引用 |
|---|---|
| 系譜 9-11（助言の閉ループ） | 73 箇所 / 17 ファイル |
| 修論 6.4.2（限界） | 67 箇所 / 18 ファイル |
| 修論 6.5（今後の課題） | 53 箇所 / 15 ファイル |

⚠️ **接頭辞（`系譜 9-6` / `修論 4.3.2`）が付いた引用ほど正確に拾える。**
接頭辞が無いと比率や日付と区別できない。**接頭辞を付けるほど検査が効く**（9-11 の規約）。

### ③ トリガー表を事故のたびに直す（型 4・6 に効く）

CLAUDE.md §4-2 の「トリガー → 反映先」表が**唯一の入口**である。
⚠️ **表に無い反映先は、その場で思い出せない。** 2026-09-13 だけで 3 件漏れ、表に 2 行足した。

## 4. ⛔ 採らなかった手と、その理由

| 案 | なぜ採らないか |
|---|---|
| **md を相互リンクのグラフにする** | ⚠️ **修論の章は 12 本ともリンクを張っていない。**リンクを張らせる運用コストより、**既にある識別子を使う方が安い。**（②で代替） |
| **正しい値を YAML 等の変数に持たせ、md から参照する** | ⚠️ **原本はログである。**変数表を作ると**原本とログの二重管理**になる。`check_docs_consistency.py` が**ログと直接照合**しており、そちらが強い |
| **⛔ 「ここは変わらない」印を付けて検査から外す** | ⚠️ **この repo では「変わらないはず」が 3 回外れた**（`armature`・`solref`・TP の飽和）。**不変の宣言は、まさに事故を生んだ思い込みそのもの。** |
| md を分割して小さくする | 被参照が集中する `実験系譜.md`（34）を割ると、**識別子の逆引きが効かなくなる**。**大きいこと自体は問題ではない**（索引で引く） |

### ⭐ ただし「変わらない印」には**成立する版がある**

**「今後変わらない」ではなく「意図的に過去の記録である」を宣言するのは正しい。**

| 印 | 意味 | 監査 |
|---|---|---|
| **追記のみ** | 実験系譜の過去の段・デバッグ戦記・取り下げの記録 | **現在性を問わない**（歴史だから） |
| 執筆メモ | 各章末の `## 執筆メモ（本文には含めない）` | 本文の検査から外す |

⚠️ **「変わらないから見ない」ではなく「歴史だから現在性を問わない」。** ここを混ぜない。

## 5. 運用（**これだけ覚える**）

```bash
# 何かを変えたら
python3 scripts/doc_refs.py <変えた識別子>      # 見る場所の一覧が出る
python3 scripts/check_docs_consistency.py       # 値 ↔ 原本
python3 scripts/check_stale_claims.py           # 主張の横断
python3 scripts/check_citations.py              # 引用 ↔ 参考文献

# 修論の節を足したら
python3 scripts/dump_thesis_outline.py --write

# 週に 1 回
python3 scripts/check_docs_inventory.py
```

⚠️ **道具は「漏れを 0 にする」ものではない。**
型 1〜3 と 5 は機械で拾えるが、**型 4・6（反映先そのものが分かっていない）は人が表を直すしかない。**
**だから事故のたびに §4-2 の表を直すのが、実は一番効く。**
