# 外部 API の使い方と費用（Tripo3D・Gemini）

> **役割**: キーの置き場・単価・残高・実際の回し方を 1 枚にまとめる。
> ⚠️ **キーそのものは書かない。**`.env`（gitignore 済み）に置く。

---

## Tripo3D（M2: 画像 → 三次元形状）

### 費用と残高

| | |
|---|---|
| 入金 | **10 ドル ＝ 1000 クレジット**（先払い。指導教員が 2026-09-18 に入金） |
| **1 生成** | ⭐ **30 クレジット ≒ 0.30 ドル** |
| 1000 クレジットで | **約 33 回** |
| 残高の確認 | `python3 scripts/tripo_api.py --balance` |

**⭐ 課金されるのは生成だけ。** 次は**すべて無料**である。

| 操作 | 課金 |
|---|---|
| 残高照会 | 無料 |
| パラメータ検証 | 無料 |
| **画像アップロード** | ⭐ **無料**（`image_token` の取得まで） |
| **生成（`image_to_model`）** | ⛔ **30 クレジット** |

⚠️ **アップロードまで無料なので、生成の直前まで課金なしで確認できる。**
**新しい画像を試すときは、まずアップロードだけ通すこと。**

### キーの置き場

```bash
# .env（gitignore 済み。⚠️ リポジトリには絶対に書かない）
TRIPO_API_KEY=tsk_...
```

⚠️ **`git check-ignore -v .env` で追跡されないことを確認済み。**
⚠️ **キーはチャットに貼られた時点で会話ログに残る。**気になるなら管理画面で再発行する。

### 使い方

```bash
python3 scripts/tripo_api.py --balance                       # 残高（無料）
python3 scripts/tripo_api.py --image <画像> --seed 42 --out <出力先>
python3 scripts/tripo_api.py --verify-seed --image <画像>     # 同 seed で 2 回（60 クレジット）
```

### ⭐ 再現性について — **実測した結果**（9-115）

⚠️ **公式は「同じ seed なら同一のモデル」と明記するが、厳密には偽である。**

| 比べる量 | 結果 |
|---|---|
| GLB の sha256 | ⛔ **異なる** |
| 頂点数 | ⛔ **104,959 / 104,963（4 個違う）** |
| 面数・体積 | ✅ 一致 |
| ⭐ **外接箱** | ⭐ **完全一致** |
| ⭐ **主軸・最遠点距離** | ⭐ **完全一致** |

```
Web UI の揺れ（9-39 実測）: ±0.7 %
⭐ API（同 seed）の揺れ    :  0.0000 %
```

**⭐ 後段（M3〜M4）が使う量は完全に一致するので、研究方針 段 2〜4 の
「M2 の揺れをゼロにして残る揺れを M1 に帰属する」は成立する。**
⚠️ **ただし「同一」とは書かない。「後段が使う量が一致する」と書く。**

### ⚠️ 注意

- ⚠️ **1 回の `--verify-seed` で 60 クレジット（2 生成）。** 残高を見てから回す
- `model_version` を指定すると版を固定できるが、**不正な値は `code 1004` で弾かれる**
- 生成は 3〜5 分かかる。`tripo_api.py` が完了まで待つ

## Gemini（M1: スケッチ → マーカー付き画像）

⚠️⚠️ **未着手。キーは未取得**（2026-09-19 時点）。

### ⭐ キーが手に入ったらやること — **1 行足すだけ**

```bash
# .env（受け取り口は用意済み。コメントを外して貼る）
GEMINI_API_KEY=AIza...
```

⭐ **発行ページ**: https://aistudio.google.com/u/2/api-keys
⚠️ **ここはキーを「作る」ページであり、URL 自体はキーではない。**
ページで作成して `AIza...` の文字列をコピーする。

```bash
python3 scripts/gemini_api.py --check    # ⭐ これが通れば準備完了
```

**2 段階認証に指導教員の許可が要るため保留**（ユーザー判断）。
⭐ **骨組みだけ作ってある**: `scripts/gemini_api.py`（9-123）。

### 状態

```
python3 scripts/gemini_api.py --check
⛔ GEMINI_API_KEY が無い。
   ⚠️ 2 段階認証に指導教員の許可が要るため、キーの取得は保留中
```

⚠️ **`google-genai` も未インストール**（`pip install google-genai`）。
⚠️ **単価は不明。** Tripo と違い、疎通の時点で課金の有無を確かめること。

### ⚠️ M1 が要るのは「画像生成」であって「検出」ではない

ユーザー提供のサンプルは `gemini-robotics-er-1.5-preview` で**点を検出して JSON を返す**ものだった。
**M1 は手描きスケッチから整形画像を生成する工程**なので、モデルが違う。
⭐ **入力の渡し方（`types.Part.from_bytes`）だけ流用した。**

### ⭐ 指導教員へ確認すべき 2 点 — **「API が違う」ではない**

⭐ **検出用と生成用で API 自体は同じ**（ライブラリ・クライアント・メソッド・入力の渡し方すべて共通）。
差は **モデル名**と**出力の読み方**（`resp.text` → `inline_data.data`）だけ。

⚠️ **ただし次の 2 点は私に確認できないので、指導教員に聞く必要がある。**

| # | 確認事項 | 理由 |
|---|---|---|
| 1 | ⭐ **同じキーで画像生成モデルを呼べるか** | **権限がモデル単位で制限されていることがある** |
| 2 | ⭐ **画像生成の課金体系** | ⚠️ **検出とは単価が違う可能性が高い。**研究室の予算の話 |

⚠️ **1 が駄目ならキーの再発行、2 は予算の承認が要る。**
⭐ **モデル名は `GEMINI_MODEL` で差し替えられる**ので、指定があってもコードは直さない。

### 許可が下りたらやること

1. `.env` に `GEMINI_API_KEY=...`（⚠️ **リポジトリには書かない**）
2. `--check` で疎通（**課金の有無を先に確認**）
3. `--sketch <手描き> --n 10` で 10 枚
4. `probe_m1_compliance.py` で遵守率（9-84）

⚠️ **Tripo と性質が違う。**公式が **seed の決定性を保証していない**（研究方針 段 2〜4）。
**温度と seed を固定しても出力が変わる**という報告がある。
⭐ **したがって M1 の揺れは原理的に残る。**それを n 回の試行で測るのが 9-84 の設計である。
