# セカンドオピニオン — 別モデルへ貼り付けるプロンプト雛形

> ⭐ **CLAUDE.md §10 から移した**（2026-09-25）。
> **ユーザーが別サービスへ貼り付けるための文面**であって、Claude への指示ではない。
> ⭐ **受け取ったレビューの処理は `/review-in`**（CLAUDE.md §10）。

### A. コードレビュー用プロンプト

```
以下のPythonコードは、Claudeが[機能名]のために実装したものです。

次の3点から厳しくレビューし、問題点と具体的な改善案を出してください:
1. バグ・エッジケース漏れ（入力が空・型が違う・境界値など）
2. セキュリティ上の懸念（パス操作・外部入力の扱い・コマンド注入など）
3. パフォーマンス上のボトルネック

[ここにコードを貼り付け]
```

### B. 研究レビュー用プロンプト

実験設計・結論の妥当性を批評させる。コードより優先度が高い。
実験設計の欠陥はコードのバグより修正コストが大きいため。

```
以下は Stackelberg PPO を用いた形態-制御 co-design 研究の[章名 / 実験名]の記述です。
Claudeが整理・執筆したものです。

次の4点から厳しく批評してください:
1. 実験設計の妥当性（交絡変数が制御されているか・比較条件が公平か）
2. 結論の根拠（データから言える範囲を超えた主張をしていないか）
3. 再現性（同条件で他者が再現できるか・記述が十分か）
4. 主張と証拠の整合（「〜を示した」「〜を実証した」という表現が証拠に見合っているか）

「この主張は根拠が弱い」「この条件設定では交絡が残る」のように具体的に指摘してください。
研究の背景: Choreonoid シミュレータ上の2関節固定アーム、3タスク（Pusher/Reach/Target-Pusher）、seed×2による再現性確認。

[ここに対象テキストを貼り付け]
```
