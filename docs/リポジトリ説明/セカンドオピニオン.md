### B. 研究レビュー用プロンプト

実験設計・結論の妥当性を批評させる。コードより優先度が高い。
実験設計の欠陥はコードのバグより修正コストが大きいため。

```
以下は Stackelberg PPO を用いた形態-制御 co-design 研究の[章名 / 実験名]の記述です。
Claudeが整理・執筆したものです。

次の4点から厳しく批評してください:
1. 実験設計の妥当性（交絡変数が制御されているか・比較条件が公平か）
2. 結論の根拠（データから言える範囲を超えた主張をしていないか）
3. 再現性（同条件で他者が再現できるか・記述が十分か）
4. 主張と証拠の整合（「〜を示した」「〜を実証した」という表現が証拠に見合っているか）

「この主張は根拠が弱い」「この条件設定では交絡が残る」のように具体的に指摘してください。
研究の背景: Choreonoid シミュレータ上の2関節固定アーム、3タスク（Pusher/Reach/Target-Pusher）、seed×2による再現性確認。

[ここに対象テキストを貼り付け]
```

### C. 修論の文章を yomiyasu に読ませる（2026-10-19、ユーザー判断）

[yomiyasu](https://github.com/nanaism/yomiyasu)（日本語の推敲スキル、MIT、Python の標準ライブラリだけで動く）を、**文章を書き換える道具ではなく、いまの文章を通すとどんな指摘が出るかを見る「もう一人の読者」として使う。**
理由: 書き換えを任せると、どの直しを採ったかが見えなくなる。指摘だけをもらえば、採るかどうかをユーザーが決められる。

| 手順 | 中身 |
|---|---|
| 1. 本文だけを取り出す | 章ごとに、PDF に入る本文だけにする（`build_thesis_pdf.py` と同じく「## 執筆メモ」以降と「> 📝 **執筆メモ…**」の引用ブロックを落とす）。メモの ⭐⛔ や太字が混ざると指摘が雑音だらけになる |
| 2. lint を論文モードで通す | `python3 tools/yomiyasu/scripts/yomiyasu_lint.py <本文.md> --doc-type paper`。文章は変えない |
| 3. ユーザーが一覧から採るものを選ぶ | 直すのは Claude でもよいが、採否はユーザー。直したら修論の検査（`check_section_refs`・`check_stale_claims`・`check_docs_consistency`・`check_citations`）と PDF のビルド |

⚠️ 知っておくこと:
- **lint が見るのは書式と言い回しだけ**（太字の多さ・太字が表示されない書き方・読点・「AではなくB」・AI らしい語）。2026-10-19 に要旨で試すと、ユーザーが読んで感じた構成の違和感 4 点（話の飛び・用語の説明の要否・新規性の書き方・障壁と解決策の距離）は 1 つも拾わなかった。**人の読みの代わりではなく補い。**
- 論文モードでは、慎重な言い方・引用の印・数値・専門用語・「である」調を直さない決まり（`references/doc-types/paper.md`）。そのぶん中身の正しさ（数値とログの一致・取り下げた読み・章をまたぐ主張）は見ない。そこはこのリポジトリの検査とファクトチェック ②（[新しいチャットの始め方.md](新しいチャットの始め方.md)）が担う。
- **スキル本体の AI の部分（「書き手に確かめたい点」を出す部分）は、先入観が無いときにしか読者にならない。**ユーザーの指摘を読んだ後の Claude が規則どおりに読むと、指摘に引きずられる。使うなら、ユーザーが読む前に通すか、指摘を知らないエージェントに通す。
- 「AではなくB」で否定が意味を担っている文や、場面の枠を示す読点（「評価では、」）の指摘は、規則の上でも残してよい。
- 置き場所: **`tools/yomiyasu/`**（リポジトリの直下、`.gitignore` 済み。ユーザー判断 10-19）。docs の外なので docs の検査には触れない。他人のコードなので公開リポジトリへは出さない。取ってきた版は `79d15a6`（2026-10-19、v2.0.2）。更新するときは `cd tools/yomiyasu && git pull`。⚠️ `.gitignore` の対象なので、コンテナを作り直しても `/userdir` に残るが、別の場所へ clone し直した環境には無い（`git clone https://github.com/nanaism/yomiyasu.git tools/yomiyasu`）。⚠️ `yomiyasu_check.py`（推敲の前後を比べる検査）を使うと、記録を git の最上位の `.yomiyasu/` に書く（中に自分で `.gitignore` を置く作り）。lint だけなら何も書かない。
