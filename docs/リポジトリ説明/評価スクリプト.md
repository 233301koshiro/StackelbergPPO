# 評価スクリプトの使い方

学習済み重みを使った評価・可視化スクリプトのまとめ。

> **注意**: choreonoid は `--` を引数終端マーカーとして扱わない。
> eval スクリプトへのパラメータは**環境変数**で渡す。

---

## eval の動作概要

eval でも毎エピソード最初から設計フェーズを走らせる。理由は「どんな形態を作るか」自体がポリシーネットワーク（Leader）の出力だからで、固定 URDF を読むのではなくエピソードのたびに形態を設計し直す。

```
eval の 1 エピソード:
  設計フェーズ → Leader が「どんな形にするか」を決める
    ├─ skeleton_transform（5 ステップ）: ボディの追加・削除
    └─ attribute_transform（1 ステップ）: リンク長・ギア比の調整
  実行フェーズ → Follower がその形でタスクを実行（最大 1000 ステップ）
```

### ターミナルログの流れ方

設計フェーズ（6 ステップ）は**スリープなしで全速**で走る。各ステップで `reload_sim_model()` が呼ばれ Choreonoid のロードログが一気に流れる。実行フェーズのみ指定 fps でスリープが入る。

```
[設計フェーズ] 6 回の reload → ログが一気に流れる
       ↓
[実行フェーズ] 最大 1000 ステップ、fps に合わせてゆっくり進む
       ↓
次のエピソードへ（VIEWER_EPISODES 回繰り返す）
```
choreonoidのmessageのばっーって出る間の時間は各エピソードの区切りの時間だよ

## ユースケース別スクリプト選択

| やりたいこと | スクリプト |
|-------------|-----------|
| 成功率・報酬を数値で確認したい | `eval_cnoid_numerical.py` |
| 動作を動画（mp4）で記録したい | `eval_cnoid_visual.py` |
| GUIでリアルタイムに動きを見たい | `eval_cnoid_viewer.py` |
| 学習曲線グラフを出したい | `plot_rewards.py` |
| 最終形態を URDF として保存したい | `save_morphology_urdf.py` |
| **形態がタスクに向くか診断したい** | **`diagnose_morphology.py`**（第1層だけなら学習前でも使える） |
| **判定に何エポック必要か測りたい** | **`rank_settle.py`**（学習不要・stdout.log だけ読む） |
| **docs が古くなっていないか検査したい** | **`check_docs_consistency.py`**（学習不要・ログとMDだけ読む） |

## eval_cnoid_numerical.py — 数値で成功率を確認

**ユースケース**: 学習後に「本当にタスクが解けているか」を定量的に確かめたい。ヘッドレス（GUI不要）で動くので ssh 環境でも使える。

```bash
EVAL_RESTORE_DIR=single_run/<run名> EVAL_NUM_EPISODES=5 \
  USE_CHOREONOID=1 choreonoid --no-window --python scripts/eval_cnoid_numerical.py
```

**出力**: `{restore_dir}/eval/eval_numerical.png` に報酬の棒グラフを生成。

| 環境変数 | デフォルト | 説明 |
|---------|-----------|------|
| `EVAL_RESTORE_DIR` | （必須） | 学習ディレクトリ |
| `EVAL_EPOCH` | `best` | チェックポイント（`best` or エポック番号）|
| `EVAL_NUM_EPISODES` | `5` | 評価エピソード数 |

## eval_cnoid_visual.py — 動画として記録

**ユースケース**: 動作を mp4 で保存してあとから確認・共有したい。GUI不要で動く。

**注意**: Choreonoid の 3D 画面を録画するのではなく、ボディ座標を matplotlib でプロットした疑似可視化。ロボットは「青い球（関節）＋青い線（リンク）」、cube はオレンジの点として表示される。実際の capsule 形状・テクスチャは表示されない。

```bash
EVAL_RESTORE_DIR=single_run/<run名> \
EVAL_OUTPUT=single_run/<run名>/videos/eval_visual.mp4 \
  USE_CHOREONOID=1 choreonoid --no-window --python scripts/eval_cnoid_visual.py
```

**出力**: 指定パスに mp4 ファイルを生成（デフォルト: `{restore_dir}/videos/eval_visual.mp4`）。

| 環境変数 | デフォルト | 説明 |
|---------|-----------|------|
| `EVAL_RESTORE_DIR` | （必須） | 学習ディレクトリ |
| `EVAL_OUTPUT` | `{restore_dir}/videos/eval_visual.mp4` | 出力パス |
| `EVAL_FPS` | `20` | フレームレート |

## eval_cnoid_viewer.py — GUIでリアルタイム再生

**ユースケース**: Choreonoid の 3D ビューアで実際の動きをリアルタイムに確認したい。

```bash
# 事前に X11 認可を通す（root で GUI を開く場合、ubuntu ユーザー側で実行）
#   xhost +SI:localuser:root
VIEWER_RESTORE_DIR=single_run/tripo_arm_v2c_pusher VIEWER_EPOCH=best VIEWER_FPS=25 VIEWER_EPISODES=3 \
  DISPLAY=:1 USE_CHOREONOID=1 OMP_NUM_THREADS=1 \
  /choreonoid_ws/install/bin/choreonoid --python scripts/eval_cnoid_viewer.py
```

| 環境変数 | デフォルト | 説明 |
|---------|-----------|------|
| `VIEWER_RESTORE_DIR` | （必須） | 学習ディレクトリ |
| `VIEWER_EPOCH` | `best` | 読み込む checkpoint |
| `VIEWER_FPS` | `25` | 再生フレームレート（実行フェーズのみ 1/fps 秒ずつ sleep。形態組み立てフェーズは早送り） |
| `VIEWER_EPISODES` | `3` | エピソード数（0=無限ループ）|

**起動に関する注意（2026-07-31 実機確認）**:
- **`vglrun` は使わない**。この環境の `vglrun` は `VGL_DISPLAY=:0` 固定で起動に失敗する。素の `choreonoid` を `DISPLAY=:1` で起動するのが正しい（旧版のこのドキュメントは「VirtualGL が必要」と書いていたが誤り）
- root で GUI を開く場合、事前に**ubuntu ユーザー側で** `xhost +SI:localuser:root` を実行して X11 認可を通す必要がある。通っていないと `xhost: unable to open display` で失敗する
- 起動直後の数秒だけ Items/Scene が「パラパラ漫画」のように激しく切り替わるのは**仕様**。形態組み立てフェーズ（`attribute_transform`）で Leader が形態を確定するたびに BodyItem が削除→再読み込みされるため（デバッグ戦記.md Bug 17 の副産物節）

### 画面録画は不採用（2026-07-31、試行の記録として残す）

`eval_cnoid_viewer.py`の再生をffmpeg x11grab + xdotoolで自動画面録画する`scripts/record_cnoid_viewer.sh`を一度実装したが、**学習4本と並行稼働させるとChoreonoid自体が「応答なし」になり最終的に落ちた**ため不採用として削除した（学習プロセス自体は無事、GUI側のみクラッシュ）。fps/解像度を下げる軽量化までは行ったが、それでも解決しなかった。

わかったこと（再度この方向を試す場合のために記録）:
- **ChoreonoidのMovieRecorderはPythonに公開されていない**: C++側（`src/Base/MovieRecorder.h`）には存在するが、`src/Base/pybind11/PyBaseModule.cpp`にMovie/Record関連の登録が一切なく、Pythonスクリプトから直接制御することはできない（2026-07-31確認）。外部からのOS側キャプチャ（ffmpeg x11grab等）に頼らざるを得ない
- **マルチモニタ環境での座標系のズレに注意**: この開発環境は仮想デスクトップが2枚のモニタ横並び（各4384×2466、合計8768×2466）になっており、`xdotool getdisplaygeometry`は**モニタ単位のサイズ**（4384×2466）しか返さない。x11grabが実際に見るroot windowは合計サイズ（8768×2466）なので、正しい全体サイズは`xdpyinfo | grep dimensions`から取る必要がある
- x11grabは無圧縮のraw pixelを毎フレームXサーバから取得するため重い（フル解像度4384×2318・25fpsだと1フレーム約40MB相当）。学習4本と同時実行時のCPU負荷競合が「応答なし→クラッシュ」の一因と見られる

現状は[eval_cnoid_viewer.py](#eval_cnoid_viewerpy--guiでリアルタイム再生)でGUI上で直接見るか、[eval_cnoid_visual.py](#eval_cnoid_visualpy--動画として記録)（matplotlibベースの模式図動画、実際のChoreonoid 3D画面ではない）で代替する。

## check_docs_consistency.py — docs とログの突き合わせ

CLAUDE.md §4-2 の4層モデルで「① 原本（`log/log_train.txt`）」を真として、docs を検査する。
**値を更新したら必ず走らせる。**

```bash
python3 scripts/check_docs_consistency.py           # 全検査
python3 scripts/check_docs_consistency.py --only A  # 特定の検査だけ
python3 scripts/check_docs_consistency.py --quiet   # 問題があるものだけ
```

| 検査 | 内容 |
|---|---|
| **A** | 完走済みの run を「進行中/稼働中/学習中」と書いている |
| **B** | `best` の直後の数値が、その run のどのエポック値とも一致しない |
| **C** | docs にある run 名が `single_run/` に無い（改名漏れ・削除済み） |
| **D** | checkpoint があるのに台帳（実験系譜・実験一覧）に載っていない＝**記録漏れ** |

**誤検出を抑えるための工夫**（素朴に作ると使い物にならなかった）:

- run 名は**最長一致**。`tripo_arm_v2c_pusher` は `..._ns2` の部分文字列なので、素朴だと別 run の行を拾う
- B は **`best` の直後の数値だけ**見る。同じ行にピーク速度・倍率・リンク長・理論上限が混在するため
- 正当な値の集合は「**全エポックの生値 + running best**」。`ep189=28.68 → ep199=34.32` のような
  意図的な履歴記述を誤検出しないため
- 日付を含む行と、履歴を残す性質のファイル（デバッグ戦記・実験系譜・方針レビュー）は A の対象外

**出力は「候補」であって断定ではない。** C は過去に削除した run 名を多く含む。1件ずつ判断すること。

## rank_settle.py — 判定に必要なエポック数を測る（第4章 4.3.4.2）

複数 run の学習曲線から、**順位が最終順位に固定される最小エポック**を測る。学習も Choreonoid も不要で、
`single_run/*/stdout.log` を読むだけ。

```bash
python3 scripts/rank_settle.py                        # 既定の11コホートを全部測る
python3 scripts/rank_settle.py tripo_pj_mid tripo_pj_long   # 任意の run を比較
```

⚠️ データ源は `log/log_train.txt`（`stdout.log` は再開で先頭が失われる。Bug 18）。
共通epochが0から始まらない場合は `≤N` と表示され、確定点の**上界**としてしか読めない。

判定量は **running best**（そのエポックまでの最良 exec_R_eps）。第4章 4.1.4 が各 run の代表値を
best checkpoint と定めているため、判定を ep E で打ち切ったときに読む値がこれになる。
生の各エポック値はノイズで順位が頻繁に入れ替わるので較正には使わない。

「確定エポック」は**そのエポック以降、最後まで一度も最終順位から外れない最小のエポック**。
途中で崩れたら数え直すので、逆転が完全に止まった点を返す。

結果の要点（2026-08-06）: 所要エポックは**候補間の隔たりに支配される**。設計が実際に異なる対は 6〜27ep、
乱数しか違わない同一条件の対は最大 116ep。運用は「明確に異なるなら 30ep、拮抗しうるなら 120ep」。

## diagnose_morphology.py — 形態がタスクに向くか診断する（M7）

「向いていません」だけでなく**何がどうダメで、どう直せばよいか**を返す。修論では第3章 3.12 節。

### 第1層だけ（学習不要・約1秒・Choreonoid 不要）

XML を見るだけで「届くか」「初期状態でめり込まないか」を判定し、届かない場合は**必要な拡大倍率**を返す。
**学習を始める前のスクリーニングに使える**のがこの層の価値。

```bash
python3 scripts/diagnose_morphology.py --xml tripo_arm_v2c_pj_short --task reach
python3 scripts/diagnose_morphology.py --xml tripo_arm_v2c_pj_long  --task pusher
```

出力例:

```
❌ 腕が短すぎて目標に届きません（届く範囲は 0.403 m まで、目標は 0.800 m 先）。
    → 腕全体を 2.19 倍に伸ばしてください。
    　（1.99 倍で計算上は届きますが、腕を伸ばしきった姿勢でしか触れられないため余裕を含めた値を示しています）
```

オプション:

| 引数 | 意味 |
|---|---|
| `--xml <名前>` | `assets/mujoco_envs/` 内の XML 名（拡張子なし） |
| `--task reach\|pusher` | 対象タスク。既定は `reach` |
| `--target x y z` | Reach の目標位置。既定は `0.8 0.0 0.15` |
| `--length-free` | リンク長も最適化対象として判定する（既定はリンク長凍結） |

⚠️ リンク長が最適化対象の場合、第1層は「**届かない**」としか言わない（学習中に伸びうるため「届く」とは断定しない）。

### 第1〜3層すべて（学習済み run が必要・Choreonoid 経由）

`EVAL_RESTORE_DIR` に run を渡すと、その run の設定から XML 名とタスクを自動で復元し、
収束形態（第2層）と行動トレース（第3層）まで診断する。best checkpoint を使う。

```bash
EVAL_RESTORE_DIR=single_run/tripo_pj_short USE_CHOREONOID=1 \
  /choreonoid_ws/install/bin/choreonoid --no-window \
  --python scripts/diagnose_morphology.py
```

所要時間は数分〜15分程度（1エピソード再生を含むため）。**学習と同時に走らせると CPU を奪うので注意。**

⚠️ 第2層の「gear と太さが揃って下限」は**単独では不適合の指標にならない**。Reach では弱く細いのが
正常な最適解でもあるため（到達できる形態と到達できない形態が同じ署名を示す実測あり）。
第1層（届くか）か第3層（実際に到達したか）と組み合わせて読むこと。詳細は第5章 5.5.2。

## 出力ディレクトリ構成

```
single_run/<run名>/
├── log/                     ← 学習ログ（log_train.txt）
├── models/                  ← チェックポイント（best.p, epoch_XXXX.p）
├── videos/                  ← 動画ファイル
│   └── eval_visual.mp4      ← eval_cnoid_visual.py 出力
├── eval/                    ← 数値評価グラフ
│   └── eval_numerical.png   ← eval_cnoid_numerical.py 出力
├── morphology/              ← 形態ファイル
│   ├── morphology_best.urdf ← save_morphology_urdf.py 出力
│   └── morphology_best.xml
└── plots/                   ← 学習グラフ
    └── reward_plot.png      ← plot_rewards.py 出力
```
