## ② ファクトチェック（① の後に貼る。週に 1 回か、大きな変更の後）

```
一次データからファクトチェックをしてほしい。前のチャットや md の文章は根拠に使わない。根拠にしてよいのは次だけ:
- 学習ログ single_run/*/log/log_train.txt、軌跡 trace/*.npz、launch_env.json
- コードと XML（assets/mujoco_envs/*.xml）、それを実際に動かした結果（再実行・再計算・MuJoCo での計算）
- 論文の PDF・arXiv・Crossref、メーカーのデータシートなどの一次資料

まず次の候補から、今回やるものと順番をおすすめ付きで提案して、私の返事を待つこと:
A. 参考文献: 書誌（著者・掲載先・ページ）を Crossref・arXiv で、本文の要約を論文の中身（PDF）で確かめる。check_citations.py は本文とリストの対応しか見ないので、ここは検査の外
B. 物理の値: docs/研究応用/設計/シミュレーションの値の変更表.md の各行を出典に当て、導出した値（式から計算したもの）は自分で計算し直す。XML とキューの起動行に実際に入っている値とも照らす
C. 最新の段: 実験系譜の最新の段（前回のファクトチェック以降）の数値を、ログと軌跡から計算し直す。再実行で同じ値が出るかも見る
D. 修論と取り下げ: 知見総括表 E 節の取り下げた主張を正規表現にして修論ドラフト全体に当てる。各章の冒頭に必要な撤回の注記があるかも見る
E. 状態の行: python3 scripts/check_open_gaps.py --status の行を 1 行ずつ、ps・キュー・single_run と照らす
F. 方針: 研究方針.md の決定事項が、その後の決定や実験で覆っていないか。古い節番号・終わった期の「進行中」も見る
G. 道具と環境: CLAUDE.md・docs/デバッグ戦記.md・スクリプトの注意書きにある、道具や環境の振る舞いについての現在形の主張（時間・終わり方・何が読まれるか）。まず python3 scripts/check_env_claims.py を回し、載っていない主張は安く動かせるものから実際に動かして確かめる。確かめられたものは check_env_claims.py に足す

進め方:
1. 指摘は先に表で出す（場所・記述・判定・一次資料）。判定は ✅ 一致／⛔ 誤り／⚠️ 古い／❓ 根拠が無い の 4 つ。✅ だった項目も「何で確かめたか」を書く。
2. 私が確認するまで直さない。直すときは消さずに「⛔ 訂正（日付、系譜 N-M）」を添えて経緯を残す。訂正は grep で全出現箇所を洗う。
3. 結果は実験系譜.md に新しい段として書き、冒頭の「第9段の索引」にも 1 行足す。
4. 直した後は python3 scripts/check_docs_consistency.py・check_stale_claims.py・check_section_refs.py・check_citations.py・check_code_docs_sync.py を回す。
5. 最後に、何を確かめて合っていたか・何が誤っていたか・私の判断が要るものを分けて報告する。

過去に踏んだ罠（このチェックで実際に起きた）:
- 学習は XML を名前で読み、run に XML のコピーを残さない。値を直すときに既存の XML を上書きすると、過去の run の再生が新しい値で走る。新しい名前の XML を作る。
- 動いている bash のキューは書き換えない（bash は読み進めるので壊れる）。止めてから直す。いずれも私の確認が要る。
- Choreonoid のプローブは出力をファイルへリダイレクトし、timeout は 1200 秒以上（⛔ 訂正（2026-10-19、系譜 9-257）: 根拠だった「起動に約 105 秒」は実測 2 秒。timeout は起動ではなくプローブ自体の所要時間から決める）。Choreonoid は SIGTERM を無視する（❓ 未検証。check_env_claims.py に入っていない）ので、止めるなら子プロセスから kill -9（私の確認の後）。
- 文献の数値は「どの量か」まで確かめる（例: モーターの慣性だけか、減速機の慣性も含むか。最大値か定格か）。名前が同じでも量が違うことがある。
- 割合の数字は分母まで確かめる（「差 0.6 %」が何に対する割合か）。
- 検査スクリプトが全部通っても、要約が論文と合っているか・方針が古くなっていないかは見ていない。
- A〜F は研究の中身だけを対象にしていて、CLAUDE.md とデバッグ戦記（道具の振る舞い）を誰も見ていなかった。10-14 に「Choreonoid の起動 105 秒」（実測 2 秒）と「sys.exit(0) のせいで exit 137」（実際は自分で終わらない）が残っていた。G はそのために足した。
- 観測が md と食い違ったら、もっともらしい説明で埋めずに測る。10-14 に再生が 8 秒で終わったのを AI が「キャッシュに乗っていたため」と確かめずに説明した。md のほうが古かった。
```

## 使い方のメモ

- ① だけで足りる日は ② を貼らない。② は時間がかかる（2026-10-14 は A〜F で半日）。
- ② の候補のうち、取り直し中で差し替える予定の結果（撤回した旧い物理の数値）は照合しても捨てる。照合は差し替えた後に回す。
- プロンプトを直したら、この md を直す（他に写しは無い）。
